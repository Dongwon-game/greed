# 실행 파일의 종료와 재실행 확인

## 백그라운드 결과 보존 보완

2026-10-21 소스는 완료된 일반/무한 결과를 앱 일시중단·포커스 손실 때도 한 번 보존한다. 복귀 뒤 결과 버튼은 기록/성장을 다시 지급하지 않는다. 진행 중 런을 실패/포기로 정산하거나 저장 칸을 자동 선택하지 않는다. Editor의 `Greed Last/Run Background Result Recovery Check`는 40개 격리된 콜백/JSON 대조다. 실제 휴대폰 종료·강제 종료·물리 창 입력 검사는 별도다. 새 실행본 검증 진행 상태와 원시 로그는 [확인 이력](GreedLast_Prototype_CheckHistory.md)을 따른다.

## 목적과 범위

에디터 안에서 JSON을 다시 읽는 검사와 별도로, 실제 Windows 실행 파일의 `Application.Quit` 뒤 새 프로세스가 같은 시험 저장소를 읽는지 확인한다. 게임 규칙을 새로 추가하는 작업이 아니라 기존 한 번 저장/두 번 사용/정산 경계를 확인하는 개발 도구다.

검사는 현재 커밋을 `Logs/PlayerPersistenceChecks/<새 GUID>/Project`로 내보낸다. 복사본에만 Editor 텍스트 시험 코드를 컴파일하고 회사/제품을 `GreedLastPrototypeChecks/Persistence-<GUID>`로 바꾼다. 개인 실행본과 회사/제품, 저장 경로를 공유하지 않는다. 원본 프로젝트 설정과 개인 Greed 설정은 전후 읽기 전용 비교로 확인하며 초기화·레지스트리 복사·추측 복원을 하지 않는다.

## 실행

1. 개인 Greed 플레이어와 해당 프로젝트 Unity 에디터를 닫는다. 도구는 열려 있으면 건드리지 않고 중단한다.
2. Unity `6000.4.3f1`, Windows Build Support, 정식 Windows 빌드를 준비한다. 게임 소스·장면·자원·패키지·설정 변경을 먼저 검토/커밋한다.
3. PowerShell에서 프로젝트의 `tools/check-player-persistence.ps1`을 실행한다. `-WhatIf`는 생성 전 중단한다. `-CaptureFrames`를 명시한 경우에만 별도 오프스크린 렌더 일곱 장을 먼저 검사한다.
4. 마지막 출력의 `Report`에서 `Succeeded`, 단계별 해시, 소유 프로세스 종료, 개인 설정/원본 설정 불변을 확인한다. 실패 JSON과 로그는 삭제하거나 성공으로 덮어쓰지 않는다.

새 복사본의 Library/실행본을 만들므로 여유 디스크와 컴파일 시간이 필요하다. 생성 자료는 `Logs` 아래에 보존하고 GitHub에는 포함하지 않는다. 이 도구는 알림·관리자 창·예약 작업·PC 종료를 설치하지 않는다.

## 열 번의 새 프로세스

| 단계 | 실제 확인 |
| --- | --- |
| clear | 개발 바로가기 없이 첫 연습과 일반 런을 끝내고, 결과의 다음 버튼 없이 정상 종료 |
| save | 새 실행에서 클리어 1회·성장 3·미저장 후보 복원. 칸 없는 확정 거부 후 S3를 직접 골라 한 번 저장 |
| first-use | 준비 취소는 2회 유지. 실제 무한 시작은 2→1이며 주행 중 종료는 종료 기록/보상을 만들지 않음 |
| last-use | 새 실행에서 1회 유지. 두 번째 실제 시작은 자동 비움이지만 현재 무한은 유지. 자연 실패 뒤 다음 버튼 없이 종료 |
| verify | 새 실행에 빈 슬롯과 실제 무한 기록/보상이 정확히 한 번 남음 |
| verify-again | 정산된 로비를 다시 종료/실행해도 기록/성장이 늘지 않음 |
| live-normal | 실제 첫 함정이 있는 일반 런의 주행 중 종료. 의도적인 포기나 실패로 바꾸지 않음 |
| normal-fail | 새 실행에 앞선 주행 중 종료의 시도/보상이 없음. 실제 무입력 실패 결과에서 다음 버튼 없이 종료 |
| verify-failure | 실패 1회와 실패 성장 보상 1회, 실제 직전 실패 기록의 수치 보존 |
| verify-failure-again | 정산된 실패를 다시 종료/실행해도 추가 정산되지 않음 |

각 단계는 실제 프레임으로 흐르는 게임의 앱 명령을 호출한다. 읽기 전용 스냅샷/카운터 관찰에 reflection을 쓰지만 게임 시계나 점수·체력·저장 상태를 직접 쓰지 않는다. 사용자 손가락·키보드 입력을 재현했다는 뜻은 아니다.

## 백그라운드 선보존 옵션

`-BackgroundResults`는 같은 열 프로세스를 새 고유 제품에서 실행하되, 실제 프레임으로 도달한 일반 클리어·일반 실패·무한 종료 결과에서 앱의 포커스 손실/일시중단 핸들러를 명시적으로 호출한다. 종료 전에 기록/보상이 정확히 한 번 반영돼야 하고, 반복 콜백 뒤 정상 종료와 새 프로세스에서 중복되지 않아야 한다. 무한 첫 실제 사용과 진행 중 일반 런은 별도 무정산 대조다. 총 다섯 경계의 성공 횟수가 보고서에 필요하며 옵션 누락도 실패로 처리한다.

0.25초 동안 결과/진행 수치 보존, 복귀 뒤 완료 결과의 입력 가능/진행 중 런의 자동 재개 금지, 슬롯 사용 횟수 불변을 확인한다. 게임 시계·점수·피해나 사용권을 직접 쓰지 않는다. 실제 Windows 창/휴대폰 OS를 전환하거나 프로세스를 강제 종료했다는 뜻은 아니다. `-InteractiveWindow`와 혼용하면 생성 전에 거부하며 옵션이 없으면 기존 정상 종료 우선 검사를 유지한다. 원시 보고서의 `BackgroundResultsRequested`와 단계별 `BackgroundChecks`로 두 실행을 구분한다.

이 옵션은 개발 검증 도구 변경이므로 게임 실행본을 새 기능으로 교체하지 않는다. 현재 일반 배포는 14:15/background-results를 유지하며 실제 실행 결과는 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 별도로 기록한다.

## 전체 엔진 검사와 시작 감시 구분

이 문서의 실제 실행 파일 열 단계와 Editor의 `RunFullLoop`는 다른 검사다. 10월 21일 기본/백그라운드 두 제품의 실제 실행 파일 20단계가 통과했다. 이어진 새 사본의 첫 프레임 시작 실패는 Assets 검색 인덱스 정의의 누락/추가/제거 대조로 준비 조건을 좁혔고, 정의를 복원한 사본과 아래 전용 도구의 새 사본에서 각각 두 재로딩 방식 전체 루프가 통과했다. 앞선 실패와 임시 진단은 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 그대로 보존한다.

현재 Editor 도구는 Play 모드 진입 후 15초 내 `Driver.Start`가 없으면 포커스·편집기 정지·프레임·그래픽 상태를 보고하고 설정을 복원한다. 정상 시작한 전체 코스의 기존 시간 제한은 유지한다. 성공한 이 거부 대조나 동기 전체 스모크를 전체 엔진 루프 성공으로 표시하지 않는다. 본게임 백그라운드 설정·시간·판정이나 Windows 창 제어는 바꾸지 않았다.

## 새 사본의 엔진 검사 도구

개인 Greed 플레이어/해당 프로젝트 편집기를 닫고 게임·Editor·장면·자원·패키지·설정 변경을 먼저 검토/커밋한다. Unity 6.4 `6000.4.3f1`과 Windows Build Support가 있는 Windows에서 프로젝트 루트의 PowerShell로 실행한다.

```powershell
./tools/check-engine-loop.ps1 -WhatIf
./tools/check-engine-loop.ps1
./tools/check-engine-loop.ps1 -CueOnly
```

세 명령을 모두 연속 실행해야 하는 것은 아니다. `-WhatIf`는 파일/시험 제품 생성 전 미리 보기다. 기본 모드는 대표 전체 루프, `-CueOnly`는 함정 예고/재개의 짧은 범위만 두 재로딩 방식에서 검사한다. 짧은 성공을 전체 완주/저장/사용권 검사의 성공으로 세지 않는다. 기본 검사는 준비/컴파일 외 실제 엔진 구간에 약 15분이 걸렸고 시간은 PC 상태에 따라 달라진다.

도구는 커밋을 `Logs/EngineLoopChecks/<새 GUID>/Project`에 내보내고 기본 Assets 인덱스 정의를 직접 만든다. 개인 `Search.settings`·검색 기록·계정 파일을 복사하지 않는다. SDK로 시험 회사/제품을 준비하는 편집기를 먼저 종료한 뒤, 해당 고유 제품으로 새 편집기를 시작한다. 열린 개인 편집기/플레이어는 종료시키지 않고 도구가 중단한다. 개인 Greed 저장값과 원본 PlayerSettings는 전후 읽기 전용 비교다.

최종 `report.json`은 당시 도구/소스 ZIP 해시, 소유 프로세스 종료, 실제 엔진의 보존 아카이브 경로/해시와 설정 불변을 포함한다. 엔진이 실패 보고서를 남겼다면 외부 실행 실패에도 그 원인/경로를 함께 보존한다. 잘못된 ID·비동기 검사에 `-quit` 혼용·인덱스 누락은 시작 전에 거부한다. 로그/실패 자료/시험 제품은 유지하며 초기화·알림·예약·PC 종료를 설치하지 않는다.

10월 21일 기본 전체 모드와 짧은 모드, 실제 시작 보호 세 가지, 보고서 읽기 일곱 조건이 통과했다. 별도 사본의 비개발 Windows 전체 스모크/빌드와 시험 코드 배포 제외도 통과했다. 게임 입력 15파일은 두 사본 모두 `1084cdf`와 동일한 Git 경로 필터로 대조했다. 새 렌더/실제 창 입력·가청 소리·휴대폰 성능 검사는 아니며 개인용 실행본/ZIP은 14:15/background-results 그대로다. 근거는 [확인 이력](GreedLast_Prototype_CheckHistory.md)의 전용 엔진 도구 완료 절을 따른다.

## 시험 코드 배포 제외

검사 코드는 원본에서 `Assets/Editor/GreedLastPlayerPersistenceProbe.cs.txt` 텍스트 자산이다. 정식 스모크는 런타임 타입 부재를 검사하고 정식 실행본 검증 도구도 해당 네임스페이스가 들어 있으면 거부한다.

도구의 네 가지 음성 대조는 잘못된 빌드 ID, 경로 탈출 단계 이름, 다른 출력 루트, 시험 DLL이 섞인 가짜 배포를 각각 거부하는지 확인한다. 가짜 배포는 정적 검사에만 사용하고 실행하지 않는다.

## 선택적 오프스크린 렌더

`-CaptureFrames`는 그래픽 장치가 있는 시험 플레이어에서 실제 로비·연습 시작·함정·일시정지·재개 카운트·같은 함정 재개·연습 결과를 PNG로 남긴다. 게임 시계나 피해를 직접 바꾸지 않으며, 실제 카메라에 현재 UI를 잠깐 연결해 RenderTexture로 그린 뒤 원래 오버레이/카메라 연결을 복원한다. 프레임 크기·색상 변화·서로 다른 이미지와 정지 중 거리/체력/실수 불변을 대조한다.

이는 숨긴 창의 화면 버퍼나 OS 바탕화면 캡처가 아니다. 이 환경의 숨긴 창/배치 `ScreenCapture`는 검게 나왔고 실패로 보존했다. 오프스크린 렌더 성공으로 이 실패를 대체하거나 실제 화면·손/기기 검사를 완료했다고 표시하지 않는다. 옵션이 없으면 렌더는 미실행이며 종료·재실행 단계만 검사한다.

자동 명령 입력으로 얻은 연습 결과/추천 보정은 사람의 입력 지연 측정값이 아니다. 개인 보정값에 복사하지 않는다.

## 실제 Windows 창 옵션

**검증 상태**: 이 선택 옵션은 컴파일/경로 보호까지만 확인했고 실제 입력 검증은 완료하지 않았다. 10월 21일 첫 실행은 물리 ESC로 Windows 제어가 중단돼 실패/중단으로 보존했다. 기본 열 단계의 성공을 이 옵션의 성공으로 확대하지 않는다. Windows 제어를 다시 시작하라는 별도 요청 없이 자동으로 재개하지 않는다.

`-InteractiveWindow`는 기본 열 단계와 별도로 네 프로세스를 사용한다. `-CaptureFrames`와 함께 쓰지 않는다. 명시적 옵션일 때만 시험 창을 표시하며 일반 실행/백그라운드 검증에는 창을 띄우지 않는다.

1. 첫 시험 창에서 실제 기초 연습 버튼과 ESC를 사용한다. 먼저 재동기화 화면이 보이면 재시도로 입구에 복귀한다. 정지 메뉴에서 0.6초 이상 기다린 뒤 ESC/재개를 누른다. 재개 카운트 뒤 실제 함정이 다시 진행하면 창을 닫는다. 관찰기는 게임 명령을 대신 누르지 않고 상태 변화를 기록한다.
2. 다음 시험 창은 실제 프레임의 앱 명령으로 연습/일반 런을 자동 완주한다. `window-clear-ready.json`이 생긴 결과 화면에서 저장/로비 버튼을 누르지 않고 창을 닫는다.
3. 두 번의 새 헤드리스 프로세스에서 연습 종료 무정산, 일반 클리어 1/성장 3/미저장 후보와 실제 직전 기록 보존, 재종료 중복 없음을 확인한다.

각 대화형 단계는 최대 330초 동안 기다리며 외부 입력이 없으면 실패로 끝난다. 도구의 시간 초과 정리는 자신이 시작한 시험 프로세스만 대상으로 하며 성공한 창 종료 검사로 세지 않는다. 회사/제품/경로 보호와 개인 설정 전후 불변 규칙은 기본 검사와 같다.

프로그램 안의 `OnApplicationQuit` 관찰만으로 X/Alt+F4를 구분하지 않는다. 실제 운영체제 창·버튼/키 입력을 별도로 관찰한 기록과 결합해야 해당 종료 방법의 성공을 주장할 수 있다. Windows 주입 입력은 실제 손가락 리듬 정확도·소리 지연이나 휴대폰 성능 검사가 아니다. 현재 옵션의 실행 결과는 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 별도로 남긴다.

## 남은 직접 확인

`Application.Quit`의 성공은 실제 OS 창의 X/Alt+F4, 강제 종료·정전 복구, 스피커 소리·입력 지연·휴대폰 성능의 성공을 뜻하지 않는다. 게임 화면의 직접 순서는 [빠른 확인](GreedLast_Prototype_QuickCheck.md)을 따른다. 검증 수치를 늘리려고 개인 조합이나 진행도를 초기화·소모하지 않는다.

10월 19일 첫 연습 원본 값 손실은 별도 이력이며, 이 시험 저장소의 성공을 당시 개인 값 복구로 표시하지 않는다.
