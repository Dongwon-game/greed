## 장별 목표와 첫 무한 구간의 실제 재실행

`./tools/check-player-persistence.ps1 -ScopedGoals`는 기존 열 단계를 사용하는 명시적 검사 옵션이다. 기본 실행의 기초연습→첫 일반 런 자동 연결은 그대로 유지한다. 이 옵션에서만 개인 데이터와 무관한 시험용 로비 안내로 목표를 주고, 실제 프레임과 앱 명령으로 판정/결과를 만든 뒤 `Application.Quit`와 새 프로세스로 전체 기록·목표 결과를 대조한다.

- 일반 `1장 보정 0회`: 실제 15판정 완주 중 2장에 Good 한 번을 넣어도 1장 달성은 유지된다. 다른 프로세스의 자연 실패에서는 1장 실수로 실패하고, 뒤의 두 실행에서도 달성으로 바뀌지 않는다.
- 무한 `다음 구간 무실수`: 실제 세 정확 입력으로 첫 구간을 완료한다. 그 뒤 입력하지 않아 자연 체력 0 종료/전체 Miss가 생겨도 첫 구간 달성은 유지되고, 새 프로세스의 정비 목표는 `다음 구간 보정 0회`로 이어진다.
- 한 번 저장·정비 취소 무소모·실제 2→1→0/자동 비움과 시작한 런 유지, 살아 있는 런 종료의 무정산, 결과 보상 한 번 반영 및 전체 기록 비교도 기존 단계에서 함께 확인한다.

`-BackgroundResults`만 선택적으로 함께 쓸 수 있다. 이때 실제 프레임의 앱 일시정지/포커스 콜백을 명시적으로 호출해 정상 종료보다 먼저 결과를 보존한다. 실제 OS 최소화/강제 종료나 휴대폰 프로세스 회수 검사가 아니다. 캡처·대화형 창·읽기 불가 자료·연습 종료 옵션과 혼용하면 사본 생성 전에 거부하며 `-WhatIf`도 지원한다. 여섯 혼용 거부 대조는 새 게임 실행 없이 확인했다.

2. 다음 시험 창은 실제 프레임의 앱 명령으로 연습/일반 런을 자동 완주한다. `window-clear-ready.json`이 생긴 결과 화면에서 저장/로비 버튼을 누르지 않고 창을 닫는다.
3. 두 번의 새 헤드리스 프로세스에서 연습 종료 무정산, 일반 클리어 1/성장 3/미저장 후보와 실제 직전 기록 보존, 재종료 중복 없음을 확인한다.

각 대화형 단계는 최대 330초 동안 기다리며 외부 입력이 없으면 실패로 끝난다. 도구의 시간 초과 정리는 자신이 시작한 시험 프로세스만 대상으로 하며 성공한 창 종료 검사로 세지 않는다. 회사/제품/경로 보호와 개인 설정 전후 불변 규칙은 기본 검사와 같다.

프로그램 안의 `OnApplicationQuit` 관찰만으로 X/Alt+F4를 구분하지 않는다. 실제 운영체제 창·버튼/키 입력을 별도로 관찰한 기록과 결합해야 해당 종료 방법의 성공을 주장할 수 있다. Windows 주입 입력은 실제 손가락 리듬 정확도·소리 지연이나 휴대폰 성능 검사가 아니다. 현재 옵션의 실행 결과는 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 별도로 남긴다.

## 선택적 실제 메뉴 제스처 - 검증 미완료

`./tools/check-player-persistence.ps1 -InteractiveMenus`는 현재 실험용 선택 경로다. 컴파일/빌드와 실행 전 보호는 통과했지만 실제 드래그/포커스 복귀는 아직 완료하지 못했다. 두 미완료 시도의 범위는 [확인 이력](GreedLast_Prototype_CheckHistory.md)을 따른다. 다른 검사 옵션과 혼용하지 않는다.

1. 별도 제품의 연습/첫 일반 완주→S3 한 번 저장→다음 일반 완주를 SDK 앱 명령으로 준비한다. `window-menu-ready.json` 뒤 기존 S3는 2회이고 새 후보는 미저장이다. 개인 조합/레지스트리를 복사하거나 게임 시계를 바꾸지 않는다.
2. 실제 창에서 S3를 선택하고 상세 비교를 연다. 긴 본문을 드래그하고 손잡이로도 움직인다. 관찰기는 실제 제스처 활성 상태와 정규화 위치 0.15 초과·본문 10픽셀 초과 이동을 모두 요구한다. 내용이 짧은 빈 슬롯을 비교하는 것으로 대신하지 않는다.
3. 시험 창을 최소화/복귀하고 새 손잡이 드래그를 한다. 이는 새 입력 복구 확인이며, 원자적 드래그 도중 포인터를 유지한 채 중단하는 검사나 휴대폰 터치 검사는 아니다. 다른 앱이 가리거나 사용자 입력이 감지되면 추가 입력을 중단하고 성공으로 세지 않는다.
4. 저장/덮어쓰기/삭제/후보 포기는 누르지 않는다. `window-menu-completed.json`이 나온 뒤 정상적으로 창을 닫는다. 두 새 프로세스는 두 클리어/성장 6·원래 S3 전체 기록과 2회 사용권·미저장 후보 보존을 확인한다.

입력 단계는 최대 600초, 외부 래퍼는 630초로 제한한다. 필수 제스처 없이 닫으면 실패이며, 관찰기는 버튼/스크롤을 대신 조작하거나 실패를 성공으로 바꾸지 않는다. SDK 준비·실제 OS 메뉴 입력·새 프로세스 보존은 별도 범위다. 게임 런타임이나 개인 배포에는 이 시험 코드가 포함되지 않는다.

공용 시험 보고서 변경 뒤 `f8804c3`의 기본 모드 열 프로세스/네 안전 대조 호환 검사는 별도 고유 제품에서 통과했다. 메뉴 드래그나 포커스 복귀 검증의 성공으로 대신하지 않는다. 원본 성공/미완료 자료는 각각 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 보존한다.

## 실제 창의 저장과 두 번 사용

`./tools/check-player-persistence.ps1 -InteractiveLoadout`은 고유 제품의 초기 연습/일반 완주만 SDK로 준비하고, 이후 메뉴를 외부에서 직접 누르도록 기다린다. `-InteractiveWindow`/`-InteractiveMenus`/`-CaptureFrames`/`-BackgroundResults`와 혼용하면 생성 전에 거부한다. 개인 조합/진행도를 쓰지 않는다.

1. 일반 탈출 결과에서 저장 슬롯 선택→빈 S3 직접 선택→저장을 한 번 확정한다. 저장 관리 재진입 시 후보가 없어야 한다.
2. 무한 준비에서 기프트/유물을 고른 뒤 로비로 취소한다. 사용권은 2회다. 이 취소를 먼저 관찰해야 첫 시작 검사가 통과한다.
3. 다시 준비하고 실제 시작을 별도로 확정한다. 2→1만 차감한다. 무입력/무적 OFF 체력 0 자연 종료 뒤 로비에서 한 번 정산한다.
4. 두 번째 준비/실제 시작은 1→0·슬롯 자동 비움이며 현재 런은 이어진다. 다시 자연 종료하고 로비로 돌아온다.
5. `window-loadout-ready.json`의 `nativeLoopCompleted`가 참인 뒤 실제 창 X/Alt+F4로 닫는다. 두 새 헤드리스 프로세스가 기록 2회/성장/빈 슬롯의 중복 없는 보존을 확인한다.

대화형 단계의 기한은 600초이며 준비 취소 누락·조기 종료/시간 초과를 성공으로 표시하지 않는다. 단계별 관찰 JSON과 외부 실제 입력 기록을 함께 읽는다. 10월 22일 `a992f24926364cdfb1beff620186cc7b`의 세 단계·네 안전 대조가 통과했으며 클리어 1·무한 2·성장 5·세 슬롯 0을 두 재실행에서도 유지했다. 시험 관찰기 변경이며 실제 손 리듬/소리·기기 성능이나 새 게임 배포가 아니다.

후속 `3b9b976`/`6132d6f5b53b4f34b89d359f16f45703`은 두 번째 실제 런이 슬롯 비움 뒤 살아 있는지 명시하고, 마지막 무한 기록의 점수·거리·정확/Good/Miss·타이밍 요약도 종료 전과 두 재실행에서 대조한다. 기록 횟수/성장만 맞는 것으로 완료 처리하지 않는다. 이 후속 검사는 통과했지만 마지막 로비는 캡처가 잘려 화면 확인 대신 준비 완료 JSON과 실제 ESC/Alt+F4 기록으로 범위를 구분했다. 앞선 완전한 창 관찰을 대체하거나 크기 변경 성공으로 세지 않는다.
