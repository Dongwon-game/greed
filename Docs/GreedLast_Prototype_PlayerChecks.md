`-BackgroundResults`는 같은 열 프로세스를 새 고유 제품에서 실행하되, 실제 프레임으로 도달한 일반 클리어·일반 실패·무한 종료 결과에서 앱의 포커스 손실/일시중단 핸들러를 명시적으로 호출한다. 종료 전에 기록/보상이 정확히 한 번 반영돼야 하고, 반복 콜백 뒤 정상 종료와 새 프로세스에서 중복되지 않아야 한다. 무한 첫 실제 사용과 진행 중 일반 런은 별도 무정산 대조다. 총 다섯 경계의 성공 횟수가 보고서에 필요하며 옵션 누락도 실패로 처리한다.

이 문서의 실제 실행 파일 열 단계와 Editor의 `RunFullLoop`는 다른 검사다. 10월 21일 기본/백그라운드 두 제품의 실제 실행 파일 20단계가 통과했다. 이어진 새 사본의 첫 프레임 시작 실패는 Assets 검색 인덱스 정의의 누락/추가/제거 대조로 준비 조건을 좁혔고, 정의를 복원한 사본과 아래 전용 도구의 새 사본에서 각각 두 재로딩 방식 전체 루프가 통과했다. 앞선 실패와 임시 진단은 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 그대로 보존한다.

현재 Editor 도구는 Play 모드 진입 후 15초 내 `Driver.Start`가 없으면 포커스·편집기 정지·프레임·그래픽 상태를 보고하고 설정을 복원한다. 정상 시작한 전체 코스의 기존 시간 제한은 유지한다. 성공한 이 거부 대조나 동기 전체 스모크를 전체 엔진 루프 성공으로 표시하지 않는다. 본게임 백그라운드 설정·시간·판정이나 Windows 창 제어는 바꾸지 않았다.

## 새 사본의 엔진 검사 도구

개인 Greed 플레이어/해당 프로젝트 편집기를 닫고 게임·Editor·장면·자원·패키지·설정 변경을 먼저 검토/커밋한다. Unity 6.4 `6000.4.3f1`과 Windows Build Support가 있는 Windows에서 프로젝트 루트의 PowerShell로 실행한다.

```powershell
./tools/check-engine-loop.ps1 -WhatIf
./tools/check-engine-loop.ps1
./tools/check-engine-loop.ps1 -CueOnly
```

세 명령을 모두 연속 실행해야 하는 것은 아니다. `-WhatIf`는 파일/시험 제품 생성 전 미리 보기다. 기본 모드는 대표 전체 루프, `-CueOnly`는 함정 예고/재개의 짧은 범위만 두 재로딩 방식에서 검사한다. 짧은 성공을 전체 완주/저장/사용권 검사의 성공으로 세지 않는다. 기본 검사는 준비/컴파일 외 실제 엔진 구간에 약 15분이 걸렸고 시간은 PC 상태에 따라 달라진다.

도구는 커밋을 `Logs/EngineLoopChecks/<새 GUID>/Project`에 내보내고 기본 Assets 인덱스 정의를 직접 만든다. 개인 `Search.settings`·검색 기록·계정 파일을 복사하지 않는다. SDK로 시험 회사/제품을 준비하는 편집기를 먼저 종료한 뒤, 해당 고유 제품으로 새 편집기를 시작한다. 열린 개인 편집기/플레이어는 종료시키지 않고 도구가 중단한다. 개인 Greed 저장값과 원본 PlayerSettings는 전후 읽기 전용 비교다.

최종 `report.json`은 당시 도구/소스 ZIP 해시, 소유 프로세스 종료, 실제 엔진의 보존 아카이브 경로/해시와 설정 불변을 포함한다. 엔진이 실패 보고서를 남겼다면 외부 실행 실패에도 그 원인/경로를 함께 보존한다. 잘못된 ID·비동기 검사에 `-quit` 혼용·인덱스 누락은 시작 전에 거부한다. 로그/실패 자료/시험 제품은 유지하며 초기화·알림·예약·PC 종료를 설치하지 않는다.

10월 21일 기본 전체 모드와 짧은 모드, 실제 시작 보호 세 가지, 보고서 읽기 일곱 조건이 통과했다. 별도 사본의 비개발 Windows 전체 스모크/빌드와 시험 코드 배포 제외도 통과했다. 게임 입력 15파일은 두 사본 모두 `1084cdf`와 동일한 Git 경로 필터로 대조했다. 새 렌더/실제 창 입력·가청 소리·휴대폰 성능 검사는 아니며 개인용 실행본/ZIP은 14:15/background-results 그대로다. 근거는 [확인 이력](GreedLast_Prototype_CheckHistory.md)의 전용 엔진 도구 완료 절을 따른다.

## 시험 코드 배포 제외

검사 코드는 원본에서 `Assets/Editor/GreedLastPlayerPersistenceProbe.cs.txt` 텍스트 자산이다. 정식 스모크는 런타임 타입 부재를 검사하고 정식 실행본 검증 도구도 해당 네임스페이스가 들어 있으면 거부한다.

도구의 네 가지 음성 대조는 잘못된 빌드 ID, 경로 탈출 단계 이름, 다른 출력 루트, 시험 DLL이 섞인 가짜 배포를 각각 거부하는지 확인한다. 가짜 배포는 정적 검사에만 사용하고 실행하지 않는다.

## 선택적 오프스크린 렌더

`-CaptureFrames`는 그래픽 장치가 있는 시험 플레이어에서 실제 로비·연습 시작·함정·일시정지·재개 카운트·같은 함정 재개·연습 결과를 PNG로 남긴다. 게임 시계나 피해를 직접 바꾸지 않으며, 실제 카메라에 현재 UI를 잠깐 연결해 RenderTexture로 그린 뒤 원래 오버레이/카메라 연결을 복원한다. 프레임 크기·색상 변화·서로 다른 이미지와 정지 중 거리/체력/실수 불변을 대조한다.

이는 숨긴 창의 화면 버퍼나 OS 바탕화면 캡처가 아니다. 이 환경의 숨긴 창/배치 `ScreenCapture`는 검게 나왔고 실패로 보존했다. 오프스크린 렌더 성공으로 이 실패를 대체하거나 실제 화면·손/기기 검사를 완료했다고 표시하지 않는다. 옵션이 없으면 렌더는 미실행이며 종료·재실행 단계만 검사한다.

자동 명령 입력으로 얻은 연습 결과/추천 보정은 사람의 입력 지연 측정값이 아니다. 개인 보정값에 복사하지 않는다.

## 실제 창의 저장과 두 번 사용

`./tools/check-player-persistence.ps1 -InteractiveLoadout`은 고유 제품의 초기 연습/일반 완주만 SDK로 준비하고, 이후 메뉴를 외부에서 직접 누르도록 기다린다. 다른 세 옵션 `-InteractiveWindow`/`-CaptureFrames`/`-BackgroundResults`와 혼용하면 생성 전에 거부한다. 개인 조합/진행도를 쓰지 않는다.

1. 일반 탈출 결과에서 저장 슬롯 선택→빈 S3 직접 선택→저장을 한 번 확정한다. 저장 관리 재진입 시 후보가 없어야 한다.
2. 무한 준비에서 기프트/유물을 고른 뒤 로비로 취소한다. 사용권은 2회다. 이 취소를 먼저 관찰해야 첫 시작 검사가 통과한다.
3. 다시 준비하고 실제 시작을 별도로 확정한다. 2→1만 차감한다. 무입력/무적 OFF 체력 0 자연 종료 뒤 로비에서 한 번 정산한다.
4. 두 번째 준비/실제 시작은 1→0·슬롯 자동 비움이며 현재 런은 이어진다. 다시 자연 종료하고 로비로 돌아온다.
5. `window-loadout-ready.json`의 `nativeLoopCompleted`가 참인 뒤 실제 창 X/Alt+F4로 닫는다. 두 새 헤드리스 프로세스가 기록 2회/성장/빈 슬롯의 중복 없는 보존을 확인한다.

대화형 단계의 기한은 600초이며 준비 취소 누락·조기 종료/시간 초과를 성공으로 표시하지 않는다. 단계별 관찰 JSON과 외부 실제 입력 기록을 함께 읽는다. 10월 22일 `a992f24926364cdfb1beff620186cc7b`의 세 단계·네 안전 대조가 통과했으며 클리어 1·무한 2·성장 5·세 슬롯 0을 두 재실행에서도 유지했다. 시험 관찰기 변경이며 실제 손 리듬/소리·기기 성능이나 새 게임 배포가 아니다.
