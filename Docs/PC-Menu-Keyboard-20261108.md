# 긴 PC 메뉴 본문 읽기

프로필·기록·저장 비교 본문은 길어질 때 별도 스크롤 영역으로 표시한다. PC 독자가 선택 버튼과 본문을 구분해 읽을 수 있도록 이 세 메뉴에서 PgUp/PgDn으로 한 화면보다 조금 적게 이동하고 Home/End로 본문 처음/끝에 이동한다. 버튼 위치·선택·확정·저장 규칙은 바꾸지 않는다. 실행 중 개발용 PageUp/PageDown/End는 기존 경로를 유지한다.

입력 순서는 기존 ESC/P·개발 키·Enter·회전·채널 선택 뒤 본문 이동이다. 같은 프레임의 명시적 선택/확정을 본문 이동이 가로채지 않는다. Control/Alt/system modifier 차단과 화면 미표시 전환 차단을 유지한다. 숨긴 본문·짧은 본문·소유 중인 본문/손잡이 포인터·입력 취소 프레임에는 적용하지 않고, 유효한 본문 이동은 이전 스크롤 관성을 멈춘다.

검사는 실제 Unity ScrollRect 기하의 페이지 이동·문맥 겹침·경계·관성과 제어권 차단, 실제 저장 비교의 두 보기에서 다섯 명령씩 및 command/focus/app 취소·다음 프레임 복구를 포함한다. 각 동작 뒤 슬롯·사용권·후보·성장·클리어 기록이 같은지 확인한다. 검사 코드가 있다는 이유로 통과로 기록하지 않고 아래 실제 실행 결과를 추가한다. 키보드 읽기는 본문/손잡이의 물리 드래그 통과를 대신하지 않는다.

현재 상태: `878b01c`의 전체 스모크·Windows 후보 `abf22860b8914c82b01689e5895715df`와 아래 메뉴 프레임 검사가 통과했다. 개인 저장·원본 설정은 유지됐다. 전체 실행 흐름과 OS 키 입력·물리 드래그는 후속 확인 중이다.

같은 입력의 두 재로딩 조건 메뉴 전용 Play Mode `e420464e8da94f86a1425ed10f2c98da`도 통과했다. 조건마다 실제 저장 비교 두 보기의 키보드 명령 10개, 취소 6개와 다음 프레임 복구 6개를 확인했고 저장 자료를 보존했다. 보고서 SHA256 `69B503249BBBF5C726908D834198A4DB69C4F82F729245F2256E36CF6885817D`. 이 검사는 실제 엔진 프레임과 앱 입력 경로를 사용하지만 OS 키 주입이나 사람이 하는 물리 드래그는 아니다.

첫 후보 `97560b081fab4aed8850de14ea17112b`에서는 새 ScrollRect 기하 검사가 통과했지만, 기존 PC 안내 검사가 모든 PgUp 문구를 개발 키로 금지해 실패했다. `878b01c`는 허용할 ` / 휠·PgUp/PgDn 본문`만 정확히 분리하고 나머지 안내의 개발 키 금지를 유지했다. 모바일 안내의 기대값은 바꾸지 않았다. 실패를 성공으로 재분류하지 않고 별도 후속 후보를 실행했다.
