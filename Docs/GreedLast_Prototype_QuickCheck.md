# Greed Last 프로토타입 빠른 확인

기준: 2026-10-09 종료 뒤 ESC와 저장 확인 입력 보호. 기존 성장 보호·누적 진행·메뉴 배치·비개발 도구 잠금·무한모드 분리는 유지한다. 목표는 기획서의 직선 달리기·회피·리듬 보상과 일반 런→한 번 저장→무한 두 번 시작을 체감하는 프로토타입이다. 누적 검사와 과거 추가 안내는 [확인 이력](GreedLast_Prototype_CheckHistory.md), 상세 회귀는 [전체 체크리스트](GreedLast_Prototype_Checklist.md)에 있다.

## 실행

1. Unity Hub에서 `C:\Projectunity\greed last`를 Unity 6.4로 연다.
2. `Assets/Scenes/GreedLast_Boot.unity`를 열고 가로 Game 뷰에서 Play한다.
3. Unity 없이 볼 때는 `Builds/GreedLastPrototype/GreedLastPrototype.exe`를 연다.
   같은 검증 빌드의 보존 패키지는 `Builds/GreedLastPrototype-verified-20261009-slot-change.zip`이다. 평소 확인은 위 실행 폴더를 사용한다. 이전 result-confirmation/growth-input/progress-layout/progress/release-tools ZIP은 앞선 보존본이다.
4. 기존 진행도와 보관할 저장 조합은 유지한다. 확인 때문에 초기화하거나 보관할 조합을 삭제·소모하지 않는다.

처음부터 끝까지 한 환경에서 확인한다. 에디터 Play와 Windows 실행 파일은 [Unity의 PlayerPrefs 저장 위치](https://docs.unity3d.com/6000.4/Documentation/ScriptReference/PlayerPrefs.html)가 달라 처음 보이는 조합/설정이 다를 수 있다. 환경을 옮긴 뒤 빈 슬롯을 기존 저장 소실로 단정하거나 레지스트리를 직접 복사·초기화하지 않는다.

## 이번 추가분 먼저 확인

슬롯을 바꿀 때도 새 명령이 필요하다. 저장 버튼을 누른 채 A/S/D로 다른 칸을 고른 뒤 이전 누름을 떼어도 저장하지 않아야 한다. 새 탭만 선택한 칸에 한 번 저장한다. 삭제/이름 변경/무한 준비도 같은 원칙이며 보관할 조합을 시험용으로 삭제하지 않는다. `Greed Last/Run Held Slot Change Check`가 여섯 경로를 격리 검사한다.

1. **종료 뒤 ESC**: 연습 완료/실패·일반 실패·무한 종료 화면에서 ESC로 로비에 돌아오는지 본다. 결과/성장 보상은 한 번만 반영돼야 한다. 일반 클리어 뒤 ESC는 저장 후보를 버리지 않고 저장 슬롯 선택을 연다. 진행 중 ESC/P의 정지·재개는 그대로다.
2. **확인 화면의 새 입력**: 덮어쓰기·삭제·이름 변경·저장 포기 확인을 열기 전부터 누른 두 번째 손을 늦게 떼어도 확정되지 않아야 한다. 확인 화면에서 보호 뒤 새 탭은 정상이다. 보관할 개인 조합을 확인용으로 삭제할 필요는 없다. Play 중지 뒤 `Greed Last/Run Held Save Confirmation Check`가 여섯 경로를 격리 검사한다. `Greed Last/Run Result Back Navigation Check`는 결과 뒤로 가기와 저장 후보 보호를 검사한다.
3. **저장 기회 유지와 소비**: 일반 클리어→ESC→원하는 빈 칸 선택→저장 한 번을 따른다. 저장 포기 확인을 ESC로 연 뒤 예전 로비 버튼 누름을 떼는 것만으로 후보를 버리지 않아야 한다. 저장 또는 의도적인 포기 뒤에만 같은 후보가 없어지며, 무한 준비 취소 무소모/실제 두 번 시작·자동 비움은 유지한다.

## 앞선 성장·기록 확인

1. **성장 본문과 한 번 구매**: 로비→성장에서 위쪽 본문/스크롤과 아래쪽 생존·집중·타이밍 선택이 분리되는지 본다. 강화하려던 항목이 있을 때만 잔액/레벨이 한 번 바뀌는지 확인한다. 입장 때 유지한 손을 새 구매 버튼으로 옮겼다 떼거나, 추천이 바뀌는 빠른 연타/이미 누른 두 번째 손을 늦게 떼는 것만으로 추가 구매되면 안 된다. 보호 시간 뒤의 새 탭은 정상 구매한다. 개인 포인트를 확인용으로 소모할 필요는 없다. Play 중지 뒤 `Greed Last/Run Growth Command Protection Check`는 개인 데이터 없이 다섯 경우를 검사한다.
2. **보상·기록·시작 보너스**: 정확/Good/Miss의 실제 점수 증가, 종료 뒤 기록 한 번 반영과 재진입 시 같은 점수/등급/거리를 본다. 무한은 일반 누적 점수/판정 수를 이어받지 않고 기존 조합 시작 보너스만 받는다. 큰 수는 Play 중지 뒤 `Greed Last/Run Progress Boundary Check`와 `Greed Last/Run Record Statistics Boundary Check`의 격리 검사로 확인할 수 있다. 직접 큰 값을 만들거나 개인 저장값을 편집하지 않는다.
3. **처음부터 전체 흐름**: 아래 12단계를 한 환경에서 따른다. 일반/연습/탈출과 무한 동작 분리는 유지한다. 선택한 입력을 유지·해제하는 것만으로 다음 선택을 넘기지 않고 저장 확정은 한 번만, 실제 무한 시작은 사용권 하나만 차감해야 한다. 두 손가락 검사는 격리 검사와 실제 휴대폰 확인을 구분한다.

## 입력·복구 함께 확인

1. **보정과 판정**: 평소 보정값으로 기초 연습의 정확/Good/입력 없음을 본다. 음수 보정으로 늦게 도착한 유효 Good을 원래 충돌 시각에 미리 놓치지 않아야 한다. 보정 입력을 기다리는 짧은 구간은 `보정 입력 대기`이며 실제 입력 전 점수/판정을 만들지 않는다. 기본/F11 상세가 같아야 하고 박자음/함정 이동은 옮겨지지 않는다. 필요할 때만 다른 보정값을 시험하고 끝나면 원래 값으로 돌린다.
2. **소리 복구와 재개**: 선택적으로 주행 중 출력 장치를 바꾼다. Unity가 변경을 통지하면 정지 메뉴가 뜨고 오래된 소리는 멈춰야 한다. 재개 2→1→GO와 앞 여유 뒤 같은 함정/박자음이 이어져야 한다. 재개 중 재변경은 다시 정지하며 볼륨/진동/기울임/시야 안정 설정은 유지한다. 자동 검사는 모의 콜백이며 실제 블루투스 지연을 측정한 것은 아니다.
3. **중단 뒤 명령**: 정지/장치 변경/앱 전환을 가로질러 누르던 버튼을 떼는 것만으로 재개하거나 로비로 나가면 안 된다. 화면 갱신이 오래 멎어 자동 정지한 경우 체력/거리/집중과 같은 함정을 유지하고 직접 재개해야 한다. 일부러 PC를 멎게 할 필요는 없다. 에디터의 격리 `Run Frame Interruption Check`와 전체 Play 모드 검사로 확인할 수 있다.

4. **복귀 전 새 입력**: 기초 연습에서 정지→Alt+Tab→복귀를 한다. 복귀만으로 재개하지 않고 새 재개 입력을 기다려야 한다. 일반 런 시작 기프트도 기존 선택을 유지하고 새 탭만 받는다. 에디터에서 선택적으로 `GreedLastApp` 컴포넌트만 껐다 켜면 남은 화면의 버튼/긴 본문 스크롤은 중단 동안 움직이지 않고, 복귀 후 원래 잠금과 스크롤 위치를 유지해야 한다. 중단 전 또는 중단 중 시작한 누름/드래그를 떼는 것만으로 명령이 실행되면 안 된다. 개인 데이터를 초기화할 필요는 없다.

## 앞선 변경 함께 확인

1. **재생과 재개**: Play 중지→다시 Play→로비→연습→ESC/P→재개를 본다. 앱/화면/소리가 겹치지 않고 같은 함정을 `2→1→GO`로 이어야 한다. 에디터에서 선택적으로 런타임 `GreedLastApp` 오브젝트를 껐다 켜도 비활성 동안 거리/집중/체력이 변하지 않고 정지 메뉴로 복원돼야 한다. 삭제나 진행도 초기화는 필요 없다. 씬 재로드/자원 정리는 Play를 멈춘 뒤 `Greed Last/Run Engine Play Mode Lifecycle Check`의 격리 검사로도 볼 수 있다.
2. **한글과 안내 간격**: 포함한 Noto Sans KR 보통/굵은 글꼴을 쓴다. 작은 창과 태블릿 크기에서 한글·회전 `⭯`/`⭮`가 네모로 바뀌지 않아야 한다. 타이밍 안내와 행동/판정 두 줄, 진행 글자와 막대, 체력/집중 숫자가 겹치거나 잘리지 않아야 한다. 정확/Good/Miss와 F11 왕복, 가장 큰 GO를 함께 본다. 글꼴 설치는 필요 없다.
3. **전환 잔상**: 실제 입력이나 Miss 뒤 정지·로비·선택·기록·종료로 옮긴다. 이전 함정/띠/입력 파동/피격이 남지 않고 새 입력과 점수/소리가 한 번씩 나와야 한다. 확인 때문에 보관할 조합이나 개인 보정/설정을 초기화하지 않는다.

## 처음부터 눌러볼 순서

복기 버튼이 나타나는 기존 일반/무한 결과가 있다면 먼저 눌러 본다. `숙이기 복기`는 2단계, `비틀기 복기`는 3단계부터 시작하며 완료 뒤 `복기 다시 확인`으로 같은 단계에 돌아와야 한다. 기본 연습은 기존 1→2→3 순서다. 이 확인을 위해 진행도나 보관할 조합을 초기화할 필요는 없다.

1. **진입**: 타이틀의 도깨비 소녀와 피라미드 통로 뒤로 입구 로비가 자동으로 열린다. 개발 연결 전환을 누를 필요는 없다.
2. **기초 연습**: 로비의 기초 연습/다시 연습으로 들어간다. 바닥 가시·상단 칼날·측면 날과 점프·숙이기·비틀기가 구분되고, 판정선에 도달할 때 같은 채널을 누른다. 정확/Good/Miss의 수치와 소리가 달라야 한다. 정확/Good의 `+N점`이 총점의 실제 증가량과 같아야 하며 조금 빠른/늦은 Good은 방향이 맞아야 한다. 다른 레인을 한 번 눌러 실제 누른 레인의 Miss와 정답 안내가 분리되는지 본다. 아무것도 안 누른 함정은 `입력 없음`으로 구분되고 타이밍 보정 조언이 없어야 한다.
3. **기본/상세 화면**: 처음부터 기본 표시로 시작한다. 큰 제목, `연습 1/3`과 진행 막대가 분리되어야 한다. 중복 연습 배너는 없어도 시작음은 난다. 에디터 F11로 상세 표시를 열면 실제 빠름·늦음 방향은 그대로이고 판정이 다시 재생되지 않아야 한다. 상세 설명은 게이지를 덮지 않으며 작은 창/태블릿에서도 글자가 잘리지 않아야 한다. 복기 런에서 목표·경로/묶음 보상·새 보정 추천이 함께 나와도 모두 영역 안에 남고 F11 왕복으로 다시 재생되면 안 된다. 다시 F11로 기본 표시로 돌아온다.
4. **정지 메뉴와 보정**: 아래 `일시정지` 또는 Enter/ESC로 멈춘다. 별도 메뉴와 `보정 0ms` 등 현재 적용값이 나오고 뒤의 레인 입력·거리·피해는 멈춘다. 빠름/늦음 조절은 ±20ms씩 즉시 표시되고 0ms 복귀도 바로 반영된다. 포기는 이 메뉴 안에서만 보인다. 바꿔 본 설정은 원래 값으로 돌린다.
5. **재개와 테스트 복귀**: 재개 숫자가 뜰 때 Alt+Tab했다 돌아온다. 다시 정지해 있어야 한다. 새로 재개하면 카운트와 앞 여유 뒤 같은 함정이 이어지고, 대기 시간이 거리나 피해로 더해지면 안 된다. 버튼을 누른 채 F11을 바꿔 손을 떼면 명령은 실행되지 않는다. 상세 화면에서 자동 정지→F11 기본→`함정 재개`를 누르면 다음 함정까지 다시 이어져야 한다. 기본 표시에서 F6 집중 MAX나 무한 PageUp/PageDown 후 F11을 열면 도구 문구가 현재 값과 일치하고, 정지/종료 중 잠긴 도구가 다시 활성화되면 안 된다.
6. **일반 런 시작과 선택**: 연습 결과의 `일반 런으로` 또는 로비의 일반 런을 누른다. 진입 탭이 시작 기프트를 자동 선택하면 안 된다. 시작 기프트→카운트·챕터 배너→첫 함정으로 이어진다. 챕터 뒤 루트를 고르면 기프트가 나오며 빠른 두 번 클릭이 다음 선택까지 건너뛰면 안 된다.
7. **주행과 회전**: `N장 · 통과 수/목표`가 갱신되고 정확 입력의 집중·반격·연쇄 보상이 보여야 한다. 안정 루트에서 피해 후 Good 회복과 정확 묶음 완주의 실제 회복은 `체력 +N`과 게이지가 일치해야 한다. F11 상세의 경로 진행/중단 설명에는 다음 박자와 동작이 남고 작은 창에서도 판정·게이지가 겹치지 않아야 한다. 에디터 F9로 회전 통로를 골라 Q/E를 눌러볼 수 있다. 통로만 제한적으로 기울고 HUD·판정선은 고정되어야 한다.
8. **공명핵과 탈출**: 일반 런의 선택과 함정을 끝까지 통과한다. 빠른 에디터 확인은 F1 무적과 F4 핵 직후/F5 탈출 직전을 쓴다. 마지막 게이트 뒤 클리어 점수·기록과 `저장 기회 1회`가 나타나야 한다.
9. **한 번만 저장**: 결과의 `저장 슬롯 선택`을 누르고 빈 S2/S3 등 원하는 칸을 골라 확정한다. 같은 클리어 후보를 다시 저장할 수 없어야 한다. 덮어쓰기·이름 변경·삭제·저장 포기는 빠른 두 번 클릭으로 확정되지 않아야 한다. 관리 동작은 소모해도 되는 조합에만 시험한다.
10. **무한 준비 취소**: 소모해도 되는 조합을 골라 준비에 들어간다. 진입 탭이나 기프트/유물 연타가 다음 선택·실제 시작까지 넘기면 안 된다. 취소는 2회 그대로이며 별도 실제 시작만 2→1로 줄어야 한다.
11. **두 번째 시작과 자동 비움**: 첫 무한을 정산한 뒤 같은 조합으로 다시 실제 시작한다. 슬롯은 자동으로 비지만 이미 시작한 런은 계속된다. 무적 OFF의 체력 0 종료와 기록 요약을 확인한다. 에디터 End는 테스트 정산용이며 일반 빌드에는 없다.
12. **기록과 재시작**: 로비의 기록 보드에는 실제 기록만 나오고 개발 메모·설정 안내가 섞이지 않아야 한다. 새 기초 연습은 0점·새 체력·새 카운트로 시작하며 이전 피격·결과가 남지 않아야 한다.

## 모바일에서 추가 확인

현재 Unity 6.4 설치의 `PlaybackEngines`에는 Windows 지원만 있다. Android 빌드와 휴대폰 센서/오디오/FPS 검사는 아직 실행하지 않았으며 아래 항목은 실기기 확인 단계다.

1. 가로 방향을 좌우로 바꿔도 기울임 방향이 뒤집히거나 떨리지 않아야 한다.
2. 기울임 ON은 좌우 입력 뒤 중립으로 복귀해야 다음 입력이 한 번 들어간다. OFF는 좌우 탭으로 대응하며 센서 커서/중립 게이트를 숨긴다.
3. 앱 전환→재개, 두 손가락 입력, 노치/크기 변경과 소리 지연은 실제 휴대폰에서 확인한다.
4. 앱 재실행 뒤 소리·진동·기울임·시야 안정·보정 설정이 유지되어야 한다.
