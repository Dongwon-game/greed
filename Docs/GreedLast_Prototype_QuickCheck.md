# Greed Last 프로토타입 빠른 확인

## 확인 목표

- 템플런처럼 한 방향으로 달리며 함정을 읽는지 확인한다.
- `위험 확인 → 맞는 동작 → 박자 입력 → 정확 보상`이 한 덩어리로 느껴지는지 확인한다.
- 회전 통로는 화면 전체가 돌지 않고 통로만 살짝 기울며, 모바일에서는 폰 기울임 또는 좌우 탭으로 대응하는지 확인한다.
- 일반 런에서 만든 조합이 무한모드에 이어지고 두 번 사용한 뒤 자동으로 비워지는지 확인한다.

## 시작 전

1. Unity Hub에서 `C:\Projectunity\greed last`를 Unity 6.4로 연다.
2. Game 뷰를 가로 화면으로 두고 Play를 누른다.
   부트 씬은 `Assets/Scenes/GreedLast_Boot.unity`다. 기존 진행도는 이 확인만으로 초기화하지 않는다.
3. 프로토타입 저장은 실행 사이에 유지된다. 현재 로비가 가리키는 강조 버튼부터 이어서 확인하면 된다.
4. 공유용 실행 파일이 필요하면 재생을 멈춘 뒤 `Greed Last > Build Verified Windows Prototype`을 실행한다. 전체 스모크를 통과한 경우에만 `Builds/GreedLastPrototype/GreedLastPrototype.exe`가 갱신된다.

## 에디터 조작

- 좌 / 중 / 우: `A` / `S` / `D` 또는 방향키 / Space
- 회전 통로: `Q` / `E`
- 일시정지: `ESC` 또는 `P`
- 무적: `F1`
- 기프트 / 유물 / 핵 직후 / 탈출 직전 바로가기: `F2` / `F3` / `F4` / `F5`
- 집중 MAX: `F6`
- 목표 / 경로 / 동작 / 낙하 보기: `F7` / `F8` / `F9` / `F10`
- 테스트 버튼 숨김 / 복원: `F11`. 무적과 바로가기 키는 그대로 작동하며, 소리·보정 설정은 `ESC` 메뉴에서 다시 보인다. 일반 실행 빌드에서는 테스트 버튼 없이 이 화면이 기본이다.
- 무한 위협 조절: `PageUp` / `PageDown`
- 무한 정산 종료: `End`

## 이번 그래픽 변경만 먼저 볼 때

1. Play 후 타이틀에서 입구 그림을 보고, 로비에서는 중복 캐릭터·좌중우 글자·노란 사각형·판정선이 사라졌는지 확인한다.
2. 연습이나 일반 런으로 들어가면 움직이는 도깨비 소녀와 입력 레인·판정선이 다시 보여야 한다.
3. 일반 런에서 `F11`로 테스트 버튼을 숨긴 뒤 `F1`과 `F9`를 사용해도 무적·동작 확인이 그대로 작동하는지 본다. 연습에서는 일부 개발 바로가기를 제한하므로 이 확인은 일반 런에서 한다.
4. `ESC` 메뉴에서는 소리·보정·진동·기울임·시야 안정 버튼이 메뉴 안에 보여야 한다. `시야 안정`을 직접 눌러 글자가 바뀌는지 확인한다. 재개 중에는 제목 숫자가 내려가고 재개 준비 버튼은 비활성화되며, 달리기가 다시 시작되면 설정 버튼은 다시 숨는다. `F11`을 다시 누르면 개발 버튼이 복원된다.
5. 가시·칼날문·측면 회전날과 캐릭터 그림이 찌그러지거나 배경 사각형 없이 보이는지 확인한다.
6. 주행 중 소개 문구가 주자 위에 쌓이지 않고, 전환 배너는 입력 레인 위쪽에 나타나야 한다. 동작 안내는 주자 아래에 보이며 판정 피드백과 동시에 겹치지 않아야 한다.
7. 일반 런 클리어 후 선택지·요약·저장 슬롯 글자는 그대로 표시되는지 확인한다. 이번 주행 문구 숨김은 결과 화면을 숨기지 않는다.

해상도별 고정 화면은 `Greed Last > Capture Prototype Visual Checks`로 생성한다. `Logs/VisualChecks`의 PNG는 화면 배치 비교용이며 실제 플레이 결과는 아니다.

## 2026-09-16 소리와 재개 확인

기존 진행도를 초기화하지 않고 아래 순서로 확인한다. 이번 변경은 음량·백그라운드 피드백·박자 예약 처리이며 판정 폭, 저장 기회 1회, 조합 2회 사용 규칙은 그대로다.

1. `GreedLast_Boot`에서 Play하거나 검증된 Windows 실행 파일을 연다. 로비에서 기초 연습 또는 일반 런에 들어가 선택→카운트→첫 함정의 소리를 듣는다.
2. 달리는 중 ESC를 누른다. 주행 박자는 멈추고, 메뉴 안의 소리 설정을 0으로 바꾸면 설정 미리듣기도 없어야 한다. 다시 음량을 올리면 선택한 크기로 돌아와야 한다. 볼륨을 절반으로 낮췄을 때 두 번 곱해져 지나치게 작아지면 안 된다.
3. 재개를 누른 직후 Alt+Tab으로 다른 창으로 갔다 돌아온다. 게임은 다시 정지 상태여야 한다. 재개를 누르면 카운트의 첫 박자부터 다시 시작하고 GO 뒤 함정에 대응할 여유가 있어야 한다. 멈춰 있던 소리가 한꺼번에 재생되면 안 된다.
4. 재개와 창 전환을 두 번 더 반복한다. 첫 박자가 빠지거나 GO가 겹치지 않아야 한다. 로비로 돌아갔다 새 연습을 시작해도 이전 런의 카운트가 이어지면 안 된다.
5. 모바일에서는 홈 화면/앱 전환 후 복귀로 같은 항목을 본다. 화면 밖에서는 새 소리와 진동이 발생하지 않아야 하고, 복귀만으로 자동 달리기가 시작되면 안 된다. 소리 0과 진동 설정은 서로 독립적이다. 첫 출발 카운트 중 나갔다 돌아와도 함정이나 거리가 진행되면 안 된다. 재개 후에는 남은 시작 준비 시간을 이어간다.
6. 일반 런 클리어→원하는 슬롯 저장→무한모드 준비 취소→실제 시작 2회→자동 비움→기록까지 확인한다. 음량과 재개 변경으로 저장 횟수나 결과가 달라지면 안 된다.

최종 검증: `Logs/prototype-audio-final-verified-20260916.log` 전체 스모크·실제 앱 콜백·Windows 빌드 통과. Runtime UI의 Update와 런 코어를 연결해 정지 중 무박자, 재개 중단, 화면 갱신 없는 새 런, GO 1회와 로비 격리를 검사했다. 첫 출발 중 1시간 경과는 가상 시계로 검사했고 실제로 1시간을 기다린 것은 아니다. 스피커 출력·휴대폰 진동·오디오 지연은 자동 검사하지 않았으며 위 직접 확인이 필요하다.

화면 검증: `Logs/prototype-audio-visual-20260916.log`의 68장 통과. 버튼 입력 67시나리오, 레인/확대 영역 입력 213시나리오, 본문 스크롤 17시나리오 통과. 작은 정지 메뉴와 태블릿 재개 화면도 직접 이미지로 확인했다. 테스트 입력 컴포넌트와 편집기 검사는 실행 빌드에 포함하지 않는다.

## 2026-09-15 추가 입력 확인

이번 수정은 회전 테스트 드래그와 UI 조작의 충돌을 막는다. 그래픽·박자 판정·저장 규칙은 변경하지 않았다.

1. 일반 런에서 F9로 회전 통로까지 이동한다. 레인·버튼이 없는 빈 통로에서 마우스를 누르고 좌우로 끌면 회전 테스트가 동작해야 한다. 레인이나 일시정지/개발 버튼 위에서 시작한 조작이 회전 드래그로 함께 처리되면 안 된다. Q/E와 모바일 기울임은 그대로다.
2. 레인의 중앙과 가장자리 안쪽을 각각 길게 누른 뒤 놓는다. 판정은 누르는 순간 한 번이며, 유지·놓기에서 추가 판정이 없어야 한다. 옆 레인까지 누른 채 끌어도 그 레인이 새로 눌리면 안 된다. 모바일에서는 두 손가락을 하나씩 떼거나 창 전환 후 다시 누를 때 눌림 표시와 입력이 복원되는지 본다.
3. 저장·기록의 일반 버튼은 놓을 때 한 번만 실행된다. 누른 채 버튼 밖으로 이동한 뒤 놓으면 실행되지 않아야 한다. 모바일 시스템 제스처로 터치가 취소된 경우에도 실행되면 안 된다.
4. 저장 덮어쓰기 비교나 긴 기록 본문을 휠과 드래그로 각각 스크롤한다. 본문 아래 슬롯이 선택되면 안 되며, 드래그를 취소한 뒤 새 탭에서 본문이 갑자기 이동하면 안 된다. 남겨둘 조합으로 삭제 테스트를 하지 않는다.
5. 일반 런 클리어→S3 저장→무한 준비→두 번 사용→슬롯 자동 비움→기록 확인으로 마친다. 같은 클리어 후보를 두 번 저장하거나 조합을 세 번째 사용할 수 없어야 한다.

최종 검증: `Logs/prototype-touch-final-verified-20260915.log` 전체 스모크·앱 콜백·Windows 빌드 통과. `Logs/prototype-touch-final-visual-20260915.log` 화면 68장, 버튼 입력 시나리오 67회, 레인/확대 터치 영역 입력 시나리오 213회, 본문 스크롤 시나리오 17회 통과. 실제 StandaloneInputModule에 합성 마우스·터치를 공급했으며, 터치와 마우스 에뮬레이션 중복·포커스 상실 후 남은 터치·이웃 레인으로 끌기도 검사했다. 숫자는 여러 해상도에서 반복한 시나리오 수다. 실제 모바일 센서·오디오 지연·손 조작 검사는 별도다.

3. `기울임 OFF`에서는 회전 통로 안내가 좌 / 우 탭으로 바뀌고 센서 커서, 손잡이, 중립 게이트가 숨는지 본다.
4. 앱을 종료해 다시 열어도 소리, 진동, 기울임 설정이 유지되는지 본다.
