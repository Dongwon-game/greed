## 이번 추가분 먼저 확인

1. **정비 결과 유지**: 소모해도 되는 조합의 무한 결과에서 바로 다음 정비로 들어간다. 기프트/유물을 고르고 다시 고르거나 다른 조합을 선택해도 현재 정비가 먼저, 직전 결과가 아래 스크롤에 한 번만 남아야 한다. 정비 또는 조합 관리에서 취소해도 기록 완료 안내가 남고 추가 정산/차감은 없어야 한다.
2. **첫 카운트 포기**: 아래 기본 12단계용과 다른 임시 조합으로 실제 무한 시작 후 첫 카운트 중 일시정지한다. `기록 없이 로비`와 `사용권 차감 유지`가 보여야 한다. 종료하면 기록/성장 보상은 늘지 않고 실제 시작의 사용권은 차감된 채 유지된다. 남은 조합은 새 정비, 소진된 조합은 보충으로 안내한다. End 정산 테스트는 진행도를 만들므로 이 확인 대신 쓰지 않는다.
3. **클리어 직후 정상 종료**: 일반/보충 런의 탈출 결과에서 저장 선택을 누르기 전에 창을 정상 종료한다. 같은 환경 재실행 뒤 클리어/후보가 남고 직접 칸을 고르기 전 저장은 잠겨 있어야 한다. 원하는 칸에 한 번 저장하며 기존 슬롯/사용권과 이미 저장/포기한 후보는 변하거나 되살아나면 안 된다. 강제 종료·전원 단절·휴대폰 회수의 보장은 아니다.
4. **실패·무한 결과 직후 정상 종료**: 일반 실패 또는 임시 조합의 무한 체력 0 결과에서 다음 버튼/로비로 가기 전에 정상 종료한다. 같은 환경에서 다시 열어 기록 보드에 해당 결과가 한 번만 남고 성장 보상이 반복되지 않는지 본다. 이미 정산한 뒤 종료해도 중복되면 안 된다. 주행 중/일시정지 종료의 자동 저장·이어하기는 이번 범위가 아니다.

자동 대조가 필요할 때만 Play를 중지하고 `Greed Last > Run Infinite Retry Review Check` 또는 `Run Clear Quit Recovery Check`를 쓴다. 전자는 격리 정비/시작/카운트 포기, 후자는 시험 키의 종료 콜백·재읽기/한 번 저장을 검사한다. 실제 OS 창 닫기·손/기기 검사는 별도다. 이전 `Run Record Distance Recovery Check`도 유지하며 개인 기록에 잘못된 값을 주입하거나 보관할 조합/포인트를 소모하지 않는다.

직접 플레이는 [기획 체감 다섯 가지](GreedLast_Prototype_PlanCoverage.md)의 직선 주행·함정 가독성·정확 타이밍 이득·제한된 회전·한 판 마무리가 우선이다. 앞선 체력/집중·채점 안내의 세부 비교는 전체 체크리스트로 옮겨 보고, 아래 12단계는 기본 표시에서 진행한다. 집중 중 Miss도 기존처럼 피해를 받는다.

## 세부 검사는 필요할 때

성장 구매·입력/저장 보호·오디오 장치 변경·앱 전환·프레임 중단·한글/회전 기호·전환 잔상의 자세한 항목은 Unity의 `Docs/GreedLast_Prototype_Checklist.md`를 따른다. 개인 포인트나 보관할 조합을 확인용으로 소모하지 않는다. 먼저 아래 12단계를 한 환경에서 보고 문제가 있는 구간만 상세 검사로 돌아온다.

## 처음부터 눌러볼 순서

복기 버튼이 나타나는 기존 일반/무한 결과가 있다면 먼저 눌러 본다. `숙이기 복기`는 2단계, `비틀기 복기`는 3단계부터 시작하며 완료 뒤 `복기 다시 확인`으로 같은 단계에 돌아와야 한다. 기본 연습은 기존 1→2→3 순서다. 이 확인을 위해 진행도나 보관할 조합을 초기화할 필요는 없다.

1. **진입**: 타이틀의 도깨비 소녀와 피라미드 통로 뒤로 입구 로비가 자동으로 열린다. 개발 연결 전환을 누를 필요는 없다.
2. **기초 연습**: 로비의 기초 연습/다시 연습으로 들어간다. 바닥 가시·상단 칼날·측면 날과 점프·숙이기·비틀기가 구분되고, 판정선에 도달할 때 같은 채널을 누른다. 정확/Good/Miss의 수치와 소리가 달라야 한다. 정확/Good의 `+N점`이 총점의 실제 증가량과 같아야 하며 조금 빠른/늦은 Good은 방향이 맞아야 한다. 다른 레인을 한 번 눌러 실제 누른 레인의 Miss와 정답 안내가 분리되는지 본다. 아무것도 안 누른 함정은 `입력 없음`으로 구분되고 타이밍 보정 조언이 없어야 한다.
3. **기본/상세 화면**: 처음부터 기본 표시로 시작한다. 큰 제목, `연습 1/3`과 진행 막대가 분리되어야 한다. 중복 연습 배너는 없어도 시작음은 난다. 에디터 F11로 상세 표시를 열면 실제 빠름·늦음 방향은 그대로이고 판정이 다시 재생되지 않아야 한다. 상세 설명은 게이지를 덮지 않으며 작은 창/태블릿에서도 글자가 잘리지 않아야 한다. 복기 런에서 목표·경로/묶음 보상·새 보정 추천이 함께 나와도 모두 영역 안에 남고 F11 왕복으로 다시 재생되면 안 된다. 다시 F11로 기본 표시로 돌아온다.
4. **정지 메뉴와 보정**: 아래 `일시정지` 또는 Enter/ESC로 멈춘다. 별도 메뉴와 `보정 0ms` 등 현재 적용값이 나오고 뒤의 레인 입력·거리·피해는 멈춘다. 빠름/늦음 조절은 ±20ms씩 즉시 표시되고 0ms 복귀도 바로 반영된다. 포기는 이 메뉴 안에서만 보인다. 바꿔 본 설정은 원래 값으로 돌린다.
5. **재개와 테스트 복귀**: 재개 숫자가 뜰 때 Alt+Tab했다 돌아온다. 다시 정지해 있어야 한다. 새로 재개하면 카운트와 앞 여유 뒤 같은 함정이 이어지고, 대기 시간이 거리나 피해로 더해지면 안 된다. 버튼을 누른 채 F11을 바꿔 손을 떼면 명령은 실행되지 않는다. 상세 화면에서 자동 정지→F11 기본→`함정 재개`를 누르면 다음 함정까지 다시 이어져야 한다. 기본 표시에서 F6 집중 MAX나 무한 PageUp/PageDown 후 F11을 열면 도구 문구가 현재 값과 일치하고, 정지/종료 중 잠긴 도구가 다시 활성화되면 안 된다.
6. **일반 런 시작과 선택**: 연습 결과의 `일반 런으로` 또는 로비의 일반 런을 누른다. 진입 탭이 시작 기프트를 자동 선택하면 안 된다. 시작 기프트→카운트·챕터 배너→첫 함정으로 이어진다. 챕터 뒤 루트를 고르면 기프트가 나오며 빠른 두 번 클릭이 다음 선택까지 건너뛰면 안 된다.
7. **주행과 회전**: `N장 · 통과 수/목표`가 갱신되고 정확 입력의 집중·반격·연쇄 보상이 보여야 한다. 안정 루트에서 피해 후 Good 회복과 정확 묶음 완주의 실제 회복은 `체력 +N`과 게이지가 일치해야 한다. F11 상세의 경로 진행/중단 설명에는 다음 박자와 동작이 남고 작은 창에서도 판정·게이지가 겹치지 않아야 한다. 에디터 F9로 회전 통로를 골라 Q/E를 눌러볼 수 있다. 통로만 제한적으로 기울고 HUD·판정선은 고정되어야 한다.
8. **공명핵과 탈출**: 일반 런의 선택과 함정을 끝까지 통과한다. 빠른 에디터 확인은 F1 무적과 F4 핵 직후/F5 탈출 직전을 쓴다. 마지막 게이트 뒤 클리어 점수·기록과 `저장 기회 1회`가 나타나야 한다.
9. **한 번만 저장**: 탈출 결과에서 저장 선택 전 창을 정상 종료했다 같은 환경에서 다시 열어도 후보가 남아야 한다. 결과/로비의 저장 선택으로 들어가 빈 S2/S3 등 원하는 칸을 직접 고른 뒤 확정한다. 선택 전 저장은 잠겨 있고 저장/포기 후 같은 후보는 없어야 한다. 다음 새 일반 클리어는 다시 한 번 저장할 수 있다. 덮어쓰기·이름 변경·삭제·저장 포기는 빠른 두 번 클릭으로 확정되지 않아야 한다. 보관할 조합을 관리 시험에 쓰지 않는다.
10. **무한 준비 취소**: 새로 저장한 임시 조합의 준비에 들어간다. 진입 탭/선택 연타가 다음 선택이나 실제 시작까지 넘기면 안 된다. 정비 취소는 2회 그대로, 별도 실제 시작만 2→1이다. 이 기본 순서에서는 카운트 포기 없이 11단계의 주행을 이어간다. 위 별도 카운트 포기는 이미 차감한 사용권을 돌려주지 않으므로 같은 두 번 사용 확인에 섞지 않는다.
11. **바로 재도전과 자동 비움**: 첫 무한의 자연 종료 결과에서 재도전/다음 준비를 눌러 같은 조합으로 다시 실제 시작한다. 방금 결과의 최신 복기 목표가 정비와 다음 런에 이어져야 한다. 슬롯은 자동으로 비지만 이미 시작한 런은 계속된다. 무적 OFF의 체력 0 종료와 기록 요약을 확인한다. 에디터 End는 테스트 정산용이며 일반 빌드에는 없다.
12. **기록과 재시작**: 로비의 기록 보드에는 실제 기록만 나오고 개발 메모·설정 안내가 섞이지 않아야 한다. 새 기초 연습은 0점·새 체력·새 카운트로 시작하며 이전 피격·결과가 남지 않아야 한다.

## 모바일에서 추가 확인

현재 Unity 6.4 설치의 `PlaybackEngines`에는 Windows 지원만 있다. Play 중지 뒤 `Greed Last > Check Android Prerequisites`는 모듈 로드 가능 여부와 포함 JDK·SDK/API 36·빌드 도구·NDK 파일을 읽기만 하고 `Logs/AndroidChecks`에 결과를 남긴다. 파일이 모두 있어도 APK 빌드·약관 동의·실제 도구 버전/실행·서명·기기 확인 통과라는 뜻은 아니다. 외부 사용자 지정 도구 설정은 바꾸거나 평가하지 않는다.

10월 17일 21:49 KST 재확인도 지원 없음/아홉 포함 도구 파일 누락이다. 결과는 `prerequisites-20261017-124934-5398744.json`, SHA-256 `B1B78F759777C3C221FA16D2D8551AC5D276BB54418BCA8F8584618EAF653AE9`이며 설치나 동의를 대신하지 않았다.

Android 준비는 Unity Hub의 설치→Unity 6.4 `6000.4.3f1` 관리→모듈 추가에서 Android Build Support와 SDK & NDK Tools, OpenJDK를 함께 확인한다.
