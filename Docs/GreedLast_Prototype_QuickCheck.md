# Greed Last 프로토타입 빠른 확인

시작 화면부터 대표 한 판과 저장/무한 연결을 확인하는 순서다. 현재 소스와 실행본은 아래 최신 기준으로 구분한다. 상세 근거는 [확인 이력](GreedLast_Prototype_CheckHistory.md), 세부 검사는 [전체 체크리스트](GreedLast_Prototype_Checklist.md)를 따른다.

최신 실행본: 2026-10-22 13:51 KST 비개발 Windows/saved-gifts, 게임 소스 `5b5b26d`. 저장 후보 요약·비교 보너스·추천을 실제 기프트 전용 저장 내용에 맞췄으며 일반 클리어 원본의 유물은 유지한다. 한 번 저장·실제 두 번 사용/자동 비움·점수/피해/판정 규칙은 그대로다. 수정 전 실패 재현과 수정 후 8조건·전체 스모크·두 재로딩 방식 전체 엔진·새 프로세스 종료/재실행 10단계·154파일 ZIP·20초 초기 구동이 통과했다. 전후 각 21장 오프스크린 결과 관찰은 실제 창 입력·손/소리/실기기 검사가 아니다. 실제 창 제어는 활성화 오류 두 번/입력 0회로 미완료다. 이전 827장·일곱 장과 백그라운드 재실행 이력은 새 실행 결과로 다시 세지 않는다. 상세 근거는 확인 이력/실행 파일 검증을 따르며 아래 이전 시점 수치는 당시 이력이다.

**10월 19일 첫 연습 표시 이력**: 당시 실패한 검사 뒤 완료 표시가 0으로 남았고 종료 전 원본 값/존재 여부가 확인되지 않아 추측 복원하지 않았다. 첫 연습이 다시 나오면 세 동작을 한 번 마치고 이어간다. 기존 조합/기록이나 전체 진행도를 초기화하지 않는다. 이번 검사 시작값의 복원이나 별도 시험 저장소의 성공을 이 최초 사건의 원상복구로 표시하지 않는다.

## 이번 우선 확인

### 무한 정비 뒤 성향

1. 새 임시 조합으로 무한 준비에 들어가 기프트/유물을 고른다. 정비 기프트로 성향이 바뀌는 경우 준비 화면의 `성향`도 바뀐 이번 런 기준이어야 한다. 모든 기프트가 반드시 성향을 바꾸는 것은 아니다.
2. 실제 시작 뒤 상세 성향이 준비 예고와 같고 저장 이름/기프트 원본은 유지되는지 본다. 정비 취소는 무소모이며 두 번째 실제 시작의 자동 비움도 그대로다. 보관할 조합을 이 확인만을 위해 소모하지 않는다.
3. 직접 같은 조건을 만들기 어려우면 Play 중지 뒤 `Greed Last > Run Prepared Profile Preview Check`에서 메모리 전용 27조건을 확인할 수 있다. 이 검사는 실제 창/손·소리/휴대폰 체감 검사가 아니다. 실행본 적용 시점은 위 최신 기준과 확인 이력을 따른다.

### 저장 후보의 기프트 표시

1. 새 일반 런에서 유물을 선택하고 탈출한 뒤 `저장 슬롯 선택`에서 원하는 임시 칸을 고른다. 후보 이름/구성에는 저장할 기프트만 표시되어야 한다. 일반 클리어 원본 기록의 유물을 삭제하는 변경은 아니다.
2. 상세 비교·덮어쓰기 예고도 같은 기프트 전용 후보와 보너스를 보여야 한다. 확인 목적으로 보관할 기존 조합을 덮어쓰거나 삭제할 필요는 없다.
3. 한 번 저장한 뒤 무한 준비에 들어가면 유물을 새로 선택할 수 있어야 한다. 정비 취소는 무소모, 실제 두 번째 시작의 자동 비움은 기존 규칙 그대로다. 아래 기본 순서는 별도 임시 조합으로만 확인한다.

### 결과 화면의 앱 전환 추가 확인

보관할 기존 조합 대신 새 임시 조합으로 확인한다. 개인 진행도를 초기화하지 않는다.

1. 일반 런 탈출 결과에서 저장/로비를 누르기 전에 다른 앱으로 갔다 돌아온다. 같은 결과에서 저장을 선택하고 원하는 칸을 직접 골라 한 번 저장한다. 저장 관리에 재진입해도 같은 후보를 다시 저장할 수 없어야 한다.
2. 다음 클리어 결과에서도 앱을 전환했다 돌아와 저장하지 않고 입구로 나간다. 포기한 후보가 다시 생기지 않고 기록/성장이 중복 반영되지 않아야 한다.
3. 무한이 실제로 종료된 결과에서도 앱 전환→복귀→로비 또는 다시 시작을 확인한다. 종료 기록/보상은 한 번만 남고 앱 전환 자체로 사용 횟수가 줄지 않아야 한다. 준비를 마치고 실제 시작한 경우만 사용권을 소모한다.
4. 진행 중인 런에서는 앱 전환만으로 실패/포기 결과나 저장 후보가 생기면 안 된다. 복귀 후 정지 메뉴와 새 재개 입력·카운트를 거쳐 같은 구간을 이어간다.

자동 검사의 콜백/JSON 대조는 실제 휴대폰의 OS 강제 종료 검사를 대신하지 않는다.

### 기존 대표 한 판

1. 기초 연습에서 ESC 정지→대기→새 재개를 누른다. 메뉴와 카운트 뒤 같은 함정이 앞 여유를 두고 이어져야 한다. 앱 전환만으로 자동 재개하면 안 된다.
2. 일반 핵→탈출 결과에서 원하는 한 칸을 직접 골라 한 번만 저장한다. 저장 관리에 다시 들어가도 같은 후보를 또 저장하면 안 된다.
3. 새 임시 조합으로 무한 준비 취소는 무소모, 실제 시작은 2→1→자동 비움인지 본다. 비운 뒤 현재 런은 이어지고 결과/기록/보상은 한 번만 남아야 한다.

이번 변경은 저장 후보의 예고를 실제 기프트 저장 내용에 맞추는 것이다. 앞선 완료 결과의 백그라운드 보존과 중복 정산 방지도 유지한다. 실제 `Application.Quit` 복원은 시험 제품에서 확인하며 OS 창 X/Alt+F4·손/소리/휴대폰 성능은 직접 확인으로 남는다. 상세 개발 절차는 [실행 파일 검증](GreedLast_Prototype_PlayerChecks.md)을 따른다. 기본 전체 순서는 아래 12단계다.

## 처음부터 눌러볼 순서

기본 표시에서 아래 12단계를 우선한다. F11 상세 수치보다 [기획 체감 다섯 가지](GreedLast_Prototype_PlanCoverage.md)의 직선 주행·함정 가독성·정확 타이밍 이득·제한된 회전·한 판 마무리가 먼저다.

1. **진입**: 타이틀에서 입구 로비가 열리는지 본다. 개발 연결 전환을 누를 필요는 없다.
2. **기초 연습**: 기초 연습/다시 연습에 들어가 바닥 가시·상단 칼날·측면 날과 점프·숙이기·비틀기를 확인한다. 함정과 같은 채널을 판정선에 맞춰 누른다. 정확/Good/Miss의 표시와 소리가 구분되고 정확/Good의 `+N점`이 실제 총점 증가와 같아야 한다.
3. **오입력과 표시**: 다른 채널을 한 번 누르면 실제 누른 채널의 Miss와 정답 안내가 분리되어야 한다. 무입력은 `입력 없음`으로 표시되고 보정 조언이 없어야 한다. 작은 창에서도 제목·진행 막대·판정이 겹치지 않는지 본다. 필요할 때만 에디터 F11로 상세를 열었다 기본으로 돌아온다. 이미 나온 판정이 다시 재생되면 안 된다.
4. **일시정지**: 아래 일시정지 또는 ESC/P를 누른다. 별도 메뉴와 흐릿한 배경, 현재 보정값이 보여야 한다. 수동 정지 시각까지 거리/집중은 한 번 반영하고 이후 입력·거리·피해는 멈춘다. 이미 마감한 함정이나 마지막 결과가 재개로 되살아나면 안 된다. 보정 ±20ms/0ms는 필요할 때만 조절하고 바꿨다면 원래대로 돌린다.
5. **앱 전환과 재개**: **이번 우선 확인**은 시작 카운트 중, 함정이 보일 때, 재개 카운트 중에 각각 Alt+Tab했다 돌아오는 것이다. 마지막 표시의 함정/시작 카운트/경직과 거리/집중이 멈추고 복귀만으로 자동 재개하지 않아야 한다. 새 재개 입력 후 카운트와 앞 여유를 거쳐 **같은 함정**이 이어져야 한다. 이전 버튼의 손 뗌으로 재개되면 안 된다. 아직 함정이 내려오기 전 준비 탭은 체력/실수를 늘리지 않고, 내려온 뒤 새 탭으로 처리할 수 있어야 한다. 실제 함정 시작 뒤의 빠름/오채널 입력은 여전히 Miss다.
6. **일반 런 시작**: 연습 결과의 일반 런/로비의 일반 런을 누른다. 진입 탭이 시작 기프트를 자동 선택하면 안 된다. 시작 기프트→카운트→첫 함정으로 이어지고 챕터 뒤 루트·기프트 선택의 빠른 두 번 클릭이 다음 선택까지 넘기면 안 된다. 이전 미저장 후보가 있으면 먼저 아래의 후보 확인 흐름을 따른다.
7. **주행·정확 입력·회전**: 앞으로 달리는 통로와 세 동작이 읽히는지 본다. 정확 입력은 Good보다 점수·집중/연쇄 이득이 있어야 한다. 회복이 나면 실제 체력 증가와 표시가 같아야 한다. 회전 통로에서는 통로만 제한적으로 기울고 HUD·판정선은 고정되어야 한다. 집중 중 Miss도 피해를 받는 것이 현재 규칙이다.
8. **핵과 탈출**: 공명핵 회수 뒤 탈출 게이트까지 통과한다. 핵만 얻고 끝나면 안 된다. 클리어 점수·기록과 저장 기회가 보여야 한다. 빠른 에디터 확인은 F1 무적, F4 핵 직후/F5 탈출 직전을 사용한다.
9. **원하는 한 칸에 한 번 저장**: 결과에서 저장 선택으로 가 빈 S2/S3 등 원하는 칸을 **직접** 고른다. 칸 선택 전 확정은 잠겨 있어야 한다. 한 번 저장/명시적 포기 후 같은 후보가 다시 저장되면 안 된다. 다음 새 일반 클리어는 새 기회 1회다. 덮어쓰기/삭제/포기에는 별도 확인이 필요하다.
10. **무한 정비 취소**: 새 임시 조합으로 무한 준비에 들어가 선택 후 취소한다. 사용권은 2회 그대로여야 한다. 다시 준비해 **실제 시작**하면 2→1이다. 이 기본 순서에서는 첫 카운트 포기 없이 주행을 이어간다.
11. **두 번째 시작과 자동 비움**: 첫 무한의 자연 종료 결과에서 다음 준비로 바로 들어간다. 직전 결과는 현재 정비 아래 한 번만 남고 복기 목표가 다음 런에 이어져야 한다. 두 번째 실제 시작에서 슬롯은 자동으로 비지만 이미 시작한 런은 계속된다. 무적 OFF 체력 0의 종료 요약을 확인한다.
12. **기록과 새 시작**: 로비의 기록 보드에는 실제 기록만 나오고 개발 메모/설정 안내가 섞이지 않아야 한다. 결과와 기록이 한 번만 등록되고 성장 보상이 반복되지 않는지 본다. 새 연습은 새 체력·0점·새 카운트로 시작하며 이전 피격/결과가 남지 않아야 한다.

**이번 우선 확인**: 짧은 기록 화면 다음 긴 저장 비교 화면으로 가서 손잡이를 바로 끌어 본문이 움직이는지 본다. 포커스를 일부러 바꿔야 작동하는 상태면 안 된다. 긴 본문/손잡이를 누르거나 끌던 중 Alt+Tab 또는 창 크기를 바꾸면 옛 움직임/손 뗌은 취소되고 새로 누른 드래그만 작동해야 한다. 내용이 짧아 스크롤이 없으면 정상이다. 긴 조건을 만들려고 개인 조합을 소모하지 말고, Play 중지 뒤 `Greed Last > Run Menu Scroll Interruption Check`의 임시 긴 내용/최소 넘침 10조건으로 확인할 수 있다. 이 프리뷰는 실제 OS 전환이나 손·기기 검사를 대신하지 않는다.

## 이번 보완과 종료 확인

- **첫 연습 뒤 남은 후보**: 첫 연습을 아직 완료하지 않았고 이전 클리어 후보가 있을 때만 해당한다. 연습 완료의 `저장 후보 확인`은 새 일반 런 대신 직접 칸 선택으로 가야 한다. 이미 연습 완료 상태면 기존 반복 연습이 정상이다. 이 조건을 만들려고 진행도를 초기화하지 않는다.
- **결과에서 정상 종료**: 일반 탈출 결과의 저장 선택 전 또는 일반 실패/무한 자연 종료의 다음 버튼 전에 창을 정상 종료한다. 같은 환경 재실행 뒤 기록/성장 보상은 한 번만 남고 미저장 클리어 후보는 직접 칸 선택 전 자동 저장되지 않아야 한다. 이미 저장/포기/정산한 결과는 되살아나거나 중복되면 안 된다.
