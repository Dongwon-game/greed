# Greed Last 프로토타입 빠른 확인

기획서의 **직선 주행 → 함정 회피 → 정확 타이밍의 이득 → 제한된 회전 → 탈출/저장/무한**을 직접 보는 순서다. 처음에는 아래 12단계만 확인한다. 지난 배포 설명과 자동 검사 수치는 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 분리했다.

- Unity: `C:\Projectunity\greed last`를 **Unity 6.4 / 6000.4.3f1**로 열고 `Assets/Scenes/GreedLast_Boot.unity`에서 Play한다.
- 현재 실행본: **2026-10-29 19:23 KST / egyptian-runner**, 게임/그림 `bfc0741`, 엔진·빌드 입력 `91fd361`. 이집트풍 인간의 달리기·점프·숙이기·비틀기와 입구 인물을 연결했다. 앞선 휠/기프트 보호를 포함하며 판정·보상·한 번 저장/두 번 사용은 유지한다. 후속 `bfcc183`은 같은 연결 검사를 상시 검사로 옮기고 진단 방향 표기를 맞춘 소스이며 재검증 중이다.
- 한 저장 환경에서 진행한다. 에디터와 Windows의 저장 위치는 다를 수 있다. 다른 환경의 빈 칸을 저장 소실로 판단하거나 개인 진행도를 초기화하지 않는다.

## 이번 그림 확인

1. 타이틀 → 입구 로비: 같은 인간 주자의 피부·머리·복식 방향이 이어지는지 본다.
2. 연습 → 일반 런: 점프·숙이기·비틀기 때 실제 그림이 바뀌는지 본다. 장 마감 선택 화면에서는 기본 포즈로 돌아오는 것이 정상이다.
3. 좌우 회피 → ESC/P 정지 → 새 재개: 방향 고정/팔다리 잘림/숙인 뒤 바닥 이탈이나 이전 동작 잔상이 없는지 본다.
4. 결과 → 로비 → 새 런: 기본 달리기 그림과 크기로 복귀하고 함정/판정선 가독성이 유지되는지 본다.

그림 크기·동작의 체감과 실제 휴대폰 확인은 아직 사람이 볼 부분이다. 아래 12단계는 전체 루프가 궁금할 때 이어서 사용한다. 기존 움직임 미리보기는 캐릭터 교체 전 자료다.

## 처음부터 눌러볼 순서

1. **타이틀 → 입구 로비 → 연습 버튼**: 개발 연결 전환은 누르지 않는다. 이전 결과에 따라 버튼이 기초 연습·복기 연습·목표 연습으로 보일 수 있다. 이미 완료한 표시를 지울 필요는 없다.
2. **세 동작**: 기초 연습의 바닥 가시→점프, 상단 칼날→숙이기, 측면 날→비틀기를 본다. 짧은 복기에는 대상 동작만 나오는 것이 정상이며 나머지는 일반 런에서 본다. 위험과 같은 좌/중/우 채널을 판정선에 맞춰 누른다. 좌/중/우는 이동할 레인이 아니라 대응 채널이다.
3. **정확 / Good / Miss**: 정확과 Good의 화면·소리를 비교한다. 다른 채널을 한 번 누르면 오입력, 누르지 않으면 `입력 없음`이어야 한다. 뒤의 정답 탭으로 최초 오입력이 성공으로 바뀌면 안 된다.
4. **함정 진행 중 ESC/P → 일시정지 → 재개**: 결과 화면이면 로비에서 연습을 다시 연다. 별도 메뉴와 흐릿한 배경이 뜨고 정지 중 거리·피해가 멈춰야 한다. 새 재개 입력 뒤 `2→1→GO`와 앞 여유를 거쳐 같은 함정이 이어져야 한다.
5. **진행 중 앱 전환 → 복귀 → 새 재개**: 시작 카운트·함정·재개 카운트 중 한 곳에서 Alt+Tab한다. 돌아와도 자동 재개하면 안 된다. 새 재개 뒤 같은 구간이 이어지고, 이전 버튼의 손 뗌이나 함정 시작 전 준비 탭으로 피해가 나면 안 된다.
6. **로비 → 일반 런**: 시작 기프트→카운트→첫 함정으로 이어진다. 진입 클릭이 다음 선택까지 넘기면 안 된다. 장 마감의 루트·기프트, 중반 유물 선택도 한 번씩 분리되어야 한다.
7. **주행 / 타이밍 이득 / 회전**: 앞으로 달리는 방향과 세 회피가 읽히는지 본다. 정확이 Good보다 점수·집중/연쇄에 유리해야 한다. 회전 통로만 제한적으로 기울고 HUD·판정선은 고정되어야 한다. 집중 중 Miss도 피해를 받는 것이 현재 규칙이다.
8. **공명핵 → 탈출 게이트 → 저장 슬롯 선택**: 핵 회수만으로 끝나면 안 된다. 게이트 통과 뒤 `저장 슬롯 선택`을 누르면 클리어 요약과 칸 선택으로 이어져야 한다. 저장하지 않을 때는 `저장 없이 로비`를 누른다.
9. **저장 슬롯 선택 → S2/S3 등 원하는 칸 → 확정**: 이번 확인용 새 후보만 쓴다. 칸 선택 전 확정은 잠기고, 저장 또는 명시적 포기 후 같은 후보를 다시 저장할 수 없어야 한다. 저장은 기프트 전용이며 일반 기록의 유물은 유지된다. 기존 조합 덮어쓰기·삭제·후보 포기는 확인 창을 거친다.
10. **무한 정비 → 취소 → 다시 준비 → 실제 시작**: 취소하면 사용권은 2회 그대로다. 실제 시작할 때만 2→1이다. 준비에 표시한 성향과 이번 런의 성향이 같아야 한다. 모든 기프트가 반드시 성향을 바꾸는 것은 아니다.
11. **자연 종료 → 정산 후 재준비 → 두 번째 실제 시작**: 체력 0 결과에서 재준비하면 다음 정비로 간다. 정비 진입·취소는 무소모다. 두 번째 실제 시작에서 슬롯이 자동으로 비어도 시작한 런은 계속되어야 한다.
12. **로비 → 기록 → 새 연습**: 기록 보드에는 실제 기록만 남고 저장 관리·개발 메모는 섞이지 않아야 한다. 같은 결과를 다시 봐도 기록·성장 보상은 한 번이다. 새 연습은 새 체력·0점·새 카운트로 시작해야 한다.

9~11번은 새로 만든 임시 조합만 사용한다. 보관할 조합·개인 포인트를 소모하거나 진행도를 지워서 확인하지 않는다. 비개발 Windows에는 무적·바로가기·위협 조절이 없다.

## 다 보고 판단할 다섯 가지

- 앞으로 달리는 방향과 캐릭터 위치가 바로 읽히는가.
- 위험을 미리 구분하고 점프·숙이기·비틀기로 피했다고 느끼는가.
- 정확한 타이밍이 Good 생존보다 더 이롭다고 느끼는가.
- 회전이 짧은 변주로 읽히며 어지럽지 않은가.
- 탈출 뒤 결과·한 번 저장·무한 두 번/자동 비움이 자연스럽게 이어지는가.

불편이 있으면 **단계 번호 / 누른 버튼·키 / 기대한 것 / 실제 나온 것**만 적는다. 점수 재현이나 자동 검사 수치를 손으로 다시 맞출 필요는 없다.

## 필요한 경우만

- **복기 목표가 있을 때**: 특정 장 목표는 다른 장의 실수로 깨지지 않아야 한다. 목표 장의 실수·Good는 실패, 깨끗한 일부 진행 후 종료는 미완료, 목표 구간 전 종료는 대기다. 무한의 첫 대상 구간 달성은 그 뒤의 실수로 뒤집히면 안 된다.
- **저장 상세의 보너스 근거**: 보너스가 0인 체력/집중/콤보 항목은 근거로 나오면 안 된다. 집중 지급이 있으면 집중 근거가 보여야 한다. 성장으로 늘어난 일반 결과 체력 자체를 추가 생존 보너스로 읽지 않는다. 상세 읽기만으로 사용권은 줄지 않는다. 정확/Good 횟수의 정밀 재현은 자동 검사에서 확인했으므로 보관 조합을 소모해 재현하지 않는다.
- **결과에서 정상 종료**: 저장 선택 전 또는 일반 실패·무한 자연 종료에서 앱을 닫고 같은 환경으로 다시 연다. 기록·성장은 한 번, 미저장 후보는 직접 칸 선택 전 자동 저장되지 않아야 한다. 강제 종료·전원 단절·휴대폰 회수 복구를 보장하는 항목은 아니다.
- **첫 카운트 포기**: 별도 임시 조합만 쓴다. 실제 시작에 쓴 사용권은 돌려주지 않지만 카운트만 본 포기로 기록·보상을 주면 안 된다.
- **긴 메뉴**: 기록·저장 비교의 스크롤 손잡이/휠이 본문을 움직이는지 본다. 앱 전환·입력 취소 뒤 옛 입력으로 본문이 튀지 않고 새 드래그/휠은 정상 작동해야 한다. 같은 프레임의 정밀 재현은 자동 검사에서 확인했으므로 손으로 반복하거나 긴 내용을 만들려고 개인 조합을 소모하지 않는다.
- **저장 자료 오류로 진입 보류**: 앱을 닫고 자료와 게임 버전을 확인한다. 재시도는 초기화·자동 복원이 아니다. 기존 자료를 삭제하거나 일부러 손상시키지 않는다.
- **첫 연습이 다시 뜰 때**: 세 동작을 한 번 마친다. 10월 19일 첫 연습 표시의 원본 값·존재 여부를 잃은 이력은 미해결이며 추측 복원하지 않았다. 기존 조합·기록·전체 진행도는 초기화하지 않는다.
- **작은 화면**: 제목·판정·버튼이 겹치지 않는지 본다. 현재 Windows 배포는 고정 창이므로 크기 변경은 Unity Game 뷰에서만 확인한다. 비활성 최대화 버튼은 오류가 아니다.
