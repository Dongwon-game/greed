# Greed Last 프로토타입 빠른 확인

## 확인 목표

- 템플런처럼 한 방향으로 달리며 함정을 읽는지 확인한다.
- `위험 확인 → 맞는 동작 → 박자 입력 → 정확 보상`이 한 덩어리로 느껴지는지 확인한다.
- 회전 통로는 화면 전체가 돌지 않고 통로만 살짝 기울며, 모바일에서는 폰 기울임 또는 좌우 탭으로 대응하는지 확인한다.
- 일반 런에서 만든 조합이 무한모드에 이어지고 두 번 사용한 뒤 자동으로 비워지는지 확인한다.

## 시작 전

1. Unity Hub에서 `C:\Projectunity\greed last`를 Unity 6.4로 연다.
2. Game 뷰를 가로 화면으로 두고 Play를 누른다.
   부트 씬은 `Assets/Scenes/GreedLast_Boot.unity`다. 기존 진행도는 이 확인만으로 초기화하지 않는다.
3. 프로토타입 저장은 실행 사이에 유지된다. 현재 로비가 가리키는 강조 버튼부터 이어서 확인하면 된다.
4. 공유용 실행 파일이 필요하면 재생을 멈춘 뒤 `Greed Last > Build Verified Windows Prototype`을 실행한다. 전체 스모크를 통과한 경우에만 `Builds/GreedLastPrototype/GreedLastPrototype.exe`가 갱신된다.

## 에디터 조작

- 좌 / 중 / 우: `A` / `S` / `D` 또는 방향키 / Space
- 회전 통로: `Q` / `E`
- 일시정지: `ESC` 또는 `P`
- 무적: `F1`
- 기프트 / 유물 / 핵 직후 / 탈출 직전 바로가기: `F2` / `F3` / `F4` / `F5`
- 집중 MAX: `F6`
- 목표 / 경로 / 동작 / 낙하 보기: `F7` / `F8` / `F9` / `F10`
- 테스트 버튼 숨김 / 복원: `F11`. 무적과 바로가기 키는 그대로 작동하며, 소리·보정 설정은 `ESC` 메뉴에서 다시 보인다. 일반 실행 빌드에서는 테스트 버튼 없이 이 화면이 기본이다.
- 무한 위협 조절: `PageUp` / `PageDown`
- 무한 정산 종료: `End`

## 이번 그래픽 변경만 먼저 볼 때

1. Play 후 타이틀에서 입구 그림을 보고, 로비에서는 중복 캐릭터·좌중우 글자·노란 사각형·판정선이 사라졌는지 확인한다.
2. 연습이나 일반 런으로 들어가면 움직이는 도깨비 소녀와 입력 레인·판정선이 다시 보여야 한다.
3. 일반 런에서 `F11`로 테스트 버튼을 숨긴 뒤 `F1`과 `F9`를 사용해도 무적·동작 확인이 그대로 작동하는지 본다. 연습에서는 일부 개발 바로가기를 제한하므로 이 확인은 일반 런에서 한다.
4. `ESC` 메뉴에서는 소리·보정·진동·기울임·시야 안정 버튼이 메뉴 안에 보여야 한다. `시야 안정`을 직접 눌러 글자가 바뀌는지 확인한다. 재개 중에는 제목 숫자가 내려가고 재개 준비 버튼은 비활성화되며, 달리기가 다시 시작되면 설정 버튼은 다시 숨는다. `F11`을 다시 누르면 개발 버튼이 복원된다.
5. 가시·칼날문·측면 회전날과 캐릭터 그림이 찌그러지거나 배경 사각형 없이 보이는지 확인한다.
6. 주행 중 소개 문구가 주자 위에 쌓이지 않고, 전환 배너는 입력 레인 위쪽에 나타나야 한다. 동작 안내는 주자 아래에 보이며 판정 피드백과 동시에 겹치지 않아야 한다.
7. 일반 런 클리어 후 선택지·요약·저장 슬롯 글자는 그대로 표시되는지 확인한다. 이번 주행 문구 숨김은 결과 화면을 숨기지 않는다.

해상도별 고정 화면은 `Greed Last > Capture Prototype Visual Checks`로 생성한다. `Logs/VisualChecks`의 PNG는 화면 배치 비교용이며 실제 플레이 결과는 아니다.

## 2026-09-11 변경 확인

이번 묶음은 기능 추가보다 핵심 루프를 읽고 조작하기 쉽게 정리한 작업이다. 점수 판정, 저장 기회 1회, 조합 사용 2회 규칙은 바꾸지 않았다.

1. `F11` 클린 뷰에서 주행한다. 체력·집중은 게이지에, 점수·거리·콤보·판정 횟수는 두 줄로 보여야 한다. F11을 다시 누르면 개발 상세 정보가 돌아온다.
   함정 아래는 `위험 위치 → 대응 동작`과 `정확 점수 · 추가 이점` 두 줄로 표시된다. 일반 런에서 F9로 점프→숙이기→비틀기→좌회전→우회전을 차례로 비교한다. 회전의 Q/E 입력 구분은 클린 뷰에서도 남고, 판정 알림 중에는 동작 안내가 겹치지 않아야 한다.
   정확은 동작·보상·콤보, Good은 동작·빠름/늦음·콤보, Miss는 동작·실패 이유 또는 정답 입력·현재 체력만 두 줄로 표시한다. Miss 문구가 체력·집중 게이지를 덮지 않아야 한다. 연습 결과의 추천 보정 버튼은 그대로 남는다.
2. `ESC`를 연다. 설정 버튼 글자가 커지고 메뉴 안에 모두 들어가야 한다. 클린 뷰에서는 체력·집중·점수·거리만 간단히 보인다. 재개 카운트 동안 재개 버튼은 잠겨야 한다.
3. 일반 런을 클리어한다. 레인·게이지 대신 큰 결과 요약과 `저장 기회 1회`가 보이고, `저장 슬롯 선택` 또는 `저장 없이 로비` 중 선택할 수 있어야 한다.
4. 저장 슬롯 선택에서 오른쪽 S3를 직접 누르고 확정한다. S1에 자동 저장되면 안 된다. 같은 클리어 후보는 저장 후 소진되어 다시 저장할 수 없어야 한다.
5. 새 일반 런으로 후보를 만든 뒤 이미 찬 슬롯을 고른다. 긴 덮어쓰기 비교는 스크롤되고, 아래 슬롯·확정·포기 버튼은 가려지지 않아야 한다. 확인 전에는 기존 조합이 바뀌면 안 된다.
6. 저장 조합으로 무한모드를 준비한다. 좌/중/우 선택 칸에서 기프트 정비와 유물 정비를 각각 고른 뒤 시작을 확정한다. 준비 단계에서는 횟수가 줄지 않고 실제 시작 확정에서만 1회 줄어야 한다. 정비 중 로비로 취소해도 횟수는 그대로여야 한다.
7. 같은 조합의 두 번째 진입을 확인한다. 준비 화면에 마지막 1회와 자동 비움이 표시되고, 시작 뒤 슬롯이 비어도 진행 중인 런에는 해당 조합이 유지되어야 한다. 세 번째 재사용은 막혀야 한다.
8. 정산 뒤 기록 보드를 연다. 기록만 읽히고 주행 레인·게이지는 없어야 한다. 내용이 길 때만 스크롤이 활성화되고, 이전/다음 페이지를 바꾸면 위에서 시작해야 한다.
9. 기록·저장 화면을 거쳐 다시 연습이나 일반 런을 시작한다. 이전 런의 콤보 끊김·피격·판정 알림이 새 런에 남으면 안 된다.
10. 기초 연습을 같은 방향으로 조금 빠르거나 늦게 3회 입력해 마친다. 추천값이 생기면 결과 화면에서 `추천 적용`을 누를 수 있어야 한다. 적용 후 중복 적용이 잠기고, 재시작하면 보정 버튼은 주행 화면에서 다시 숨겨져야 한다.

16:9 가로 화면, 2340×1080 안전 여백 화면, 1024×768 태블릿 화면을 비교한다. 실제 모바일 센서·음향 지연·터치 체감은 아래 항목으로 별도 확인한다.

## 10~15분 확인 순서

처음 상태부터 다시 확인하려면 재생을 멈춘 뒤 Unity 상단 `Greed Last > Reset Prototype Progress (Keep Settings)`를 실행한다. 이 메뉴는 Greed Last 진행도와 첫 연습 완료만 지우고 소리·진동·기울임 설정은 유지한다.

1. 실행 직후 `GREED LAST`와 `리듬으로 피하고, 정확하게 돌파하라` 뒤로 도깨비 소녀와 정면 피라미드 통로 시안이 먼저 보이는지 확인한다. 연결 중에는 배경이 조금 약해지고, 입구 로비에서는 버튼과 동적 문틀보다 뒤로 물러나야 한다. 개발용 연결 전환 버튼 없이 자동으로 피라미드 입구까지 이어지는지 본다. 로비가 열릴 때 문틀, 작은 주자, 다음 행동 버튼 강조가 함께 짧게 밝아지고 올라오며 낮은 입구음은 한 번만 나야 한다. 로비 안에서 문구가 갱신될 때 연출과 입구음이 반복되지 않아야 한다. 새 프로필이면 입구와 함께 가볍게 호흡하는 `기초 연습`부터 시작한다. 기초 연습 버튼을 빠르게 두 번 눌러도 두 번째 탭이 카운트 안내를 덮지 않아야 한다. 정확 3회를 모두 맞히면 기본 버튼이 `일반 런으로` 바뀌고 로비를 거치지 않은 채 시작 기프트 선택으로 이어져야 한다. Good이나 Miss가 있으면 해당 구간 다시 하기가 먼저 보여야 한다.
2. 기존 프로필이면 로비에서 `일반 런` 또는 현재 강조된 다음 행동을 누른다. 짧은 상승 스윕과 약한 진동 한 번에 맞춰 작은 주자가 런 크기로 커지고 입구 문틀과 진행 점이 뒤로 사라져 같은 통로로 들어가는 것처럼 보여야 한다. 버튼을 빠르게 두 번 눌러도 두 번째 탭이 시작 기프트를 임의 선택하면 안 된다. 첫 일반 런의 제목은 `시작 기프트 선택`이고, 연습에서 바로 넘어왔다면 연습 완료와 일반 런 시작 문구가 함께 보여야 한다.
3. 시작 선택을 누르면 고른 좌 / 중 / 우 레인만 짧게 밝아지고 해당 레인의 음높이와 확정음이 먼저 난다. 경로에서 기프트로 이어지는 선택을 빠르게 두 번 눌러도 한 번에 한 단계만 확정되어야 한다. 이어서 `CHAPTER 1` 전환음과 배너가 한 박자 분리되어 나타나고, 그 뒤 `2-1-GO`가 시작되어야 한다. 입구 시안이 사라지는 동안 캐릭터 없는 직선 3레인 통로 시안이 자연스럽게 이어지고, 첫 함정이 내려올 때 주자 / 함정 / 판정선이 배경보다 앞에서 읽히는지 본다.
4. 바닥 / 상단 / 측면 함정을 각각 한 번씩 입력한다. 함정이 가시 / 상단 칼날문 / 측면 회전날로 구분되고 `↑ / ↓ / ↔` 기호가 그림 위에서 읽히는지 본다. 입구에서 본 도깨비 소녀가 그대로 달리며 점프 / 숙이기 / 비틀기 동작을 따라가는지, 검은 사각형이나 잘린 발끝 없이 보이는지도 확인한다. 그림 위의 반투명 동작 강조와 `정확 / Good / Miss`의 소리·색·움직임 차이도 본다.
5. 정확권에 가까워질수록 판정선, 목표 레인, 함정 기호가 같은 순간을 가리키는지 본다. 텍스트를 읽지 않아도 누를 타이밍이 보여야 한다.
6. `F9`로 회전 통로를 맞춘 뒤 `Q` 또는 `E`를 누른다. 통로와 배경 일부만 작게 기울고 제목, HUD, 판정선은 고정되어야 한다.
7. `ESC`로 멈춘다. 주변은 어두워지고 별도 메뉴가 떠야 하며, 소리 / 보정 / 진동 / 기울임 설정이 한 화면에서 바뀌어야 한다.
8. `기울임 ON/OFF`를 눌러 버튼 표시가 즉시 바뀌는지 본다. `시야 안정 ON/OFF`도 바꿔 회전 기울기와 Miss 흔들림 강도가 달라지되 판정은 같게 유지되는지 비교한다. 기본 확인은 `시야 안정 ON`으로 돌린 뒤 재개한다.
9. 재개하면 곧바로 함정이 닿지 않고 `2-1-GO`와 앞 박자 여유 뒤 주행이 이어지는지 본다.
   - 1분 이상 주행하거나 창을 잠깐 다른 곳으로 전환한 뒤에도 박자 클릭이 짧게 몰려 나오지 않고 일정 간격으로 복귀하는지 듣는다.
10. `F4`로 공명핵 회수 뒤로 이동하고 탈출 게이트 3칸을 확인한다. 필요하면 `F5`로 탈출 직전으로 이동해 마지막 구간을 통과한다.
11. 탈출 결과 요약과 `저장 기회 1회`를 확인한다. `저장 슬롯 선택`으로 넘어가 좌 / 중 / 우 슬롯을 직접 골라 확정한다. `저장 없이 로비`로 포기할 수도 있다. 저장 직후 같은 클리어를 다시 저장할 수 없어야 한다.
12. 로비에서 저장 조합을 골라 무한모드에 들어간다. 위협 단계가 오를 때 판정 폭과 정확 보상이 함께 변하는지 본다.
13. 무한모드를 정산하고 같은 저장 조합을 다시 한 번 사용한다. 두 번째 사용 뒤 슬롯이 자동으로 비워지고 남은 조합이 있으면 다음 슬롯이 자동 선택되어야 한다.
14. 모든 저장 조합이 비면 로비 버튼이 `보충 런` / `보충 안내` / `무한 조합 보충`으로 같은 재진입 방향을 가리키는지 본다.
15. 기록 보드를 연다. 점수, 거리, 구간, 위협, 콤보, 실수 같은 실제 기록만 보이고 테스트키·설정·그래픽 체크 문구는 섞이지 않아야 한다.

## 모바일에서 추가 확인

1. 가로 방향을 좌우로 바꿔도 회전 통로 기울임 방향이 뒤집히거나 떨리지 않는지 본다.
2. `기울임 ON`에서 폰을 좌우로 살짝 기울인 뒤 중립으로 돌려야 다음 입력이 한 번만 들어가는지 본다.
3. `기울임 OFF`에서는 회전 통로 안내가 좌 / 우 탭으로 바뀌고 센서 커서, 손잡이, 중립 게이트가 숨는지 본다.
4. 앱을 종료해 다시 열어도 소리, 진동, 기울임 설정이 유지되는지 본다.

## 지금 평가하지 않는 것

- 정식 도깨비 소녀 원화 교체와 프레임 단위 완성 애니메이션
- 정식 배경, 상용 이펙트, 수록곡 품질
- 계정, 서버, 결제, 길드 같은 서비스 기능
- 장기 밸런스와 모바일 성능 최적화

현재 목표는 완성 게임이 아니라 기획서의 핵심 루프와 조작 감각을 직접 비교할 수 있는 프로토타입이다.
