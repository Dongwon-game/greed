# Greed Last 프로토타입 빠른 확인

기획서의 **직선 주행·함정 회피·정확 타이밍 보상·제한된 회전·한 판 마무리**를 확인하는 순서다. 처음에는 아래 12단계만 본다. 상세 개발 검사와 지난 결과는 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 분리한다.

## 실행

- Unity: `C:\Projectunity\greed last`를 **Unity 6.4 / 6000.4.3f1**로 열고 `Assets/Scenes/GreedLast_Boot.unity`에서 Play한다.
- Windows: `C:\Projectunity\greed last\Builds\GreedLastPrototype\GreedLastPrototype.exe`를 연다.
- 현재 배포: **2026-10-23 14:13 KST / review-counts**, 게임 입력 `9c2c5ca` / Editor 검사 `01fb46b`. 자연 종료 안내와 복기 횟수 단위·기록 보드 분리를 반영했다. 보존 ZIP은 `Builds/GreedLastPrototype-verified-20261023-review-counts.zip`이다. 이전 13:20 실행본/ZIP도 보존한다.
- 한 저장 환경에서 진행한다. 에디터와 Windows의 [저장 위치](https://docs.unity3d.com/6000.4/Documentation/ScriptReference/PlayerPrefs.html)는 다를 수 있다. 다른 환경의 빈 칸을 저장 소실로 판단하거나 진행도를 초기화하지 않는다.

## 처음부터 눌러볼 순서

1. **타이틀 → 입구 로비**: 화면이 열리면 기초 연습부터 시작한다. 개발 연결 전환은 누르지 않아도 된다. 첫 연습을 이미 마쳤다면 다시 연습으로 들어간다.
2. **세 동작 연습**: 바닥 가시→점프, 상단 칼날→숙이기, 측면 날→비틀기를 본다. 같은 채널을 판정선에 맞춰 누른다. 정확/Good/Miss의 화면·소리가 구분되고 `+N점`이 실제 총점 증가와 같아야 한다.
3. **오입력 한 번**: 다른 채널을 누르면 누른 곳의 Miss와 정답 안내가 분리되어야 한다. 아무것도 안 누르면 `입력 없음`이어야 하며 빠름/늦음 보정 조언이 뜨면 안 된다. 작은 창에서도 제목·판정·버튼이 겹치지 않는지 본다.
4. **ESC/P → 일시정지 → 재개**: 별도 메뉴와 흐릿한 배경이 뜬다. 기다리는 동안 입력·거리·피해는 멈추고, 새 재개 입력 뒤 `2→1→GO`와 앞 여유를 거쳐 같은 함정이 이어져야 한다. 보정을 바꿨다면 확인 뒤 원래 값으로 돌린다.
5. **앱 전환 → 복귀**: 시작 카운트/함정/재개 카운트 중 한 곳에서 Alt+Tab한다. 복귀만으로 자동 재개하면 안 된다. 새 재개 뒤 같은 구간을 이어가며, 이전 버튼의 손 뗌이나 함정이 시작하기 전 준비 탭으로 피해가 나면 안 된다.
6. **일반 런**: 로비의 일반 런을 누른다. 시작 기프트→카운트→첫 함정으로 이어지고 진입 클릭이 다음 선택까지 넘기면 안 된다. 장 마감의 루트·기프트, 중반 유물 선택도 한 번씩 분리되어야 한다.
7. **주행과 타이밍 이득**: 앞으로 달리는 통로와 세 회피 동작이 읽히는지 본다. 정확은 Good보다 점수·집중/연쇄 이득이 있어야 한다. 회전 통로만 제한적으로 기울고 HUD·판정선은 고정되어야 한다. 집중 중 Miss도 피해를 받는 것이 현재 규칙이다.
8. **공명핵 → 탈출 → 결과**: 핵만 얻고 끝나면 안 된다. 탈출 게이트까지 통과한 뒤 클리어 점수·기록과 저장 선택이 나와야 한다. 저장하지 않을 때는 결과에서 로비로 나갈 수 있다.
9. **원하는 한 칸에 한 번 저장**: 새 확인용 후보로 S2/S3 등 원하는 칸을 직접 고른다. 칸 선택 전 확정은 잠기고, 저장/명시적 포기 후 같은 후보는 다시 저장되지 않아야 한다. 저장할 내용은 기프트 전용이며 일반 기록의 유물은 유지된다. 기존 조합 덮어쓰기/삭제/후보 포기에는 확인 창이 필요하다.
10. **무한 정비 → 취소 → 실제 시작**: 새 임시 조합으로 정비 기프트/유물을 고른 뒤 취소하면 2회 그대로다. 다시 준비를 마치고 실제 시작할 때만 2→1이다. 준비 성향과 실제 런 성향은 같아야 한다. 모든 기프트가 반드시 성향을 바꾸는 것은 아니다.
11. **자연 종료 → 다음 준비 → 두 번째 시작**: 무적 OFF로 체력이 0이 되면 결과를 본다. `정산 후 재준비`는 기록 보드가 아니라 다음 정비로 간다. 정비 진입/취소로 사용권이 줄면 안 된다. 두 번째 실제 시작에서 슬롯은 자동으로 비지만 시작한 런은 계속되어야 한다.
12. **로비 → 기록 → 새 시작**: 기록 보드에는 실제 기록만 남고 저장 관리/개발 메모가 섞이지 않아야 한다. 같은 결과를 다시 확인해도 기록·성장 보상은 한 번만 반영된다. 새 연습은 새 체력·0점·새 카운트로 시작해야 한다.

보관할 조합/개인 포인트를 확인용으로 소모하지 않는다. 9~11번은 이번 확인을 위해 새로 만든 임시 조합만 쓴다. 더 자세한 기획 범위는 [기획 체감 범위](GreedLast_Prototype_PlanCoverage.md)를 따른다.

## 이번 보완에서 볼 곳

자연 종료 안내와 복기 단위 보완은 위 14:13 실행본에 포함된다. 아래 결과 동선부터 보고 기본 12단계를 이어간다.

- 자연 무한 종료 뒤 `정산 후 재준비`와 `로비로`가 보이는지 본다. 결과에서 채널 키를 더 눌러도 점수·거리·판정 기록은 바뀌거나 런이 다시 시작되면 안 된다.
- 재준비 버튼 뒤에는 정비/별도 시작 단계가 있어야 한다. 버튼을 누르는 순간 곧바로 사용권을 더 쓰는 흐름이 아니다.
- 다음 정비 본문의 `목표:`에서 `종료 구간 실수 1회`, `직전 보정 1회`처럼 무엇의 횟수인지 읽혀야 한다. 정비 완료 뒤 아래쪽으로 밀리면 본문을 스크롤한다. 기록 보드에는 이 목표 안내가 섞이지 않고 점수 기록만 남아야 한다.
- 상세 비교나 긴 기록에서는 스크롤 손잡이가 즉시 본문을 움직이는지 본다. 드래그 중 앱 전환 뒤에는 옛 입력이 취소되고 새 드래그가 되어야 한다. 긴 내용을 만들려고 개인 조합을 소모하지 않는다.

## 필요한 경우만

- **첫 연습이 다시 뜰 때**: 세 동작을 한 번 마치고 이어간다. 10월 19일 실패 검사에서 첫 연습 원본 값/존재 여부를 잃은 이력은 미해결이며 추측 복원하지 않았다. 이후 정상 검사로 이 사건이 복구됐다고 표시하지 않는다. 조합/기록·전체 진행도는 초기화하지 않는다.
- **결과에서 정상 종료**: 저장 선택 전 또는 일반 실패/무한 자연 종료에서 창을 닫고 같은 환경으로 다시 연다. 기록/성장은 한 번만, 미저장 후보는 직접 칸 선택 전 자동 저장되지 않아야 한다. 강제 종료·전원 단절·휴대폰 프로세스 회수 복구를 보장하는 기능은 아니다.
- **첫 카운트 포기**: 기본 두 번 사용 확인과 별도 임시 조합으로만 한다. 실제 시작에 쓴 사용권은 돌려주지 않지만 카운트만 본 포기로 기록/보상을 주면 안 된다.
- **창 크기**: 현재 Windows 배포는 고정 창이다. 크기 변경은 Unity Game 뷰에서 확인한다. 비활성 최대화 버튼은 게임 오류가 아니다.
