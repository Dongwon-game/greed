기존 개인 진행도나 보관 조합을 건드리지 않고 대표 흐름을 눌러보는 **별도 Windows 제품**이다. 회사/제품명은 계속 `GreedLastPrototypePreview / Greed Last Demo 20261031`이다. 개인 게임·Unity 에디터·Demo30과 저장 공간이 각각 다르다. 이번 갱신은 Demo31 저장 환경으로 자동 실행하지 않았고 모든 관련 저장 값을 읽기 전용으로 보존했다. 13:28 최초 준비 당시의 빈 진행과 이번 같은 제품의 파일 갱신을 구분한다. 기존 Demo31 실행 파일 전체는 별도 `previous-demo31`에 백업했고 앞선 `GreedLastDemo-20261031.zip`도 그대로다.

**다시 실행하면 체험판 자체 진행은 이어진다.** 매번 초기화하는 프로그램이 아니며 기존 진행을 가져오거나 두 실행본의 저장을 합치지 않는다. 빈 칸을 기존 게임의 저장 소실로 판단하지 않는다. 어떤 저장 값도 직접 지울 필요가 없다.

## 눌러볼 순서

1. **타이틀 → 입구 → 기초 연습**: 이집트 인간 주자와 앞으로 달리는 통로를 본다. 좌/중/우는 이동 레인이 아니라 위험과 같은 대응 채널이다.
2. **점프 → 숙이기 → 비틀기**: 판정선을 보고 A/S/D 또는 해당 채널을 누른다. 동작 그림과 단계 제목이 맞아야 한다. 마지막 연습 판정 뒤 곧바로 결과로 넘어가는 것은 정상이다.
3. **연습 중 ESC/P → 재개**: 별도 정지 메뉴 뒤 새 재개 입력, 카운트와 앞 여유를 확인한다. 정확/Good의 차이와 소리는 여기서 비교한다. 보정은 직접 체감한 값만 쓰고 미리보기의 합성 -200ms를 따라 적용하지 않는다.
4. **로비 → 일반 런 → 시작 기프트**: 2초 이상 기다렸다가 고르면 출발 카운트로 이어져야 한다. 카운트 중 ESC/P → 잠시 대기 → 새 재개를 확인한다. 정지 메뉴 뒤에서 주자가 계속 커지거나 입구 연출이 재개 때 반복하면 안 된다. 0.34초 경계를 억지로 손으로 맞출 필요는 없다. 장 마감 루트/기프트와 중반 유물도 각각 고르고 정확의 이득과 짧은 회전을 본다.
5. **공명핵 → 탈출 게이트 → 클리어 요약**: 핵만 얻었다고 끝나지 않아야 한다. `저장 슬롯 선택`으로 가거나 `저장 없이 로비`를 고른다.
6. **저장할 칸 선택 → 확정**: S2/S3 등 원하는 칸에 이번 후보를 한 번만 저장한다. 관리에 다시 들어가도 같은 후보를 두 번 저장할 수 없어야 한다.
7. **무한 정비 → 취소 → 다시 준비 → 실제 시작**: 취소는 2회 그대로, 실제 첫 시작만 2→1이다.
8. **자연 종료 → 재준비 → 두 번째 실제 시작**: 칸이 자동으로 비어도 시작한 런은 계속되어야 한다. 체험판 조합이므로 보관할 개인 조합은 소모하지 않는다.
9. **로비 → 기록 → 새 연습/새 일반 런**: 기록만 보이고 옛 그림·방향·점수 표시가 새 런에 남지 않는지 본다.

이 실행본은 비개발 빌드라 무적·바로가기·위협 조절 키가 없다. 필요한 개발 확인은 Unity에서만 한다. 자세한 예외/조작은 [빠른 확인](GreedLast_Prototype_QuickCheck.md), 먼저 볼 무음 자료는 [움직임 미리보기](GreedLast_Prototype_MotionPreview.md)에 있다.
