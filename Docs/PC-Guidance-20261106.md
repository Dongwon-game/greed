# 2026-11-06 PC 안내 후속

다음 소스는 실행 검증 대기다. 집중 상태가 활성 함정의 Good 띠를 전폭 금색 띠로 덮던 경로를 분리했다. 플레이 보기에서 함정이 활성일 때 Good 띠의 범위와 색을 유지하고 집중 강조는 판정선에 적용한다. 주행 중 기본 바닥 타일의 밝기를 낮추되 박자·판정 강조를 더하는 값은 유지했다. 함정 그림이 있는 플레이 보기에서 먼 발광을 낮추고 판정 지점에서는 기존 발광을 사용한다. 다음 확인은 아래 ‘집중과 주행 표시’를 따른다.

다음 비교는 격리 Windows 후보에서 첫 중앙 함정 원거리·근거리 두 장을 기존 `ec33eaf` 캡처와 대조하는 것으로 시작한다. 그다음 연속 플레이에서 좌·중·우가 바뀌는 구간을 확인하고, 집중 발동 전후와 함정 사이를 나눠 본다. 안내가 옅어져도 목표 레인과 Good·정확이 구분되는지 확인한다. 청음과 실제 입력은 화면 캡처 결과와 구분해 기록한다.

후속 작업에서 함정 그림을 따라가는 발광·충돌 표시도 원거리에서 작아지도록 연결했다. 첫 좌우 함정의 원거리·근거리 렌더를 검사 도구에 추가했으며 실행은 대기다. 두 프레임에서 함정과 표시가 함께 접근하는지, 해당 레인 판정선이 구분되는지 확인한다.

프레임 보고서에는 함정 ID, 레인, 판정 기준 시간 차이를 포함한다. 각 프레임 쌍에서 레인과 함정이 같고 판정 시점에 더 가까워졌는지 확인한다. 첫 연습의 새 PC 안내는 키 입력이 회피 동작으로 이어진다고 설명한다. 1280×720 입구에서 줄바꿈과 Enter 진입을 확인할 예정이다.

일반 런 첫 중앙 함정의 원거리·근거리 캡처를 추가했다. 먼 바닥 함정이 주자에게 가리던 부분을 조정했고, 플레이 보기의 Good 띠와 판정선을 목표 레인 주위로 좁혔다. 상세 보기의 전폭 기준과 판정 시간은 유지한다. 연속 플레이에서는 좌우 함정, 비틀기, 빠른 판정 전환에서 좁아진 안내가 계속 읽히는지 확인한다.

주행 화면을 덜 가리도록 `9fd5e02`에서 플레이 보기의 활성 레인 면과 판정선 밝기를 줄였다. 이전과 같은 연습 프레임을 렌더해 목표 레인·함정·타이밍 문구를 확인했다. 일반 런 화면에서는 넓은 목표 표시를 더 줄였을 때 입력 방향과 타이밍이 읽히는지 비교한다. [검증 이력](GreedLast_Prototype_CheckHistory.md)

후속 검증에서 `3ef949d`의 전체 스모크와 격리 Windows 후보 빌드가 통과했다. 연습에서 렌더한 프레임에 함정 원근은 보이지만 레인 표시와 판정선이 시선을 먼저 끈다. 실제 창에서는 Enter 연습 진입과 ESC 정지·재개를 확인했다. 일반 런의 연속 화면, 직접 동시 입력·드래그·청음은 대기 상태다. 아래 작업 기록과 확인표는 처음 작업할 때의 범위를 보존한다. [검증 이력](GreedLast_Prototype_CheckHistory.md)

프로필 검증 페이지에 현재 화면의 Enter가 다음 페이지로 이동한다는 설명을 붙였다. 조작 체크의 강조 행동 설명에는 로비 문맥을 명시했다. 기존 통합 검사 기대값도 두 문맥을 구분하도록 수정했다.

사용자가 컴퓨터를 사용 중이며 검증을 미루기로 했다. 이번 변경의 컴파일, 스모크, 빌드 및 직접 창 검증은 미실행이다. 기존 a3080f7 후보는 이전 검증 결과에 해당한다. 다음에는 새 입력에서 스모크를 실행하고 1280×720 프로필 4/4 문구와 Enter 페이지 이동을 확인한다. 실제 드래그와 청음도 후속 확인 항목이다.

후속 작업에서는 PC 체험 안내와 빠른 확인 표를 실제 메뉴 동작에 맞춰 정리했다. 프로필·기록에서는 Enter로 다음 페이지를 열고, 저장 슬롯에서는 선택 후 별도 Enter로 확정한다. 새 로비 Enter 안내가 점수 행에 섞일 경우 제거하도록 정리 조건과 기존 검사 사례를 추가했다. 다음 검증에서 점수와 콤보가 보존되는지 확인한다. 검사 실행은 미뤘다.

첫 연습 입구에 PC Enter와 기초 연습 버튼을 안내했다. 체험 문서는 실행본 식별 정보로 소스와 배포본을 구분하고 F11 상세 표시의 개발 빌드 조건을 명시했다. 다음 직접 확인에서 첫 화면 안내의 줄바꿈과 Enter 진입을 확인한다. 이번 실행에서는 검증을 보류했다.

검증 재개 순서는 현재 작업 브랜치 소스로 격리 Windows 후보 생성, 첫 입구 안내와 Enter 진입, 프로필 4/4 안내와 페이지 이동, 점수·콤보 보존, 실제 드래그·청음이다. 후보 생성에는 스모크가 포함된다. 프로필·기록은 PlayerChecks의 InteractiveBoards 절차를 사용하고 기존 개인 저장과 분리한다.

복기 상태에 따라 연습 버튼 이름이 달라지는 경우를 고려해 입구 안내를 ‘연습 버튼’으로 통일했다. 기존 스모크 기대값에 PC Enter 안내와 모바일 문구 분리를 추가했다. 작업 위치 문서는 11월 4일 소스, 11월 5일 검토 후보, 11월 6일 검증 대기 변경을 구분한다. 이 단계까지 화면 조작, 컴파일, 빌드, 검사 실행을 보류했다.

PC 체험 안내에 최신 6-3 1Node의 선택 순서를 반영했다. 1~3장 루트와 마감 기프트, 2장 마감 기프트 뒤 유물, 4장 공명핵과 탈출을 구분한다. 소스의 분기를 읽어 작성했으며 이번 실행에서 일반 런을 재현하지 않았다.

프로필과 기록의 다음 버튼에는 기존 플랫폼 정책에 따라 Enter 표기를 붙였다. 기록 본문과 페이지 전환 동작은 기존 경로를 사용한다. 기존 스모크의 버튼 기대값을 갱신했으며 컴파일·스모크·창 검증은 보류했다. 다음 확인에서 1280×720의 긴 프로필 버튼 문구와 4→1 순환을 확인한다.

비개발 빌드의 입력 경로에서 Q/E가 회전 명령을 실행하지 않으면서 처리 완료를 반환해 같은 프레임의 채널 입력까지 건너뛸 수 있었다. 회전 개발 키의 활성 조건을 먼저 확인하도록 옮겼다. 이후 비개발 후보에서 Q/E 단독으로 동작이 없고, 같은 프레임의 A/S/D가 정상 전달되는지 확인한다. 개발 빌드의 회전 구간 Q/E와 Alt+Enter도 별도 대조한다. 이번에는 실행하지 않았다.

개발 빌드에서도 활성 회전 패턴이 없는 구간의 Q/E는 다음 입력 처리를 막지 않도록 했다. 활성 회전 구간의 Q/E는 기존 채널 처리로 연결된다. 정지 중에는 기존 채널 입력 차단을 따른다.
