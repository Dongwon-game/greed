# Greed Last 프로토타입 확인 순서

처음부터 짧게 확인할 때는 [GreedLast_Prototype_QuickCheck.md](GreedLast_Prototype_QuickCheck.md)를 먼저 사용한다. 이 문서는 세부 회귀와 그래픽 교체 뒤 비교할 항목을 모아 둔 전체판이다.

## 목적

- 지금 빌드는 완성 게임이 아니라 기획서의 핵심 체감인 `피하기 + 정확 타이밍 보상`을 확인하는 프로토타입이다. 1차 목표는 `시작→런 확인`과 일반 런 진입 체감이며, 구현축은 `회피·박자·보상·저장·무한`이다.
- 현재 단계는 기능 체감 우선에 1차 그래픽 패스를 얹은 상태다. 정식 아트가 아니라 시야, 속도감, 질감이 같은 체감을 살리는지 먼저 본다.
- 1차 그래픽은 도깨비 소녀 실루엣, 피라미드 암부, 금색/청록/주홍 함정 구분만 확인한다. 정식 캐릭터 원화나 배경 완성도는 아직 평가하지 않는다.
- 기본 화면은 템플런처럼 앞으로 달리는 직선 통로다. 놈식 회전 감각은 전체 화면 회전이 아니라 특정 `회전 통로` 패턴에서만 짧게 통로가 기울어지는 변주로 본다.

## 2026-10-11 전환 프레임 입력

1. 기초 연습에서 ESC/P로 정지한 뒤 새 재개 입력을 누른다. 2→1→GO와 앞 여유 뒤 같은 함정으로 돌아오고 정지 중 체력·점수·거리·집중 시간이 그대로여야 한다. 에디터 F11 상세 표시에서도 새 재개가 동작해야 한다.
2. 정지 메뉴가 나타나기 전 시작한 누름은 길게 유지했다 떼어도 재개 명령이 되지 않는다. 정확히 같은 프레임의 입력 순서를 손으로 맞출 필요는 없다. Play 중지 뒤 `Greed Last/Run Engine Play Mode Lifecycle Check` 또는 전체 루프 검사가 이 경계를 실제 EventSystem 프레임의 합성 터치/마우스로 검사한다.
3. 새 입력 차단은 취소 프레임 한 번뿐이다. 이미 표시된 메뉴에서 새로 누른 재개는 정상이어야 한다. 기존 정지 갱신·판정 폭·저장 한 번·정비 무소모·두 번 실제 시작/자동 비움은 바꾸지 않는다.
4. 기본 표시의 로비 버튼은 전환 순간 아직 숨겨져 있어 이 새 명령 재현 범위에 세지 않는다. 전체 확인의 보이는 로비/결과/저장·준비 회귀는 별도로 유지한다. 합성 엔진 입력과 실제 폰/OS 입력·지연/FPS 검사는 구분한다.

## 2026-10-10 확인 취소·확정 후속

1. 저장/무한 관리에서 삭제 또는 이름 변경 확인을 열고 취소한다. 슬롯/사용권/이름과 대기 후보가 그대로여야 하며, 취소 전에 누른 손의 늦은 해제로 확인창이 다시 열리지 않아야 한다. 취소 후 새로운 확인 입력은 정상이다.
2. 이름을 확정한 뒤 이미 누르고 있던 다른 손을 떼어도 이름 확인이 다시 열리지 않아야 한다. 삭제 확정 뒤 유지한 로비 버튼의 해제도 새 저장 포기/로비 이동을 실행하지 않아야 한다. 이름 변경은 사용권을 줄이지 않고 삭제는 선택한 조합만 비운다.
3. 일반 클리어의 저장 포기 확인에서 취소/상세로 돌아간다. 대기 후보를 유지하며 이전 로비 누름의 해제로 저장 포기 확인이 다시 열리면 안 된다. 새 로비 입력은 기존의 보호된 저장 포기 확인을 열어야 한다.
4. 보관할 개인 조합을 삭제/이름 변경할 필요는 없다. Play 중지 뒤 `Greed Last/Run Held Save Confirmation Check`는 기존 여섯 확인 진입과 새 아홉 취소·확정 경로를 격리 확인한다. 엔진 검사도 실제 활성 명령의 등록/취소를 해제 전 확인하며 휴대폰 입력/FPS 검사와 구분한다.

## 2026-10-10 실제 입력 대상 확인

기본 주행의 점수·거리·콤보·정확/Good/Miss 문구는 표시 내용이 같을 때 재사용한다. 정확/Good/Miss 뒤 실제 증가량, 정지/재개, F11 왕복과 새 연습의 0점/판정 수 0이 그대로인지 먼저 본다. 같은 숫자라도 표시 형식이 달라지는 경우는 세 읽기 전용 문화권과 같은 객체의 가변 숫자 형식으로 격리 대조했다. 메모리 할당 이벤트 감소를 실제 휴대폰 FPS 개선으로 표시하지 않는다.

1. 기본 표시로 연습에 들어가 주행 중 중앙 버튼을 마우스로 누른 채 P/ESC로 정지한다. 이전 누름을 떼어도 정지를 유지하며, 새 재개만 기존 카운트와 앞 여유를 시작해야 한다.
2. F11로 상세 표시를 먼저 연 뒤 같은 방법으로 중앙 버튼과 로비 버튼을 각각 확인한다. 로비 버튼을 누른 채 정지한 뒤 해제해도 포기/정산하지 않아야 한다. F11 전환 자체가 누름을 취소하므로 누르는 도중 표시를 바꾸는 경우와 구분한다.
3. 기본 주행에서는 로비 버튼이 숨겨져 있는 것이 정상이다. 보이지 않는 위치를 눌러 두 번째 명령을 검사했다고 판단하지 않는다. 두 손가락의 실제 기기 입력은 휴대폰 확인 단계다.
4. 결과 유지의 격리 검사는 다섯 종료 경로 × 기본/상세 열 경우, 정지 메뉴는 세 주행 모드 × 기본/상세 여섯 경우다. 등록된 포인터의 클릭 자격이 해제 전에 취소됐는지 확인하며 새 입력은 정상이어야 한다.
5. 전체 엔진 검사는 두 재로딩 방식 각각 세 자연 실패 × 기본/상세, 두 표시의 세 번째 손 정지, 일반 마지막 함정과 정비 확정의 실제 유지 터치를 확인한다. 개인 조합/포인트는 사용하지 않는다. 검사 통과를 OS 키 입력·휴대폰 센서·소리 지연/FPS 통과로 확대하지 않는다.

## 2026-10-09 종료 뒤로 가기와 저장 확인

### 주행 결과·정지 메뉴·정비 전환의 유지 입력

1. 기초 연습에서 주행 중 중앙 정지 버튼을 누른 채 마지막 실패/완료를 기다린다. 결과가 뜬 뒤 떼어도 재시작되거나 로비로 넘어가지 않아야 한다. 결과에서 새로 누른 버튼과 ESC는 정상 동작한다. 일반 실패·클리어·무한 종료도 같은 원칙이다. 피격 연출의 정상 만료와 결과 수치 보존을 구분한다.
2. 무한 준비의 유물 선택 전에 중앙 `유물 선택` 버튼을 누른 채 다른 손/키로 유물을 고른다. 전환 보호 뒤 이전 중앙 누름을 떼어도 정비 완료 화면과 사용권을 유지해야 한다. 새 `시작 -1회`/`마지막 시작` 입력만 한 번 차감한다. 개인 조합을 확인용으로 소모할 필요는 없다.
3. Play 중지 뒤 `Greed Last/Run Held Run Result Check`는 세 실패·연습 완료·일반 탈출을 기본/상세 열 경우로 격리 검사한다. `Run Held Preparation Start Check`는 세 유물 × 2회/1회 잔여 여섯 경우를 확인한다. 실제 엔진 전체 검사는 자연 실패와 정비 중 유지 터치를 포함하며 손맛/실기기 센서 검사가 아니다.
4. 주행 중 중앙 버튼을 누른 채 다른 손으로 정지 메뉴를 연다. 이전 손을 메뉴의 재개 버튼으로 옮겼다 떼어도 정지 상태여야 한다. 새 재개 탭만 기존 카운트다운을 시작한다. `Run Held Pause Command Check`는 연습/일반/무한 세 모드를 기본/상세 여섯 경우로 격리 검사하며 실제 엔진은 두 유지 손 + 세 번째 정지 손으로 이동·해제와 새 재개를 확인한다.

슬롯 변경 보호도 포함한다. 저장 버튼을 누른 상태에서 A/S/D 또는 다른 손가락으로 다른 칸을 고른 뒤 이전 누름을 떼어도 새 칸에 저장되지 않아야 한다. 새 저장 입력만 후보를 한 번 소비한다. 보관할 조합에 삭제/이름 변경을 시험할 필요는 없으며 `Greed Last/Run Held Slot Change Check`가 저장·무한 준비·두 관리 화면의 삭제/이름 변경 여섯 경우를 격리 확인한다.

1. 연습 중 ESC/P로 정지·재개하고 결과 화면에서 ESC로 로비에 돌아온다. 재개는 기존 카운트/앞 여유를 유지하며 결과 뒤 P로 정산하거나 다시 주행하지 않는다. 일반 실패·무한 종료 뒤 ESC도 결과를 한 번만 반영한다.
2. 일반 클리어 뒤 ESC는 저장 슬롯 선택을 열어야 한다. 원하는 빈 칸을 고르고 한 번 저장하거나 저장 포기를 확인한다. ESC 한 번만으로 클리어 후보가 사라지면 안 된다. 기존 `로비로` 버튼의 저장 안 함 선택과 구분한다.
3. 덮어쓰기·저장 관리/무한 관리의 삭제·이름 변경·저장 포기 확인에서 이전 화면부터 누른 두 번째 손을 늦게 떼어도 확정되지 않아야 한다. 확인 화면에서 보호 뒤 새 탭은 정상 처리된다. 이 검사를 위해 보관할 조합을 삭제·소모하지 않는다.
4. Play 중지 뒤 `Greed Last/Run Result Back Navigation Check`와 `Greed Last/Run Held Save Confirmation Check`는 개인 데이터 없이 위 경로를 검사한다. `Run Engine Multi Touch Check`는 여섯 확인 경로의 실제 EventSystem 프레임을 포함하고, `Run Engine Play Mode Full Loop Check`는 클리어 뒤 저장 보호와 두 실제 무한 종료의 ESC 정산도 포함한다. 키보드 라우팅 콜백 검사와 실제 OS 키 입력은 구분한다.

## 2026-10-06 성장 입력 후속 확인

1. 개인 포인트를 확인용으로 쓰지 않는다. 강화할 계획이 있는 항목만 한 번 구매해 잔액/해당 레벨이 기존 비용대로 한 번 바뀌는지 본다. 추천이 바뀌는 빠른 연타나 이미 누른 두 번째 손의 해제만으로 추가 구매되면 안 된다. 보호 뒤 새 입력은 정상 구매한다.
2. Play를 멈춘 뒤 `Greed Last/Run Growth Command Protection Check`는 다섯 격리 경우를 검사한다. 실제 엔진 전체 루프는 추천 연타·두 명령 손가락·두 레인 손가락과 새 입력 복구도 포함하며 개인 포인트/슬롯을 사용하지 않는다.
3. 저장/무한 시작 확정은 두 손가락 중 하나를 떼어 한 번만 실행되고 다른 손을 유지하다 나중에 떼어도 새 화면 명령이 실행되지 않아야 한다. Began/Ended를 여러 프레임 반복하지 않는 합성 입력과 실제 휴대폰 확인을 구분한다.

## 2026-10-05 저녁 후속 확인

1. 일반 클리어/실패/중단 또는 무한 종료 후 성장 포인트와 해당 기록이 한 번 반영되는지 본다. 성장 구매 뒤 남은 포인트와 재진입 상태가 같아야 한다. 평소 보상량·가격은 이번 변경으로 바뀌지 않는다.
2. 무한 준비에서는 기존 조합의 시작 보너스만 받고 일반 런의 누적 점수/판정 수를 이어받지 않아야 한다. 준비 취소 무소모·실제 두 번 시작·해당 칸 자동 비움과 일반 클리어 후보 한 번 저장을 함께 확인한다.
3. 직접 큰 수를 만들 필요는 없다. Play를 멈춘 뒤 `Greed Last/Run Progress Boundary Check`는 포인트/완료 횟수·격리 재읽기/구매/재보상/두 번 사용, `Greed Last/Run Record Statistics Boundary Check`는 비율·등급·시작 보너스와 복기 안내를 검사한다. 테스트 샘플/후보도 개발 모드 안에서만 확인하며 개인 데이터 편집·초기화는 하지 않는다.
4. 성장 화면에서 본문은 위쪽 스크롤, 생존/집중/타이밍 선택은 아래쪽에 분리돼야 한다. 강화하려던 항목을 고를 때만 기존 비용과 잔액/레벨 변경을 확인한다. 확인을 위해 개인 포인트를 소모할 필요는 없다. `Greed Last/Capture Progress Boundary Checks`는 평소 3포인트·상한·구매 뒤·누적 요약의 소형/태블릿/와이드 12장 본문·클릭·스크롤을 격리 검사하며 전체 포인터 검사와 구분한다.

## 2026-10-05 점수와 기록 확인

1. 기초 연습이나 무한모드에서 정확/Good/Miss를 각각 한 번 낸다. 점수 증가와 판정 표시가 일치하고 같은 함정을 반복 눌러도 점수가 두 번 붙지 않아야 한다. 일반적인 손 플레이로 21억 점까지 도달할 필요는 없다.
2. 무한 종료 뒤 기록 보드에서 최근/최고/랭킹의 점수·등급·거리와 다음 목표를 확인한다. 종료 직후와 로비에서 다시 열었을 때 같은 기록이어야 하며 준비 취소로 기록이나 사용권을 바꾸면 안 된다.
3. 숫자 경계는 Play를 멈춘 뒤 `Greed Last/Run Score Boundary Check`로 확인한다. 상한 직전의 실제 5점 반영, 상한의 0점 추가, 정확/Good/Miss·중복 입력·구간 보상·등급·복기 목표·격리 JSON 재읽기를 검사한다. 정상 저장은 세 칸 × 두 경계에서 후보 한 번/두 번 실제 시작/자동 비움·세 번째 거절과 런 전용 유물 제외/무한 정비 재선택도 대조한다. 개인 슬롯은 소비하지 않는다.

4. 저장 후보를 슬롯에 저장한 직후 저장 조합 화면으로 다시 들어가면 `저장 후보 없음`, `새 저장은 다음 클리어 후 1회`, 기본 저장 버튼 비활성, `로비로` 복귀가 같이 보이는지 본다.
5. 저장 조합을 두 번 사용해 자동 비움이 된 뒤 로비 실제 버튼이 `보충 런` / `보충 안내` / `무한 조합 보충`으로 갈라지고, 저장 조합 / 무한 준비도 같은 보충 흐름으로 이어지는지 본다.
6. 기록 보드에서 저장 후보, 품질 비교, 테스트키, 무적 테스트, `무적 ON/OFF`, `무적ON`, `종료 테스트`, `배율 +20`, `배율+20`, 예비 자세, 상태줄 보상, `보상 25점`, `점수 +N`, `정박 중앙 집중 +N`, `자동 비움`, 검증 순서의 `1 일반 런:`, `2 저장 조합:`, `3 무한모드:`, `4 기록/흔적:` 같은 안내가 빠지고 점수가 있는 실제 기록 행만 남는지 본다. `S1 마지막 1회`, `S2 1회 남음`, `안정형`, `집중형`, 단독 `A/S/B/C` 같은 저장 조합 상태/성향/등급 조각도 기록값처럼 남으면 안 된다. 거리 / 구간 / 위협 / 체력 / 콤보 / 실수는 그 기록 행의 보조값으로만 붙어야 하며 단독 조각으로 남으면 안 된다.
7. 첫 일반 런이 실패/중단이어도 기록 보드 요약에는 `최근 시도`, 일반 기록 페이지에는 `시도1`과 실패/중단 기록만 짧게 남는지 본다.
8. 로비 알림 / 저장 조합 관리 / 무한 준비 / 기록 보드 / 흔적 / 성장 보드의 문구가 길어져도 폰트와 본문 높이가 조정되어 버튼, 레인, 기록값과 겹치지 않는지 본다.
9. 로비 첫 화면 중앙에는 `피라미드 입구 동기화 완료`, `일반 런은 6-2에서 열립니다`, `일반런은 6-2에서 열립니다`, `일반 런 6-2에 보입니다`, `일반런 6-2 보임`, `첫 저장 전...`, `첫저장전...` 같은 기본 안내가 보이지 않고, 줄바꿈이나 `/`로 붙어도 숨겨지는지 본다. 저장 후보 / 저장 조합 없음 / 클리어 요약처럼 실제 행동이 필요한 안내만 보여야 한다.
   `|`, `;`, 쉼표, `·`, 마침표, 숫자 목록으로 붙은 같은 기본 안내도 숨겨지고, 그 뒤에 `저장 후보 대기` 같은 실제 행동 안내가 붙으면 숨겨지지 않아야 한다.
10. 기록 보드에는 `조작: 좌 일반 런`, `중 요약`, `우 무한 랭킹`, `다음 기록`, `이전 기록` 같은 페이지 조작 오버레이가 남지 않고 점수 / 거리 / 구간 / 위협 / 콤보 중심의 기록만 남는지 본다. 좌 / 중 / 우 레인 라벨은 기본 방향명만 보이고, 실제 페이지 이동 버튼은 아래 `이전` / `다음` / `로비로`만 짧게 남아야 한다.
11. 기록 보드와 흔적 화면에서는 주행 레인 / 판정선 / 주자 프리뷰와 기본 부제가 숨겨져 기록값과 페이지 이동 버튼만 먼저 읽히는지 본다. 로비 / 저장 / 성장 / 런 화면에서는 레인 프리뷰와 기본 부제가 그대로 남아야 한다.

## 기본 진입

1. Unity에서 `greed last` 프로젝트를 실행한다.
2. 필요하면 상단 메뉴 `Greed Last/Rebuild Boot Scene`으로 부트 씬을 다시 만들고, `Greed Last/Run Prototype Smoke Check`로 자동 스모크 검사를 실행한다.
3. 로비에서 `흔적`을 열고 첫 페이지의 `프로토타입 체크`와 4페이지의 `검증 순서`를 먼저 본다.
4. 첫 페이지의 `프로토타입 체크 - 기획 체감 검증`, `체감 목표: 피하기 + 정확 타이밍`, `단계: 기능 체감 우선 / 그래픽 후 시야·속도·질감 재검증`, `체크 0/7`, `루프 0/4`, `진행칸: 체크 [-------] / 루프 [----] / 남은: 일반 탈출` 같은 진행 카운트가 일반 런, 저장, 소모, 자동 비움, 무한 기록 흐름에 맞춰 올라가는지 본다.
5. `루프 n/4`는 후보 대기에서 `루프 2/4`, 실제 저장 완료 뒤 `루프 3/4`, 첫 무한 기록 뒤 `루프 4/4`가 되는지 확인한다.
6. `루프 상태`가 `저장 후보 처리`, `마지막 소진 확인`, `루프 완료 / 보충 필요`, `완성 기록 확인`처럼 숫자로는 같은 `루프 4/4`라도 남은 검증 행동을 구분해서 말하는지 본다.
7. 4페이지 첫 순서가 `위험→동작·박자·보상·상태줄·코치·루트 버튼·탈출 게이트`를 일반 런의 첫 확인 대상으로 잡고 있는지 본다.
8. 같은 줄의 `남은:`과 표시용 `다음 확인:`이 `시작→런 확인`, `복기 후 탈출`, `저장 후보 생성`, `후보 처리`, `첫 무한`, `2회 소진`, `보충 재진입`, `완성 기록`처럼 지금 비어 있는 확인 지점을 짧게 좁히고, `실행:`이 눌러야 할 버튼이나 테스트키를 같이 보여주며 로비 강조/Enter 경로와 같은지 본다.
9. `요약/다음:기록/실행:저장 조합`, `요약|다음:무한|실행:저장 조합`, `요약;다음 확인:저장;실행:기록`, `요약|다음:완성 기록|실행:저장 조합`처럼 공백 없는 `/`, `|`, `;` 구분자로 압축되어도 `다음:` / `다음 확인:`이 `실행:`보다 우선해서 같은 로비 버튼을 강조하는지 본다.
10. `무한 복기 전 기초연습`처럼 무한모드 재도전 전에 손을 풀어야 하는 항목은 `실행: 복기 연습`으로, `무한 복기 재도전`은 `실행: 무한모드`로 갈라지는지 본다.
11. 검증 순서에 `검증 모드`, `위험→동작 바닥↑점 상단↓숙 측면↔틀`, `정확→집중·반격·연쇄`, `위기→생존·고점·회복`, `상태줄 보상`, `코치 목표`, `3동작 HUD`, `최근 흐름`, `중앙/레인 큐`, `큐 숨김`, `F8 경로 ↑↓↔·↔↓↑·↓↔↑`, `F9 동작`, `F10 낙하 보기`, `F1 무적`, `F2 기프트·F3 유물·F4 핵·F5 탈출`, `F6`, `PgUp`, `PgDn`, `End`, `위협 폭·보상`, `일시정지 재개목표·배경차단`, `소리%·진동 ON/OFF`, `터치 탭`, `자동 비움`, `완성 루프: 일반→저장→무한→기록`이 보이는지 확인한다.

## 일반 런

1. `일반 런` 시작 후 `2 / 1 / GO` 카운트인이 끝나고 첫 함정이 내려오는지 본다.
2. 에디터에서는 좌 / 중 / 우 레인에 `A/←`, `S/Space`, `D/→` 키 힌트가 보이는지 확인한다.
3. 모바일/릴리스 표기에서는 같은 레인이 `좌 탭`, `중 탭`, `우 탭`처럼 터치 대상으로 읽히는지 확인한다.
4. 레인을 누르는 순간 해당 칸 안쪽에 짧은 입력 파동이 생겨 터치가 들어갔음을 바로 알 수 있는지 보고, 목표 레인을 정확 박자 가까이 누르면 판정 전부터 조금 더 밝고 크게 반응하는지 본다. 판정 직후에는 그 파동이 판정 색과 세기로 한 번 더 이어져야 한다. hold 잔광보다 새 탭이 더 밝고, 판정 직후가 가장 강하게 읽혀야 한다.
5. 에디터에서 A/S/D나 방향키를 누르고 있는 동안 해당 레인의 hold 잔광이 유지되고, 손을 떼면 사라지며 새 탭 반응보다 은은하게 보이는지 본다.
- 활성 함정이 가까워질 때 정답이 아닌 레인을 누르고 있으면 그 레인과 라벨이 작게 붉은 경고를 받고, 정답 레인에서 먼 오입력은 조금 더 강하게 보이며, 정답 레인이나 일시정지/선택/카운트다운/결과 화면에서는 이 경고가 남지 않는지 본다.
6. 하단 가이드가 `바닥→↑점프`, `상단→↓숙이기`, `측면→↔비틀기`처럼 위험군과 회피 기호를 같은 표기로 보여주는지 확인한다.
   - 회전 통로 패턴에서는 `통로→↺회전` 또는 `통로→↻회전`으로 표시되고, 에디터 힌트가 좌회전 `Q/A/←`, 우회전 `E/D/→`, 모바일/릴리스 힌트가 `좌 기울임` / `우 기울임`으로 보이는지 확인한다.
   - 회전 통로의 코치 / 목표 / 판정 문구가 일반 `회피`가 아니라 `정렬`, `보정 정렬`, `정렬 실패`로 구분되는지 확인한다.
   - 회전 통로 입력 없음 / 오입력 안내도 일반 `좌 탭`이 아니라 `정답 좌 기울임` 또는 `정답 우 기울임`으로 나오는지 확인한다.
   - 모바일에서는 회전 통로가 뜰 때만 좌/우 기울임이 1회 입력으로 먹고, 이미 기울인 채로 들어간 패턴은 중립 복귀 전까지 자동 성공처럼 처리되지 않는지 본다.
   - 모바일 가로 좌/우 그립을 각각 한 번씩 바꿔 들어도 화면 기준 같은 쪽 기울임이 같은 회전 방향으로 판정되는지 본다. Unity 화면 방향 센서 보정을 사용하므로 앱이 축을 한 번 더 뒤집어 반대로 움직이면 안 된다. 기기 방향이 바뀌는 순간과 앱 복귀 직후에는 현재 흔들림을 버리고 중립을 거친 뒤 약 0.08초 유지한 기울임만 받아야 한다.
   - 가속도 센서가 없는 기기/시뮬레이터에서는 기울임 커서가 멋대로 움직이거나 자동 판정되지 않아야 한다. 이때도 좌/중/우 화면 터치 입력은 정상 동작해야 한다.
   - 센서 비지원 상태의 회전 통로 액션 큐와 입력 없음/오입력 안내는 `기울임` 대신 `좌 탭` 또는 `우 탭`을 보여야 한다. 센서 지원 기기에서는 기존 `중립→좌/우 기울임` 안내가 유지되어야 한다.
   - 센서 비지원 상태에서는 회전 통로 목표 방향은 보이되 하단 중립 게이트, 움직이는 센서 커서, 좌우 기울임 손잡이는 숨고 방향 피프와 레인 탭은 남아야 한다. 에디터 F9 드래그에서는 이 기울임 요소들이 계속 보여야 한다.
   - 하단 중립 게이트 아래 작은 센서 커서가 실제 기울임을 좌우로 따라오고, 정답 방향이면 금색/청록, 반대 방향이면 주홍색으로 보이는지 확인한다. 커서는 회전 통로 밖과 중립 부근에서 숨고 제목/HUD/판정선은 움직이지 않아야 한다.
   - 에디터에서는 F9로 회전 통로를 띄운 뒤 화면을 임계값보다 짧게 천천히 좌우 드래그해 같은 센서 커서 이동과 색을 먼저 확인하고, 더 길게 드래그했을 때만 실제 Q/E 대응 판정으로 넘어가는지 본다.
   - 정답 쪽으로 기울이거나 드래그하는 동안 통로 레일과 전방 수평선이 아주 조금 수평에 가까워지고 금색이 얇게 섞이는지 본다. 반대쪽은 기울기가 조금 더 남고 주홍 경고가 섞여야 하지만 화면 전체, 제목, HUD, 판정선은 돌아가거나 밀리면 안 된다.
7. 활성 함정 근처에서 에디터는 `바닥 위험 → ↑ 점프 회피 · A/← · 1박 전 · 정확+...→집중`, 모바일은 `바닥 위험 → ↑ 점프 회피 · 좌 탭 · 1박 전 · 정확+...→집중`처럼 중앙 액션 큐가 위험군, 동작, 입력, 박자, 보상 목적까지 한 줄로 보여주고 좌/우 목표 레인일 때 해당 방향으로 살짝 치우치는지 확인한다.
   - 회전 통로에서는 중앙 액션 큐가 `통로 위험 → ↺ 좌회전 정렬 · 중립→좌 기울임` 또는 `통로 위험 → ↻ 우회전 정렬 · 중립→우 기울임`처럼 방향과 중립 복귀 후 기울임 입력을 같이 보여주는지 확인한다.
- 회전 통로 판정 직후 묶음 완료가 겹쳐도 중앙 판정 피드백에 `정렬`, `정확→...`, `정박 충전` 또는 `압박 반격` 같은 직전 회전 통로 보상 줄이 남아 입력 결과가 끊기지 않는지 확인한다.
- 중앙 액션 큐가 성공 창에 가까워질수록 박자에 맞춰 조금 더 밝고 크게 숨 쉬며, 정확 창 안에서는 펄스가 더 강해져 눌러야 할 순간이 문구 크기로도 읽히는지 본다.
8. 활성 목표 레인에는 `바닥→↑점프 · 정확→충전+1`, `상단→↓숙이기 · 정확→반격+50`, `측면→↔비틀기 · 정확→연쇄+1`처럼 위험군, 회피 동작, 정확 보상이 같이 보이는지 확인한다.
- 목표 레인 타이밍 문구가 대기 중에는 `2박 전`, `1박 전`, `다음 박`처럼 박자 기준을 쓰고, 보정권에서는 `곧 0.12 · 다음 박`처럼 초 단위와 박자 기준을 같이 보여주는지 본다.
9. 활성 목표 레인 안쪽 glow가 정답 레인에만 생기고, 판정선에 가까워질수록 더 선명해지며 체력 위험 / 무한 고위협 상태에서는 조금 더 또렷해지는지 본다.
- 목표 레인 glow와 `좌 / 중 / 우` 라벨이 박자에 맞춰 살짝 밝아지고 두꺼워지며, `지금 박 / 다음 박 / N박 전`의 박자 긴급도가 올라갈수록 중앙 타이밍 가이드, 함정 마커, 판정선, 가까운 타이밍 눈금, 전진선, 바닥 박자 타일, 터널/기둥, 주자 몸짓/그림자/코어 glow, 라이브 박자음이 같이 조금 더 선명해지고, 판정 직후에는 해당 레인의 판정 색과 자연스럽게 이어지는지 본다.
- 같은 판정창에서 `지금 박`, `늦은 박`, `지난 박`, `다음 박`, `1박 전`, `2박 전` 문구와 화면 밝기/소리 긴급도가 같은 순간을 가리키는지 본다.
- 하단 타이밍 가이드가 `정박`, `지금 누르기`, `곧 정확권`, `보정권 / 늦음`, `놓침`, `준비`를 판정창 경계에 맞춰 바꾸고, 앞에 붙는 박자 큐와 의미가 충돌하지 않는지 본다.
10. 하단 상태 줄에 `바닥→↑점프 정확 +N→집중 / 보정 +N`처럼 보상 미리보기 자체에 정확 입력 목적이 붙고, 뒤에 `체감 일반 바닥→↑점프→정확→집중`, `체감 보충`, `체감 연습`, `체감 무한` 같은 짧은 체감 토큰도 현재 모드에 맞게 남는지 확인한다.
11. 탈출 검증 구간에서는 같은 상태 줄 체감 토큰이 `체감 탈출 ...→정확→반격/연쇄/집중`처럼 바뀌어 일반 챕터와 마지막 입구 마무리, 정확 입력의 목적이 같이 구분되는지 확인한다.
- 체력 1칸, 집중 상태, 복구 패턴에서는 중앙 액션 큐 보상에도 `정확+N→생존`, `정확+N→고점`, `정확+N→회복` 목적 태그가 붙어 정확 입력이 무엇으로 이어지는지 코치 줄을 보지 않아도 읽히는지 확인한다.
12. 플레이 중 코치 라인도 `정확→집중`, `정확→반격`, `정확→연쇄`, `정확→회복`처럼 정확 입력의 보상 목적을 먼저 말한 뒤 회피 동작과 세부 보상을 안내하는지 확인한다.
13. 정확 입력을 이어가면 상태 줄에 `동작 ↑ 1/3→↓`, `동작 ↑↓ 2/3→↔`처럼 이번 묶음의 채운 동작과 다음 동작이 같이 보이는지 확인한다.
14. 점프 / 숙이기 / 비틀기를 모두 정확으로 지나면 흐름 태그가 `3동작 정확`으로 바뀌고 판정선 근처 세 칸 burst가 짧게 퍼졌다 사라지는지 확인한다.
15. 에디터 / 개발 빌드에서는 흐름 줄의 최근 패턴이 `좌정·바→점 > 중압·상→숙`처럼 레인, 박자, 위험군, 회피 동작을 같이 남기는지 확인한다.
16. 정확 입력 직후 배경 전진선, 바닥 박자 타일, 기둥 이동감, 주자 보폭, 터널 깊이감이 짧게 더 빠르고 밝아져 Good보다 큰 전진 보상으로 읽히는지 본다.
- 정확 / Good / Miss 판정 직후 주자 뒤에 짧은 잔상이 남고, 정확은 가장 밝고 길게, Good은 더 약하게, Miss는 붉고 무겁게 보여 입력 결과가 화면 움직임으로도 갈라지는지 본다.
17. 활성 함정이 판정선에 가까워질수록 배경과 레인 강조색이 현재 회피 동작 / 박자 성향 쪽으로 살짝 밝아지고, 일시정지/선택/결과 화면에서는 이 분위기 가중치가 남지 않는지 본다.
18. 정확 입력을 이어가면 콤보 배지 하단 정박 보상칸이 1칸씩 차고, 3칸째 집중 보상 직전/발동 느낌으로 밝아지며 보상 준비 다운비트에서는 마지막 칸이 가장 강하게 살아나는지 본다. 배지 배경/액센트와 화면 플래시도 같이 살짝 커지고 밝아져야 하며 선택/일시정지/결과 화면에는 남지 않아야 한다.
19. 정확 입력은 `바닥→↑점프 회피`, Good은 `상단→↓숙이기 보정`, Miss는 `측면→↔비틀기 실패`처럼 위험군과 회피 품질이 같이 구분되는지 보고, 해당 레인에 `정확` / `Good` / `Miss` 작은 태그가 뜨는지 확인한다. 정확 태그는 가장 크게 위로 튀고, Good은 중간, Miss는 낮고 무겁게 남는지 본다.
20. 정확 입력 직후 중앙 판정 피드백에도 `정확→집중`, `정확→반격`, `정확→연쇄`, 복구 패턴의 `정확→회복`, 집중 상태의 `정확→고점`이 짧게 남아 입력 보상이 끊기지 않는지 확인한다.
   - 좌 / 우 레인 판정 직후 중앙 판정 피드백이 해당 방향으로 살짝 치우치고, 중앙 판정이나 일시정지 / 선택 / 결과 화면에서는 다시 중앙에 남는지 본다.
21. 채널 오류나 입력 없음에는 에디터 `정답키 A/←`, 모바일 `정답 좌 탭` 같은 힌트가 붙고, 오입력 때 누른 레인은 `Miss`, 정답 레인은 `정답` 태그로 갈라지는지 본다.
22. Good 판정이 중앙 피드백과 코치 줄 모두에서 `빠름/늦음 Nms`와 `살짝 늦게/빠르게`를 알려줘 다음 입력 보정 방향이 바로 읽히는지 확인한다.
   - 일반 런 Good 피드백과 코치 줄에는 `정확→집중/반격/연쇄 미발동`처럼 목표 보상을 놓쳤다는 문구가 붙고, 체력 1칸에서는 `Good 생존 · 정확 보상 미발동`으로 생존과 정확 보상 차이가 분리되는지 본다.
   - Good 위주로 중단/실패한 결과 화면의 훈련 힌트와 복기 줄에 `정확 보상 복기`가 붙어 다음 행동이 정확권 전환 연습으로 이어지는지 본다. 무한모드 Good 구간 결과도 힌트 앞쪽과 복기 줄에 같은 문구가 남고 최근 구간이 `무한 1구간 3/3`처럼 진행도까지 보이는지 본다.
   - Good / 타이밍 Miss 직후 상단 목표 줄에도 `다음은 살짝 빠르게`, `다음은 조금 늦게`처럼 다음 입력 보정 방향이 짧게 붙는지 확인한다.
   - 채널 오류나 입력 없음 직후 상단 목표 줄에 `정답 채널 확인`, `다음 함정 입력`이 붙어 코치 줄을 못 봐도 다음 대응을 알 수 있는지 본다.
23. 판정선 입력 흔적 위에 `정확`, `빠름 Nms`, `늦음 Nms`, `오입력` 짧은 라벨이 잠깐 뜨고, 빠름은 위쪽 기울기, 늦음은 아래쪽 기울기, Miss는 더 두꺼운 흔적으로 남아 방금 누른 타이밍을 중앙 피드백 없이도 읽을 수 있는지 본다.
24. Good / 정확 판정 밴드가 함정 접근 중 조금 더 밝아지고, 정확 창은 목표 레인 안에서 살짝 넓어지며 정박 펄스 때 작게 숨 쉬는지 본다.
25. 판정선 펄스가 정확 입력에서는 가장 크게, Good에서는 약하게, Miss에서는 붉은 끊김 라인과 함께 중간 강도의 충격으로 보여 세 판정의 차이가 선 연출로도 읽히는지 본다. 콤보 3 이상을 끊은 Miss는 끊김 라인이 조금 더 넓고 두껍고 흔들리는지 확인한다.
26. 코어 타이밍 직전 소리 큐와 점프 / 숙이기 / 비틀기 액션 큐가 함께 들리고, 충전 / 반격 / 연쇄 같은 특수 보상 타이밍에서 액션 큐가 살짝 더 또렷한지 확인한다.
27. 함정 마커가 점프는 낮고 넓게, 숙이기는 두꺼운 상단 압박처럼, 비틀기는 가늘고 기울어진 측면 공격처럼 구분되고, 마커 안에 `↑` / `↓` / `↔` 회피 기호가 같이 보이는지 본다.
28. 함정 마커 뒤의 잔상이 점프는 낮고 넓게, 숙이기는 위에서 내려오는 두꺼운 블록처럼, 비틀기는 옆으로 쓸리는 가느다란 궤도처럼 보이는지 본다.
29. 정확 성공은 짧은 금색 통과 궤적, Good은 더 약한 보정 궤적, Miss는 붉은 충격 잔상으로 갈라져 판정 품질 차이가 보이는지 본다.
30. 정확 성공 효과음은 가장 선명하고, Good은 더 낮고 부드럽고, 고위험 Miss는 더 무겁게 들려 판정 품질이 소리로도 갈라지는지 본다.
31. 함정 경로 위의 작은 타이밍 눈금 3개가 판정선 쪽으로 가까워지는 순서를 보여주고, 가까운 눈금이 더 선명하고 살짝 크게 보이는지 본다.
- 가장 가까운 타이밍 눈금이 박자에 맞춰 조금 더 밝고 두꺼워지고, 먼 눈금보다 반응 폭이 큰지 본다.
32. 함정이 판정선에 가까워질 때 입력 전 아바타가 점프는 살짝 웅크림, 숙이기는 낮고 넓어짐, 비틀기는 옆으로 몸을 빼는 예비 자세를 보여주는지 본다. 주자 주변 준비선과 준비 기호도 점프는 발밑/위쪽, 숙이기는 낮고 넓게/낮은 옆쪽, 비틀기/회전은 몸 옆 세로선/옆쪽 기호로 짧게 켜지는지 본다.
33. 체력이 절반 이하로 내려가면 화면 가장자리 붉은 위험 비네트와 체력 게이지 아래 3칸 위험 피프가 박자에 맞춰 보이고, 체력 1칸 / 피격 직후 / 무한 위협 고단계에서는 가장자리가 더 안쪽으로 조여오는지 본다.
34. 집중이 1칸 남은 상태에서 주자 코어 glow가 켜지고, 활성 함정의 4박 첫 박 다운비트에서 짧게 더 밝아지며, 집중 상태 발동 뒤에는 기존 집중 코어 빛으로 바뀌는지 본다.
35. 집중 상태 발동 뒤 집중 게이지 아래 5칸 타이머가 남은 시간에 맞춰 줄고, 마지막 1초대에는 타이머 칸이 다운비트에서 더 밝고 크게 뛰며 판정선 금색 밴드도 박자에 맞춰 반응하는지 본다. 일시정지/선택/카운트다운/결과 화면에는 남지 않아야 한다.
36. 체력 1칸에서는 하단 가이드에 `체력 위험: ... Good 이상 생존`이 보이고, 상태 줄도 `체력 위험`을 짧게 유지하는지 본다.

## 일시정지

1. 런 중 에디터에서는 `Esc` 또는 `P`, 화면에서는 `일시정지` 버튼으로 일시정지를 건다.
2. 배경이 어두워지고 상하 / 좌우가 흐릿하게 눌린 뒤 중앙 메뉴가 따로 뜨며 오른쪽 테스트 도구가 숨는지 본다.
3. 메뉴 배경 빈 곳을 눌러도 아래 레인이나 버튼이 반응하지 않는지 본다.
4. 일시정지 중 중앙 액션 큐가 메뉴 위에 남지 않는지 확인한다.
5. 다시 `Esc` 또는 `재개`를 누르면 `2 / 1 / GO` 후 첫 함정이 다시 읽기 쉬운 위치에서 시작하는지 본다. `GO` 직후 함정이 이미 지나간 판정으로 처리되지 않고, 짧은 여유 뒤 정확 입력이 가능한지 확인한다. 재개 카운트 중 블러가 조금 더 진해지고, `대기`보다 `2`, `1`, `GO`가 차례로 더 크고 밝아지며, 첫 `2` 박자음이 밀리지 않고 재개/GO 비트음도 시작 카운트보다 또렷한지 확인한다.
6. 일시정지 메뉴의 `재개 목표`와 재개 카운트 중 목표 줄에 `정확→집중/반격/연쇄/생존/고점/회복` 같은 현재 정확 입력 목적이 같이 남는지 본다.
7. 자동 진행이 켜진 상태에서 일시정지했다면 메뉴 중에는 멈추고, `GO` 뒤에는 다시 자동 진행 상태로 돌아오는지 본다.
8. 일시정지 메뉴와 재개 카운트 중에는 기존 함정 마커 / 타이밍 밴드 / 목표 레인 강조색 / 중앙 액션 큐 / 입력 파동 / `다음 함정 대기` 문구가 남지 않고, 주자 보폭과 전진선도 라이브 주행처럼 움직이지 않으며, `GO` 뒤에 다시 활성 함정과 타이밍 가이드와 전진감이 보이는지 본다.
   - 선택지, 시작 카운트다운, 결과 화면에서도 같은 기준으로 주자 보폭 / 전진선 / 다운비트 강조 / 목표 레인 / 짧은 판정 잔상 / 일반 박자음 / 박자 긴급도가 라이브 플레이처럼 남지 않는지 본다.
9. 일시정지 메뉴나 런 오른쪽 보정 버튼에서 `빠름 +20ms`, `추천`, `늦음 -20ms`를 확인한다.
10. 시작 또는 재개 `2 / 1 / GO` 중 앱 전환이나 포커스 이탈이 생기면 카운트가 멈추거나 취소되고, 돌아와서 다시 `재개`를 눌러야 진행되는지 본다.
11. 같은 메뉴에서 `설정: 소리 N% / 보정 ... / 진동 ON/OFF` 상태 줄과 `소리 -`, `소리 100%`, `소리 +`, `진동 ON/OFF` 버튼이 보이고 런 중에도 오른쪽 테스트 패널에 표시되는지 본다.
12. `소리 0%`, `소리 60%`, `소리 100%`가 표기만 바뀌는 것이 아니라 비트음 / 판정음 / 선택음 크기에도 실제로 한 번만 반영되어, 60%가 과하게 작아지지 않는지 본다.
13. 진동 ON/OFF가 표기와 실제 런 진동에 같이 반영되고, Android 실기에서는 아주 짧은 진동과 긴 진동이 1~120ms 안에서 과하지 않게 느껴지는지 본다. 시작/재개 `2 / 1 / GO`는 손에 아주 약하게 들어오되 라이브 박자마다 진동하지 않아야 하며, Good은 짧고 부드럽게, 정확 중앙 입력과 콤보/집중/목표 달성은 더 또렷하게, 고위험 Miss는 가장 무겁게 느껴지는지도 같이 확인한다.
14. 모바일 / 릴리스 표기에서는 일시정지 버튼이 `일시정지`로 보이고, 헤더와 본문 재개 줄이 `ESC`가 아니라 `재개 버튼`으로 읽히는지 본다.
15. 복기 목표와 설정 줄이 길게 붙어도 일시정지 본문이 패널 안에서 줄어든 폰트로 읽히고, 중앙 레인 / 재개 버튼과 겹치지 않는지 본다.
16. 일반/기초연습/보충/무한에서 일시정지하면 제목이 각각 `일시정지 메뉴`, `기초연습 메뉴`, `보충 런 메뉴`, `무한모드 메뉴`로 갈라지고, 재개 카운트인은 `재개 준비`로 바뀌며 로비 버튼 안내와 본문도 연습 일반 기록·저장 기회 유지 / 보충 중단 기록 / 무한 정산 종료에 맞게 바뀌는지 본다.

## 테스트 단축키

1. `F1`: 무적 ON/OFF.
2. `F2`: 기프트 선택 구간.
3. `F3`: 유물 선택 구간.
4. `F4`: 공명핵 회수 직후.
5. `F5`: 탈출 직전.
6. `F6`: 런 중 집중 발동, 로비에서는 테스트 저장 슬롯 생성 또는 후보 추천 저장, 성장판에서는 포인트.
7. `F7`: 복기 목표 직전. 버튼에는 `목표 정산`, `목표 구간`, `목표 보정`처럼 목표 종류가 먼저 붙는다.
8. `F8`: 안정 / 변주 / 압박 경로 순환. 버튼에는 `경로 안정 ↑↓↔`, `경로 변주 ↔↓↑`, `경로 압박 ↓↔↑`처럼 다음 경로의 동작 배열이 붙는다.
9. `F9`: 점프 / 숙이기 / 비틀기 / 좌회전 통로 / 우회전 통로 대표 함정 순환.
10. `PageUp` / `PageDown`: 무한 위협 상승/하강 또는 로비 저장 소모/후보 생성. 저장 조합이 비어 보충 흐름이면 `PgDn 보충 후보`로 보이는지 확인한다. 일반 런에서는 `PgDn 피해 -1`로 체력 위험 비네트를 바로 확인한다. `F10 낙하 보기`는 함정/예고 피프 접근 속도만 보통/느림/빠름으로 바꾸고 판정 위치는 유지하는지 본다. 화면 버튼은 `PgUp` / `PgDn`으로 줄여 표시된다.
11. `End`: 무한모드 정산 종료. 정산 뒤 결과/복기 문구는 `정산 종료`로 읽혀야 하며 기록 화면에 `테스트 종료 기록`이 남으면 안 된다.
12. `End 정산 종료` 결과의 다음 행동은 `정산 종료 확인 후 무한모드 실전 재개`로 읽히고, Enter/강조도 무한모드 버튼으로 잡히는지 본다.
13. 첫 저장 전 로비에서는 `PgUp 저장 없음`, 저장 조합이 전부 비어 보충이 필요한 상태에서는 `PgUp 보충 확인`으로 갈라지는지 본다.
14. 첫 저장 전 `PgUp` 알림은 `F6 테스트 저장` 또는 일반 런 클리어를 먼저 안내하고, 자동 비움 뒤 `PgUp` 알림은 무한 버튼의 보충 런을 안내하는지 본다.
15. 로비 중앙에는 기본 동기화/첫 저장 전 안내 묶음이 보이지 않고, 저장 후보/저장 조합 없음/클리어 요약처럼 눌러야 할 행동이 있는 안내만 보이는지 본다.
16. 본게임용 릴리스 빌드에서는 오른쪽 테스트 패널과 F1~F10 / PgUp / PgDn / End 개발 단축키가 보이지 않아야 한다.
17. 릴리스/모바일 정책의 흔적 검증 순서에서는 F키 대신 `터치 레인 좌·중·우`, `강조 버튼: 다음 행동`, `개발 테스트키 숨김`, `종료 흐름`처럼 본게임용 확인 문구가 보이는지 본다.

## 저장 조합

1. 일반 런 클리어 후 바로 저장 슬롯 선택 화면이 뜨고, 화면 첫 줄이 `클리어 요약`으로 시작해 점수 / 판정 / 저장 후보 / `저장 기회: 1회`를 먼저 보여주는지 확인한다.
2. 클리어 직후 하단 버튼이 `저장 슬롯 선택`과 `저장 없이 로비`로 갈라져 보이고, 저장 슬롯 화면에서 `선택 전 저장 잠김`이 보인 뒤 원하는 슬롯에 들어가는지 본다.
3. 저장 슬롯 선택 화면에서 추천 슬롯이 떠 있어도 좌 / 중 / 우로 다른 슬롯을 직접 고르면 선택이 추천 슬롯으로 되돌아가지 않고, 저장 버튼이 그 선택 슬롯에 저장하는지 본다.
4. `저장 없이 로비`로 돌아오면 저장 후보만 소모되고 `클리어 요약`은 로비에 남으며 기록 버튼이 `클리어 복기`로 바뀌는지 확인한다. 보충 런이면 같은 자리에서 `보충 런 저장 안 함`과 `보충 기록`으로 압축되어야 한다.
5. 저장 후보를 슬롯에 저장하거나 포기하면 `저장 후보 없음`으로 바뀌고, 다시 로비/저장 조합에 들어와도 같은 클리어의 저장 기회가 남지 않으며 새 저장은 다음 클리어 후 1회만 가능하다고 보이는지 확인한다. 후보가 없는 상태에서 저장을 다시 눌러도 이전 `저장 조합 저장 완료` 알림이 재사용되면 안 된다.
6. 기존 슬롯이 있는 상태에서 새 후보가 생기면 흔적과 저장 조합 화면에 `후보 비교 후 저장/포기`, `저장 버튼: 덮어쓰기 확인 / 포기 버튼: 후보 소모(1회)`가 보이는지 확인한다.
7. 저장 조합은 무한모드에서 2회 사용 후 자동으로 비워져야 한다.
8. 저장 슬롯과 무한 준비 화면에서 `2/2`, `1/2`, `자동 비움`, `시작 후 비움` 흐름이 읽히고, 로비 버튼/좌중우 슬롯/흔적 저장 페이지 압축 표기에서도 `2/2 2회`, `1/2 마지막`과 슬롯 안쪽 2칸 사용 피프가 남는지 확인한다. 슬롯 라벨이 `마지막 1회 (1/2)`, `S1 마지막 1회`, `S2 1회 남음`, `S3 2회 남음`처럼 접두어가 섞여도 같은 압축 상태로 읽혀야 한다.
9. 저장 조합을 만든 뒤 아직 무한모드에 사용하지 않았다면 흔적 첫 페이지에도 `소진 대기 S1 2/2 2회`처럼 현재 사용할 수 있는 조합과 남은 횟수가 보이는지 확인한다.
10. 흔적 4페이지 검증 순서의 `저장:` 줄도 사용 전에는 `소진 대기 S1 2/2 2회 / 2회 소진 후 자동 비움`, 첫 사용 뒤에는 `최근 소모 1/2 마지막 / 자동 비움 대기`처럼 현재 소진 상태를 말하는지 확인한다.
11. 무한 결과 메시지에 첫 사용 후 `마지막 1회 (1/2)`, 흔적 첫 페이지의 `최근 소모 1/2 마지막`, 최종 소모 뒤 `자동 비움`과 `무한 조합 보충`이 이어지는지 본다.
12. 자동 비움 뒤 흔적의 `프로토타입 체크`에 `최근 소진 자동 비움`이 보이고, 저장/성장 페이지에는 `무한 조합 보충 필요`가 보이는지 본다.
13. 자동 비움 뒤 무한 준비의 짧은 재시작 문구도 `보충 런`을 가리키고, `일반 런 클리어`로 되돌아가지 않는지 본다.
14. 선택한 슬롯이 비어 있어도 다른 슬롯에 사용 가능한 조합이 있으면 슬롯 선택 본문은 `선택 불가: 사용 가능한 슬롯을 고르세요.`와 `추천: 최고 슬롯 S... 선택 권장`을 보여주고, 보조 라벨은 `S... 불가 / 다른 슬롯`, 기본 버튼은 `추천 선택` 또는 `추천 슬롯`으로 읽히며, 무한 준비의 `추천 슬롯`은 먼저 추천 슬롯을 보여준 뒤 시작하고 `PgUp 저장 소모`는 자동으로 사용 가능 슬롯을 잡고 진행하는지 본다. S1이 2회 소진으로 자동 비워진 뒤 S2가 남아 있으면 로비 / 저장 조합 관리 / 무한 준비 / 실제 무한 시작이 모두 S2로 이어져야 하며, 프로젝트를 다시 열어도 같은 선택이 유지되어야 한다.
15. 위 상태에서 저장 후보가 없는 저장 조합 관리 본문도 `관리 모드 / 저장 후보 없음`, `선택: 슬롯 ... / 상태: 빈 슬롯`, `다음: 좌 / 중 / 우로 확인할 슬롯 선택`을 유지하고, 상세 보기 / 이름 변경 / 삭제 취소 / 저장 포기 확인처럼 같은 슬롯 화면 안의 갱신을 해도 직접 고른 빈 슬롯이 추천 슬롯으로 되돌아가지 않는지 본다.
16. 위 상태에서 상세 보기를 열면 보조 라벨이 `S... 불가 / 목록 보기`로 바뀌어 빈 슬롯 상세를 관리 대상으로 오해하지 않고, 목록으로 돌아가 사용 가능한 슬롯을 고르게 되는지 확인한다.
17. 저장 후보가 없는 저장 조합 관리 화면에서 빈 슬롯을 누르면 `슬롯 ...은 비어 있습니다`, `다른 슬롯에서 저장 조합을 확인하세요`, `S... 빈 슬롯 / 다른 슬롯`이 보이고, 상세 보기에서는 `S... 빈 슬롯 / 목록 보기`로 바뀌며, 이름 변경/삭제 안내가 뜨지 않는지 본다.
18. 저장 조합이 비어 있는 로비/저장 조합 관리/무한 준비/슬롯 선택 화면에서 로비 실제 버튼은 `보충 런` / `보충 안내` / `무한 조합 보충`으로 보이고, 저장 조합 관리와 무한 준비의 보조 버튼도 `보충 안내`로 통일되는지 본다. 본문은 `저장 후보 없음`, `보충 런 버튼: 보충 런 진입`, `다음: 보충 런 클리어 후 새 조합 저장`을 중심으로 읽히고, 선택 전 화면도 빈 슬롯 선택 대신 보충 런 안내로 읽혀야 한다.
19. 저장 조합이 전부 빈 상태에서 빈 슬롯 상세를 열어도 `일반 런 클리어`나 `좌 / 중 / 우로 확인할 슬롯 선택`이 아니라 `보충 런으로 새 저장 조합`과 `다음: 보충 런 클리어 후 새 조합 저장`이 보이는지 본다.
20. `다음: 보충 런...`, `다음 확인: 보충 런...`, `보충 런 버튼: 보충 런 진입`, `보충 후 무한 재진입` 문구가 보이면 로비 강조/Enter가 일반 런이 아니라 무한 조합 보충 버튼으로 이어지는지 본다.
21. 저장 후보가 남아 있으면 화면에 `보충 런...`, `보충 런 버튼: 보충 런 진입`, `보충 후 무한 재진입`이 같이 보여도 Enter/강조는 먼저 `저장 조합`으로 가는지 본다.
22. 저장 후보가 남아 있는 동안 에디터 `PgUp` 테스트 버튼은 `후보 우선`으로 보이고, 저장 슬롯이 비어 있거나 기존 조합이 있어도 보충 준비/저장 소모로 넘어가지 않고 후보 저장/포기를 먼저 안내하는지 본다.
23. 저장 후보가 남아 있는 동안 에디터 `F6 추천 저장`은 샘플 조합을 새로 만들지 않고 후보를 추천 슬롯에 저장하며, `PgDn 후보 대기`는 새 테스트 후보로 덮어쓰지 않고 저장/포기를 먼저 안내하는지 본다. 저장 뒤에는 `저장 후보 소모 완료 / 같은 클리어 재저장 불가`가 보여야 한다.
24. 저장 조합이 전부 비었을 때 빈 슬롯을 눌러도 `선택 완료`가 아니라 보충 런 안내가 유지되는지 본다.
25. 로비 저장 소모만으로 슬롯이 먼저 비었을 때도 `다음 확인:`이 `무한 기록 생성`보다 `보충 후 무한 재진입`을 우선 안내하는지 본다.
26. 저장 후보가 남아 있는 동안 흔적 4페이지의 무한모드 순서가 `후보 처리 후 시작`으로 보이고, 자동 비움 뒤에는 저장 조합 순서가 `보충 클리어 후 저장`으로 보이는지 본다.
27. 보충 런 클리어 뒤 하단 버튼이 `저장 없이 로비`로 읽히고, 저장하지 않고 나가면 `보충 런 저장 안 함`, `저장 조합은 갱신되지 않았습니다`, `기록:` 한 줄만 남으며 기록 버튼이 `보충 기록`으로 이어지는지 본다. 저장 후보/판정 상세가 다시 뜨면 안 된다.
28. 일반 클리어/실패/보충 런 결과 앞에 `결과` 같은 제목 줄이 붙어도 기록 버튼과 Enter가 각각 `클리어 복기`, `복기 기록`, `보충 기록`으로 가고, 보충 런 실패 재시작은 `보충 복기 재도전`으로 읽히는지 본다.

## 무한모드

1. 저장 조합으로 무한모드에 들어가면 조합 이름과 효과가 실제 선택/보상에 이어지는지 확인한다.
2. 무한모드 준비 화면과 저장 조합 상세에 에디터/디버그에서는 `입장 체크: 위협 폭·보상 / PgUp·PgDn`, 릴리스/모바일 정책에서는 `입장 체크: 위협 폭·보상 / 시작 전 확인`이 보이고, 짧은 준비 요약에는 `위협 체크`가 남는지 확인한다.
3. 기프트/유물 정비 완료 화면에서 좌는 기프트 다시, 중은 유물 다시, 우는 `현재 선택 유지`로 모두 터치 가능하고 우측을 눌렀을 때 현재 선택이 유지되는지 본다.
4. `PageUp` / `PageDown` 또는 오른쪽 버튼으로 위협 단계를 바꿔 상단 진행 바와 하단 가이드에 `위협 1/5 안정 폭좁음 정확+0`에서 `위협 5/5 최고 폭최대 정확+...`처럼 위험 폭과 보상 변화가 같이 보이는지 본다.
5. 상단 진행 막대 아래 5칸 위협 피프가 현재 위협 단계만큼 차고, 위협 단계가 바뀐 직후 현재 칸이 살짝 커지며 무한모드가 아닌 화면에는 남지 않는지 본다.
6. 위협 단계 전환 배너가 `무한 위협 n`뿐 아니라 `상승/압박/고압/최고`와 `폭 보통/확대/넓음/최대`까지 같이 보여주고, 진행 바 순간 알림도 `위협 상승 n` / `위협 하강 n`으로 읽히는지 본다.
7. 종료 후 무한 기록의 다음 목표가 위협 진입이면 `폭·보상 확인`까지 같이 붙어, 다음 무한 재도전에서 무엇을 읽어야 하는지 바로 보이는지 확인한다.
8. 종료 후 무한 기록에는 점수, 거리, 구간이 있는 기록 행과 그 행에 붙은 등급, 최고 위협, 콤보, 실수만 남고 코칭 문구나 `정답키`, `정답 좌 탭`, `터치 탭` 같은 조작 힌트가 섞이지 않는지 확인한다.
9. 무한 기록이나 일반 기록 줄에 `저장 조합 소모`, `사용 결과`, `남은 사용`, `다음 소모 후 슬롯 자동 비움` 같은 소모 알림이 기록값처럼 섞이지 않는지 확인한다.
10. `End 정산 종료`로 만든 무한 결과도 기록 보드에서는 `정산 종료 기록`, `실제 생존 흐름`, `실제 플레이` 안내가 빠지고 점수/콤보 같은 기록값만 남는지 확인한다.
11. `End 정산 종료` 직후 로비/흔적의 다음 행동은 복기 약점보다 `무한모드 실전 재개`를 우선 안내하는지 확인한다.
12. 단, End로 복기 목표를 달성한 경우에는 `목표 상향` 안내가 실전 재개보다 먼저 보이는지 확인한다.
13. `정산 종료 확인 후 무한모드 실전 재개` 결과에서는 무한 버튼이 `무한 실전 재개`로 읽히고, 준비 화면에는 `정산 종료 확인 완료` 안내만 짧게 보이며 연습 버튼/준비 화면에는 `무한 복기 재도전` 문맥이 섞이지 않는지 확인한다.
14. 실제 `무한 복기 재도전` 결과에서 무한 준비 화면으로 들어간 뒤 저장 조합 변경, 기프트/유물 정비를 거쳐도 `목표: 다음 구간...` 문맥이 시작 전까지 유지되는지 확인한다.

## 기록과 흔적

1. `무한 기록`은 기록만 깔끔하게 보여야 하며 조작 힌트, 저장 후보, 저장 관리 문구가 남으면 안 된다.
2. 기록 보드에서 레인은 좌 / 중 / 우 방향명만 남고, 현재 페이지명과 이전 / 다음 이동은 제목과 하단 버튼으로 분리되어 점수 행을 가리지 않는지 본다.
3. `흔적` 첫 페이지는 일반 / 저장 조합 / 무한 / 성장 / 중앙/레인 큐 / 자동 비움 / 복기 다음 행동을 짧게 보여야 한다.
4. `흔적` 장식 페이지는 점프 / 숙이기 / 비틀기 숙련을 보여주되 기록 보드를 더럽히면 안 된다.
5. 흔적의 `실행:`, 로비의 강조 버튼, Enter 기본 행동이 같은 다음 행동으로 이동하는지 본다.

## 빠른 회귀 순서

1. 로비에서 `흔적`을 열어 `체감 목표`, `검증 모드`, `진행`, `체크 n/7`, `루프 n/4`, `진행칸`, `바로 체크: 다음 확인 ... / 실행 ... / 목적 ...`, 에디터 `Enter/강조` 또는 모바일/릴리스 `강조 버튼`이 한 화면에 잡히고 진행 상태가 긴 한 줄이 아니라 작은 진행판처럼 나뉘어 보이는지 본다.
2. 흔적의 `검증 순서` 페이지에서 조작 체크가 긴 한 줄이 아니라 `체감 목표`, `동작 확인`, 에디터 `테스트키` / 모바일 `터치 레인`, 에디터 `Enter` / 모바일 `강조 버튼`, `GO`, `무한`, `저장` 줄로 나뉘어 읽히는지 본다.
3. `일반 런`으로 들어가 첫 활성 함정에서 레인 라벨, 중앙 액션 큐, 하단 상태줄이 모두 `위험→동작→박자→보상`을 같은 표기로 말하는지 본다.
4. `F4 핵 직후` 또는 `F5 탈출 직전`으로 클리어 흐름을 빠르게 만들고, `입구로 나가기` 뒤 `저장 슬롯 선택` 화면에서 `클리어 요약`, 기록 한 줄, 저장 후보, `저장 기회: 1회`가 먼저 보이며 슬롯을 골라야 저장이 풀리는지 확인한다.
5. 저장하지 않고 로비로 나갔을 때는 `클리어 복기`와 기록 보드만 남고, 저장 조합 슬롯은 비어 있는지 본다.
6. 다시 클리어해 저장 후보를 만들고 슬롯에 저장한 뒤, 저장 조합 화면에 `저장 후보 없음`과 `다음 클리어 후 1회`가 떠서 같은 클리어를 다시 저장할 수 없는지 본다.
7. 무한모드 준비에서 에디터/디버그 기준 `입장 체크: 위협 폭·보상 / PgUp·PgDn`, 릴리스/모바일 기준 `입장 체크: 위협 폭·보상 / 시작 전 확인`과 마지막 1회 `시작 후 자동 비움` 경고를 확인한다.
8. 저장 조합을 두 번 사용해 자동 비움이 된 뒤 로비, 저장 조합, 무한 준비 화면이 모두 `보충 런`, `무한 조합 보충`, `보충 안내`로 같은 동선을 가리키는지 본다.
9. 기록 보드 4페이지를 넘기며 저장 후보, 품질 비교, 테스트키, 액션 큐, 보정, 복기 약점 같은 안내가 빠지고 점수/거리/구간/콤보/실수만 남는지 본다.

## 이번 작업에서 새로 볼 것

- 주자가 작은 도깨비 소녀 실루엣처럼 읽히는지 본다. 뿔, 짙은 머리, 주홍 허리띠가 보이고 집중/판정 색이 들어와도 이 악센트가 완전히 사라지면 안 된다.
- 주자 파츠가 동작별로 작게 갈라지는지 본다. 점프는 머리/뿔이 위로 들리고, 숙이기는 머리와 허리띠가 낮고 넓어지며, 회전 통로는 허리띠와 머리 오프셋이 좌/우 방향을 짧게 가리켜야 한다.
- 로비/런 배경이 피라미드 내부 암부와 금색/청록 레일 조합으로 보이는지 본다. 완성 배경이 아니라 레인과 판정선을 해치지 않는 질감 확인이 목적이다.
- 활성 함정 색이 바닥은 흙빛-금색, 상단은 청록, 측면은 주홍 계열로 갈라져 모양을 보기 전에도 피할 동작이 어느 정도 구분되는지 본다.
- `흔적 저장 NEW`, `흔적 보충 NEW`, `흔적 성장 NEW`를 눌렀을 때 요약 페이지가 아니라 `저장/성장` 페이지가 바로 열리고, 아래 버튼이 `이전: 1/4 요약` / `다음: 3/4 장식` / `로비로`로 읽히는지 본다.
- 기록 보드와 흔적 보드에서는 주행 레인, 판정선, 주자 프리뷰, 기본 부제가 숨겨지고, 실제 기록값이나 흔적 본문과 아래 이동 버튼만 먼저 읽히는지 본다.
- 저장 조합 2회 소진 뒤 로비, 저장 조합, 무한 준비, 흔적 첫 페이지가 모두 남은 슬롯 또는 `보충 런` / `보충 안내` / `무한 조합 보충` 동선으로 즉시 갱신되는지 본다. S1이 자동 비워지고 S2가 남아 있으면 저장 조합 관리 화면도 빈 S1이나 보충 안내가 아니라 `> 슬롯 2`, `선택: 슬롯 2`로 읽혀야 한다.
- 일반 런/무한모드 활성 함정에서 바닥 박자 타일이 판정선 가까이 올수록 넓고 납작하고 밝게 눌려, 눌러야 할 순간이 바닥 접지선으로도 읽히는지.
- 일반 런/무한모드 활성 함정에서 터널 깊이감이 판정선 가까이 올수록 살짝 압축되고 밝아져, 배경도 “지금 눌러야 하는 순간” 쪽으로 조여오는지. 무한모드 고위협에서는 이 압박이 조금 더 강해야 한다.
- 타이밍 눈금은 정확권에서 가장 가까운 눈금이 더 밝고 세로로 또렷하게 lock되고, 뒤쪽 눈금은 약하게만 따라와 다음 박자와 실제 입력점이 구분되는지.
- 정답 목표 레인 glow가 다른 레인에는 뜨지 않고, 정확권에 가까워질수록 살짝 더 밝아지되 가로로만 퍼지지 않고 세로 lock이 더 크게 살아 중앙 액션 큐를 놓쳐도 눌러야 할 칸이 보이는지.
- 정답 목표 레인의 `좌 / 중 / 우` 라벨도 정확권과 박자 긴급도 상승 구간에서만 가로 확장보다 세로 lock이 더 크게 살아 글자만 봐도 지금 누를 칸이 읽히는지.
- 성공권 밴드가 정확 타이밍에만 더 밝고 세로 lock이 가로 확장보다 크게 살아 Good권보다 좁고 확실한 `정확권`으로 읽히는지.
- 중앙 정확선도 정확권에서 더 밝고 세로 lock이 가로 확장보다 크게 살아 목표 레인 glow / 성공권 밴드 / 마커 기호와 같은 타이밍을 가리키는지.
- 판정선 자체도 정확권에서 살짝 더 밝고 세로 lock이 가로 확장보다 크게 살아, 함정이 닿는 선과 입력 타이밍이 같은 기준선으로 읽히는지.
- 하단 타이밍 가이드 문구도 정확권에서 살짝 더 밝고 세로 lock이 가로 확장보다 크게 살아, 텍스트를 보고도 지금 누르는 순간이 읽히는지.
- 함정 마커가 판정선 근처에서 바닥 위험은 낮고 넓게, 상단 위험은 세로 압박으로, 측면 위험은 더 길고 기울어진 공격으로 반응해 점프/숙이기/비틀기 차이가 중앙 마커만 봐도 갈라지는지.
- 마커 안쪽 `↑` / `↓` / `↔` 기호가 정확권에서 더 밝아지고 세로 lock을 받아, 모양과 기호가 같은 회피 행동과 입력 타이밍을 함께 가리키는지.
- 접촉 예고선이 점프는 낮은 바닥선, 숙이기는 위쪽 압박선, 비틀기/회전은 세로 측면선으로 짧게 켜져 함정이 닿는 자리를 텍스트 없이 읽게 하는지.
- 경고 레일 2개가 접촉 예고선 주변에 낮게 켜지고, 점프는 바닥 가로 레일, 숙이기는 위쪽 하강 가로 레일, 비틀기/회전은 옆 세로 기울기 레일로 보여 함정이 닿을 방향을 한 박자 먼저 읽게 하는지.
- 에디터 F10 낙하 보기로 `낙하 보통` / `낙하 느림` / `낙하 빠름`이 순환하고, 함정과 예고 피프가 더 늦게/빠르게 내려와도 실제 정확권 판정선 위치는 그대로 읽히는지.
- 함정 압박 그림자가 함정과 주자 사이에 낮은 알파로 깔리고, 점프는 낮고 넓게, 숙이기는 세로로 내려누르듯, 비틀기/회전은 옆으로 기울어진 세로 압박으로 갈라져 함정이 조여오는 방향을 읽게 하는지.
- 함정이 정확권에 가까워질수록 직선 통로 레일 / 고리 / 중앙 이음선 / 페이스 마커가 아주 살짝 두꺼워지고 밝아져, 길 자체가 판정선 쪽으로 조여오는 느낌이 생기는지. 일시정지/선택/결과 화면에서는 이 스퀴즈가 남지 않아야 한다.
- 주자 대응 준비선과 준비 기호가 입력 직전에만 낮은 알파로 켜지고, 점프 발밑 발사선+위쪽 기호 / 숙이기 낮은 수평선+낮은 기호 / 비틀기·회전 몸 옆 세로선+옆쪽 기호로 갈라져 실제 피할 동작을 미리 읽게 하는지.
- 주자 그림자가 보폭 접지와 정확 타이밍 근처에서 살짝 넓고 어둡게 눌리고, 몸도 아주 작게 squash되어 리듬 입력이 발밑 감각으로 이어지는지. 일시정지/선택/결과 화면에는 접지 펄스가 남지 않아야 한다.
- 주자 발밑 접지 피프가 왼발/오른발 보폭에 맞춰 낮게 번갈아 켜지고, 정확권 다운비트와 접지 순간에만 조금 더 밝아져 직선 주행 리듬이 발밑에서도 읽히는지.
- 함정 접근 잔상이 판정선에 가까울수록, 무한모드 위협이 높을수록 더 커지고 밝아져 점프/숙이기/비틀기 궤도와 내려오는 압박을 추상 그래픽에서도 읽을 수 있는지.

- 회전 입력 판정 직후 같은 하단 피프가 Success는 밝게, Good은 약하게, Miss는 붉게 짧은 잔광으로 남았다가 바로 사라지는지.
- 정확 입력을 이어갈 때 콤보 배지 하단 정박 보상칸이 1칸씩 차고 배지/성공 플래시가 보상 직전 느낌을 살리며, 선택/일시정지/카운트다운/종료 화면에서는 보이지 않는지.
- 판정 직후 해당 레인에 `정확` / `Good` / `Miss` 태그가 짧게 뜨고, 오입력은 누른 레인 `Miss`와 정답 레인 `정답`으로 갈라지는지.
- 판정선 입력 흔적에 `정확`, `빠름 Nms`, `늦음 Nms`, `오입력` 라벨이 함께 뜨고, 빠름/늦음 흔적의 위아래 위치와 기울기가 달라 타이밍 복기가 즉시 되는지.
- Miss 직후 판정선 위에 붉은 끊김 라인이 짧게 뜨고, 연쇄를 끊은 Miss는 조금 더 넓고 두껍게 흔들리는지 본다. 레인 판정 태그/레인 판정 펄스/Miss 흔들림/입력 흔적/화면 판정 플래시/마커 흔들림/포커스 오라 밴드/판정 히스토리 잔상/끊김 라인/커진 판정선 펄스가 선택/일시정지/카운트다운/결과 화면에는 남지 않는지.
- 일시정지 / 선택 / 결과 화면으로 넘어가면 전환 배너와 전환선이 바로 숨고, 카운트다운이나 실제 플레이 구간에서는 필요한 구간 안내가 유지되는지.
- 무한모드 위협 5칸 피프는 실제 진행 중에만 보이고, 일시정지 / 선택 / 카운트다운 / 결과 화면에서는 숨겨 기록 요약을 방해하지 않는지.
- 일반 런 상단 경로 박자 3칸 지도는 실제 진행 중에만 보이고, 현재 칸은 판정 창에 가까워질수록 조금 더 밝고 크게 뛰며 일시정지 / 선택 / 카운트다운 / 결과 화면에서는 숨는지.
- 활성 함정 마커 안의 `↑` / `↓` / `↔` 기호가 함정 형태와 같은 회피 동작을 가리키고, 비활성/일시정지/선택 화면에서는 남지 않는지.
