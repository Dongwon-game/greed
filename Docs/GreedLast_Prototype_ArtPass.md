# Greed Last 1차 프로토타입 그래픽 패스

## 2026-10-29 캐릭터 방향 변경

사용자는 기존 이미지의 그림체만 유지하고 캐릭터는 고대 이집트풍 인간으로 바꾸기로 했다. 뿔/초록 피부/동양풍 도깨비 복식은 새 방향이 아니다. [인간 주자 시안과 생성 기록](ArtDrafts/EgyptianRunnerActions-v1.md) 및 [독립 포즈/입구 적용 기록](ArtDrafts/EgyptianRunnerIntegration-v1.md)을 우선한다. 승인 뒤 새 자원을 소스에 연결하고 검증 중이며 실행본 식별은 빠른 확인 문서의 최신 기록을 따른다. 아래 도깨비 관련 설명은 이전 패스의 이력으로 보존한다.

## 목적

이 패스는 정식 원화를 완성하려는 작업이 아니다. 첫 화면에서 아래 방향을 바로 설명하고, 실제 플레이에서는 기존 동적 판정판을 방해하지 않는 것이 목적이다.

- 템플런처럼 정면으로 길게 달리는 피라미드 통로
- 좌·중·우 세 레인과 실제 함정의 존재
- 연녹색 피부, 뿔, 짙은 머리, 주홍 허리띠로 읽히는 도깨비 소녀
- 놈처럼 제한된 회전 구간을 폰 기울임으로 넘는 모바일 조작
- 함정을 피하는 생존과 정확 타이밍 보상이 함께 있는 리듬 탈출

## 2026-10-03 밤 - 포함 한글 글꼴과 실행 자원

- 실제 글꼴 높이에 맞춰 행동 132·기본 판정 124·시작/재개 숫자 160의 고정 영역을 확보했다. 타이밍 안내 폭/간격, 진행 글자와 막대, 게이지 숫자를 분리했다. 작은 가로와 태블릿에서 글리프 잘림·실제 글자 간 겹침·큰 GO의 게이지 가림을 대조한다. 입력 영역과 판정/보상/카운트 길이는 그대로다.
- 앱/Canvas 중복 생성, UI/호스트 비활성화 중 주행, 중단된 부팅 복귀를 보완했다. 앱 컴포넌트만 종료해도 자신이 만든 화면/소리 자원을 정리하고 호스트의 외부 소스/클립/볼륨과 카메라/입력 시스템은 보존한다. 외부 키보드 탐색 설정도 원래 상태로 복원한다.
- 씬 소유 카메라/입력 시스템을 빌린 상태에서 씬을 다시 불러오면 입력이 없어지는 문제를 실제 재생에서 재현했다. 영속 화면은 유지하고 빠진 자원만 복구하며 정지 중 반복 재로드에서도 주행 수치와 하나의 실행 자원을 유지한다. 화면 종료 시 콜백도 해제한다.
- 실제 엔진 전체 검사 `prototype-engine-scene-recovery-integrated-20261003.log` **23:31 KST**는 일반/빠른 재생 두 사이클과 씬 복구·오디오 소유권·외부 설정 복원, 일반 8선택/15함정→S2 저장 1회→준비 취소→무한 두 번 시작·자연 실패→자동 비움·기록·보충을 통과했다. 각 마우스 24/터치 37회이며 개인 진행도/설정과 재생 설정은 보존한다. 실제 휴대폰 센서/소리 지연/FPS 확인은 별도다.
- 최종 통합 화면/빌드 식별은 [빠른 확인](GreedLast_Prototype_QuickCheck.md)의 최신 검증을 따른다. 글꼴 배치 실패/수정과 앞선 검사의 포함 범위는 [확인 이력](GreedLast_Prototype_CheckHistory.md)에 분리해 보존한다.

## 교체 규칙

정식 또는 다음 시안으로 교체할 때 파일 이름과 런타임 키를 유지하면 코드 변경 없이 바꿀 수 있다. 다음 조건은 유지한다.

1. 가로 16:9에 가까운 비율을 사용한다.
2. 정면 통로와 소실점을 중앙에 둔다.
3. 중요한 캐릭터와 입구 형태를 화면 안전 여백 안에 둔다.
4. 중앙 하단은 버튼과 레인 UI를 읽을 수 있게 복잡도를 낮춘다.
5. 정적 배경에 판정선, 점수, 버튼 같은 UI를 직접 그리지 않는다.
6. 실제 런 화면에는 이 배경을 재사용하지 않는다.

러너 시안을 교체할 때도 파일 이름과 런타임 키를 유지한다. 아래 조건을 지킨다.

1. 투명 배경의 세로 2:3 전신 이미지를 사용한다.
2. 뒤 또는 뒤쪽 3/4 시점으로 달리는 방향이 정면 통로와 맞아야 한다.

4. 머리끝, 발끝, 휘날리는 장식이 이미지 밖으로 잘리지 않게 안전 여백을 둔다.
5. 바닥 그림자, UI, 글자, 판정선은 이미지에 직접 그리지 않는다.

함정 아틀라스를 교체할 때는 정확히 같은 3:1 구조를 유지한다.

1. 왼쪽 1/3은 점프할 바닥 함정, 가운데 1/3은 숙일 상단 함정, 오른쪽 1/3은 비틀 측면 함정으로 둔다.
2. 각 셀은 정사각형이며 물체가 이웃 셀로 넘어가지 않게 한다.
3. 각 물체 바깥은 완전 투명으로 두고 글자와 동작 기호를 넣지 않는다.
4. 작은 화면에서도 세 실루엣의 높이와 방향이 서로 다르게 읽혀야 한다.

주행 통로를 교체할 때도 파일 이름과 런타임 키를 유지한다.

1. 16:9에 가까운 불투명 가로 이미지를 사용한다.
2. 세 레인과 소실점을 화면 중앙에 맞추고 직선 주행 방향을 유지한다.
3. 중앙 하단은 러너와 판정선을 위해 대비와 장식을 낮춘다.
4. 캐릭터, 활성 함정, UI, 글자를 배경에 직접 넣지 않는다.

## 반복 화면 검사

2026-09-09 화면 정리: 주행 중 긴 소개 문구를 숨기고 전환 배너를 입력 레인 위쪽으로 옮겼다. 동작 안내는 주자 아래 빈 영역에 표시하며, 판정 피드백이 나오는 동안에는 안내를 숨겨 겹침을 막는다. 선택 화면에서도 가운데에 반복하던 설명을 숨기며 실제 좌·중·우 선택지 이름과 효과, 아래 상태·추천은 유지한다. 결과 요약은 계속 표시한다.

일시정지에서는 공유 버튼들을 고정 메뉴판의 자식으로 배치한다. 가로 화면 너비에 따라 소리·보정 버튼이 메뉴 밖으로 벌어지던 문제와 `시야 안정` 버튼이 어두운 배경 뒤에 가리던 문제를 수정했다. 재개 숫자는 메뉴 제목에 나타나고 재개 준비 버튼은 카운트 중 비활성화된다. 재개 뒤에는 버튼들이 게임 루트로 돌아가며 숨겨진 메뉴에 남지 않는다.

Unity 재생을 멈춘 뒤 `Greed Last > Capture Prototype Visual Checks`를 실행하면 `Logs/VisualChecks`에 35개 시나리오 PNG가 생성된다. 타이틀부터 일반 런 클리어, S3 저장, 무한 정비 3단계, 마지막 사용과 자동 비움, 기록 4페이지, 덮어쓰기 비교와 포인터 드래그, 연습 결과 보정, 재시작까지 포함한다. 1280×720, 1920×1080, 2340×1080 및 좌우 96픽셀 안전 여백, 1024×768 태블릿을 비교한다. 폴더에는 이전 실행의 파일이 남을 수 있으므로 `latest-report.json`의 실행 시간, 성공 여부, 파일 목록으로 이번 실행을 구분한다.
