# Greed Last 1차 프로토타입 그래픽 패스

## 목적

이 패스는 정식 원화를 완성하려는 작업이 아니다. 첫 화면에서 아래 방향을 바로 설명하고, 실제 플레이에서는 기존 동적 판정판을 방해하지 않는 것이 목적이다.

- 템플런처럼 정면으로 길게 달리는 피라미드 통로
- 좌·중·우 세 레인과 실제 함정의 존재
- 연녹색 피부, 뿔, 짙은 머리, 주홍 허리띠로 읽히는 도깨비 소녀
- 놈처럼 제한된 회전 구간을 폰 기울임으로 넘는 모바일 조작
- 함정을 피하는 생존과 정확 타이밍 보상이 함께 있는 리듬 탈출

## 2026-09-19 타이밍 안내 보호

- 추가 마무리: 코어/UI 연결 검사에서 반복 정지·재개·GO, 선택, 새 런, 무한 결과, 로비·저장·기록의 효과 숨김/복원을 확인했다. 비대칭 노치/상하 여백 6장면을 더해 총 88장과 버튼 안전 영역 663회, 효과 여백 96곳을 통과했다.
- 화면 보고서의 `safeInsets`는 픽셀 단위 좌/하/우/상(`x/y/z/w`)이며, 이전 `safeInset` 필드는 대칭 좌우 여백용으로 보존한다. 캡처 시작부터 안전 영역을 적용해 애니메이션도 같은 영역에서 계산한다.
- 성공한 검증 빌드는 `VerifiedBuildInfo.json`을 남긴다. 재사용되는 Unity 실행기와 실제 `Assembly-CSharp.dll`을 각각 해시하고 완료 시각을 기록한다. 이는 두 파일의 식별 기록이며 전체 자산 해시나 실제 기기 실행 검증을 뜻하지 않는다.
- 판정 직전 움츠림 자세에서 발자국 2개와 점프 준비 표시가 타이밍 안내 글자에 겹치는 것을 실제 화면 좌표로 확인했다.
- 자세·회전·텍스트 강조를 계산한 뒤 효과만 안내 위로 필요한 만큼 올린다. 텍스트·판정선·입력 칸은 이동하지 않는다. 반복 실행은 누적 이동을 만들지 않고, 숨긴/투명한/빈 글자에는 제한하지 않는다.
- 공통 좌표계에서 회전된 네 모서리를 계산하며 배열을 재사용한다. 기본 동작 효과의 크기·회전·가로 방향은 유지한다.
- 회귀 검사가 수정 전 실패하고 수정 후 통과하는 것을 확인했다. 회전·확대 54조합, 반복 10회, 숨김 조건을 전체 스모크에 추가했다.
- 전체 스모크·Windows 빌드: `Logs/prototype-hud-clearance-verified-20260919.log`. 집중·저체력·공명핵·무한 위협 5가 겹치는 8장면을 추가해 화면 82장을 통과했다. `checkedRunnerCueClearances`가 효과/글자 여백 검사 수다.
- 직접 확인은 빠른 확인 문서의 9월 19일 항목을 따른다. 판정과 저장 규칙은 변경하지 않았다.

## 2026-09-18 박자 강조 시계 통합

- 배경/주자 동작의 `beatPhase`는 유지하고, 게임 박자 강조는 `PlayRhythmPulse` 이벤트 시각과 실제 박자 간격을 사용한다. 일반 0.5초, 무한 위협에 따라 0.5~0.36초다.
- 이벤트 당 한 번 정점에 도달한 뒤 0.18초 이내로 잦아들며, 새 이벤트 없이 반복 발광하지 않는다. 소리 0에서도 표시를 유지한다.
- 타이밍·판정선·체력·집중·핵·탈출 진행의 박자 강조를 같은 기준으로 연결했다. 예약 처리를 화면 강조 갱신 앞으로 옮겼다. 배경 이동, 달리기 보폭, 노트 시간과 점수는 바꾸지 않았다.
- 정지·새 런·로비 전환에서 이전 박자 강조와 강박 표시를 비운다. 재개와 GO의 기존 이벤트 순서 및 중복 방지를 유지한다.
- 전체 스모크·Windows 빌드: `Logs/prototype-beat-final-verified-20260918.log`. 무한 위협 5단계를 실제 코어로 진입하고 이벤트 정점·다음 예약 간격·늦은 프레임 중복 방지를 검사했다.
- 화면 검사에 판정 직전의 강조 전/후, 무음 와이드, 재개 태블릿, 위협 5 접근 장면을 추가했다. 준비 단계가 실패한 경우에도 실패 보고서를 남겨 이전 성공 결과로 오인하지 않게 했다.
- 자동 검증은 소프트웨어 이벤트 시점 기준이다. 장치 출력 지연·실제 청취·휴대폰 진동·메모리 프로파일링은 별도 확인한다. 직접 확인 순서는 빠른 확인 문서의 9월 18일 항목을 따른다.

## 2026-09-16 소리 및 재개 안정화

- 추가: UI가 생성한 30개 효과음만 소유권 목록에 보관하고 OnDestroy에서 해제한다. 외부 연결 음원은 삭제하지 않으며 OnDisable에서는 음원을 유지한다. 편집 모드 검사/캡처도 명시적으로 정리한다. 3회 정리로 90개 해제, 외부 음원 보존과 중복 호출을 검사했다. 최신 회귀·빌드 로그는 `Logs/prototype-audio-ownership-verified-20260916.log`다. 실제 기기 메모리 측정은 별도다.
- 런타임은 지연 Destroy, 편집 모드는 DestroyImmediate를 사용한다. [Unity 오브젝트 해제 문서](https://docs.unity3d.com/ja/6000.0/ScriptReference/Object.DestroyImmediate.html)의 구분을 따른다.
- 효과별 음량은 유지하고 공통 음량은 AudioSource에서 한 번만 적용한다. 설정 변경은 이미 재생 중인 소리에도 적용되며 0에서는 기존 소리를 멈추고 새 소리를 예약하지 않는다.
- 포커스 상실·앱 중단·컴포넌트 비활성화 중에는 소리와 진동을 차단한다. 복귀 이벤트 순서가 바뀌어도 포커스와 앱 재개가 모두 복구되기 전에는 열리지 않는다.
- 일시정지 진입과 재개 중단에서 이전 박자 예약을 비운다. 로비나 새 런에서도 이전 카운트 상태를 비운다. 두 화면 사이에 Update가 없어도 새 카운트의 첫 박자가 나와야 한다.
- GO는 한 번만 발생하며 로비에서는 지나간 주행 박자를 재생하지 않는다. 메뉴 미리듣기는 수동 일시정지 중 사용할 수 있다. 소리 0은 진동 OFF를 뜻하지 않는다.
- `GreedLastPrototypeAudioCheck`는 편집 모드의 임시 UI와 임시 런을 사용하며 사용자 음량/진동/진행도를 저장하거나 초기화하지 않는다.
- 최종 회귀·Windows 빌드: `Logs/prototype-audio-app-verified-20260916.log`. 첫 출발 중 가상 1시간 백그라운드에서도 준비 시간·거리·함정이 유지되고 GO가 한 번만 발생하는지 검사했다. 실제 앱 재개 버튼과 스냅샷 연결에서도 양쪽 콜백 순서·첫 박자·GO 1회·저장 슬롯 보존을 확인했다.
- 화면 68장·입력/스크롤 회귀: `Logs/prototype-audio-visual-20260916.log`. 작은 정지 메뉴와 태블릿 재개 화면도 이미지로 확인했다. 실제 기기 음향·진동 체감 검사는 별도이며 순서는 `GreedLast_Prototype_QuickCheck.md`의 9월 16일 항목을 따른다.

## 교체 규칙

정식 또는 다음 시안으로 교체할 때 파일 이름과 런타임 키를 유지하면 코드 변경 없이 바꿀 수 있다. 다음 조건은 유지한다.

1. 가로 16:9에 가까운 비율을 사용한다.
2. 정면 통로와 소실점을 중앙에 둔다.
3. 중요한 캐릭터와 입구 형태를 화면 안전 여백 안에 둔다.
4. 중앙 하단은 버튼과 레인 UI를 읽을 수 있게 복잡도를 낮춘다.
5. 정적 배경에 판정선, 점수, 버튼 같은 UI를 직접 그리지 않는다.
6. 실제 런 화면에는 이 배경을 재사용하지 않는다.

러너 시안을 교체할 때도 파일 이름과 런타임 키를 유지한다. 아래 조건을 지킨다.

1. 투명 배경의 세로 2:3 전신 이미지를 사용한다.
2. 뒤 또는 뒤쪽 3/4 시점으로 달리는 방향이 정면 통로와 맞아야 한다.
3. 탁한 연녹색 피부, 뿔, 짙은 머리, 주홍 허리띠처럼 작은 크기에서도 읽히는 특징을 유지한다.
4. 머리끝, 발끝, 휘날리는 장식이 이미지 밖으로 잘리지 않게 안전 여백을 둔다.
5. 바닥 그림자, UI, 글자, 판정선은 이미지에 직접 그리지 않는다.

함정 아틀라스를 교체할 때는 정확히 같은 3:1 구조를 유지한다.

1. 왼쪽 1/3은 점프할 바닥 함정, 가운데 1/3은 숙일 상단 함정, 오른쪽 1/3은 비틀 측면 함정으로 둔다.
2. 각 셀은 정사각형이며 물체가 이웃 셀로 넘어가지 않게 한다.
3. 각 물체 바깥은 완전 투명으로 두고 글자와 동작 기호를 넣지 않는다.
4. 작은 화면에서도 세 실루엣의 높이와 방향이 서로 다르게 읽혀야 한다.

주행 통로를 교체할 때도 파일 이름과 런타임 키를 유지한다.

1. 16:9에 가까운 불투명 가로 이미지를 사용한다.
2. 세 레인과 소실점을 화면 중앙에 맞추고 직선 주행 방향을 유지한다.
3. 중앙 하단은 러너와 판정선을 위해 대비와 장식을 낮춘다.
4. 캐릭터, 활성 함정, UI, 글자를 배경에 직접 넣지 않는다.
