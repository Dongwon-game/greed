# Greed Last 1차 프로토타입 그래픽 패스

## 목적

이 패스는 정식 원화를 완성하려는 작업이 아니다. 첫 화면에서 아래 방향을 바로 설명하고, 실제 플레이에서는 기존 동적 판정판을 방해하지 않는 것이 목적이다.

- 템플런처럼 정면으로 길게 달리는 피라미드 통로
- 좌·중·우 세 레인과 실제 함정의 존재
- 연녹색 피부, 뿔, 짙은 머리, 주홍 허리띠로 읽히는 도깨비 소녀
- 놈처럼 제한된 회전 구간을 폰 기울임으로 넘는 모바일 조작
- 함정을 피하는 생존과 정확 타이밍 보상이 함께 있는 리듬 탈출

## 현재 리소스

### 입구 시안

- Unity 경로: `Assets/Resources/GreedLast/PrototypeEntrance.png`
- 런타임 키: `GreedLast/PrototypeEntrance`
- 원본 비율: 16:9 가로
- 사용 화면: 타이틀. 연결과 입구 로비는 아래의 인물 없는 로비 시안으로 전환한다.
- 숨김 화면: 일반 런, 무한모드, 저장 조합, 성장, 기록, 흔적
- 임포트 기준: 최대 2048, 비율 보존, 밉맵 끔, 읽기 불가, 가장자리 Clamp

타이틀에서 가장 선명하고 연결 화면과 로비로 갈수록 낮아진다.

### 인물 없는 입구 로비

- Unity 경로: `Assets/Resources/GreedLast/PrototypeLobby.png`
- 런타임 키: `GreedLast/PrototypeLobby`
- 원본 비율: 16:9 가로, 불투명 배경
- 사용 화면: 연결, 연결 차단, 재동기화, 입구 로비
- 생성 방식: 내장 이미지 생성 도구로 입구 원본의 하단 캐릭터와 그림자만 제거했다. 통로 구도, 석재, 황동 장치, 횃불, 조명은 유지했다.

입구 원본은 삭제하거나 덮어쓰지 않았다. 로비는 인물이 없는 배경 앞에 실제 움직이는 주자 한 명만 남겨 중복 캐릭터를 없앴다. 로비와 연결 화면에서는 좌·중·우 레인 글자, 입력판과 판정선을 숨긴다. 런 진입 때 입력판과 판정선이 다시 나타나며, 캐릭터 그림이 있으면 이전 노란 사각형 박자 마커는 표시하지 않는다.

### 도깨비 소녀 러너 시안

- Unity 경로: `Assets/Resources/GreedLast/PrototypeRunner.png`
- 런타임 키: `GreedLast/PrototypeRunner`
- 원본 비율: 2:3 세로, 투명 배경
- 사용 화면: 입구 로비의 작은 주자, 일반 런과 무한모드의 플레이 주자
- 임포트 기준: 최대 1024, 비율 보존, 밉맵 끔, 읽기 불가, 가장자리 Clamp, 알파 투명도 처리

러너는 뒤쪽 3/4 시점의 전신 도깨비 소녀 그림을 본체로 사용한다. 기존 뿔, 머리, 허리띠, 팔다리 도형은 삭제하지 않고 낮은 알파의 동작 강조선과 리소스 누락 시 폴백으로 남긴다. 그래서 점프, 숙이기, 비틀기, 실패 흔들림, 출발 웅크리기 같은 기존 루트가 같은 루트 오브젝트를 따라간다. `시야 안정 ON`에서는 실패 흔들림도 함께 줄어든다.

### 세 동작 함정 아틀라스

- Unity 경로: `Assets/Resources/GreedLast/PrototypeTraps.png`
- 런타임 키: `GreedLast/PrototypeTraps`
- 원본 비율: 3:1 가로, 1:1 셀 3개, 투명 배경
- 셀 순서: 바닥 가시 / 상단 칼날문 / 측면 회전날
- 사용 화면: 일반 런과 무한모드의 활성 함정
- 임포트 기준: 최대 2048, 비율 보존, 밉맵 끔, 읽기 불가, 가장자리 Clamp, 알파 투명도 처리

현재 함정의 회피 동작에 따라 아틀라스의 1/3 영역을 골라 보여준다. 측면 회전날은 우측 레인에서 좌우 반전되어 방향 차이가 읽힌다. 기존 붉은 마커는 낮은 알파의 받침으로 남고 `↑ / ↓ / ↔` 기호, 접근 잔상, 판정선, 정확권은 그림 위에서 그대로 움직인다.

### 직선 주행 통로 시안

- Unity 경로: `Assets/Resources/GreedLast/PrototypeRunCorridor.png`
- 런타임 키: `GreedLast/PrototypeRunCorridor`
- 원본 비율: 16:9 가로, 불투명 배경
- 사용 화면: 일반 런과 무한모드의 선택 / 카운트다운 / 주행 / 일시정지 / 결과
- 임포트 기준: 최대 2048, 비율 보존, 밉맵 끔, 읽기 불가, 가장자리 Clamp

입구 시안과 같은 청록 석재, 황동, 아이보리 바닥, 주홍 천 포인트를 사용하되 캐릭터와 함정은 그리지 않았다. 세 바닥 레인과 중앙 소실점만 남겨 동적 주자, 함정 아틀라스, 판정선이 앞에서 읽힌다. 활성 주행에서는 가장 선명하고 선택 / 카운트다운에서는 한 단계 약해지며, 일시정지 / 결과에서는 더 뒤로 물러난다. 전진 중에는 작은 박자 확대와 상하 이동만 주고, 회전 통로에서는 배경 통로만 1.6도 안쪽으로 기울인다. 챕터, 탈출, 무한, 집중, 체력 위기, 함정 준비 상태의 분위기 색은 최대 28%만 섞는다. `시야 안정 ON`은 확대 이동과 기울기를 함께 낮춘다.

## 생성 기준

내장 이미지 생성 도구로 만든 임시 시안이며 아래 기준을 사용했다.

- 정면 소실점과 길게 이어진 직선 통로
- 중앙 하단 UI와 레인 표시를 위한 비교적 낮은 대비 공간
- 청록 석재, 낡은 금색, 주홍 함정 강조의 다색 팔레트
- 뒤 또는 반측면에서 보이는 작은 도깨비 소녀 주자
- 글자, 로고, UI, 워터마크, 현대 물건, 추가 인물 제외
- 과도한 어둠, 안개, 모션 블러 제외
- 특정 작가나 기존 게임의 화풍 복제 제외

## 교체 규칙

정식 또는 다음 시안으로 교체할 때 파일 이름과 런타임 키를 유지하면 코드 변경 없이 바꿀 수 있다. 다음 조건은 유지한다.

1. 가로 16:9에 가까운 비율을 사용한다.
2. 정면 통로와 소실점을 중앙에 둔다.
3. 중요한 캐릭터와 입구 형태를 화면 안전 여백 안에 둔다.
4. 중앙 하단은 버튼과 레인 UI를 읽을 수 있게 복잡도를 낮춘다.
5. 정적 배경에 판정선, 점수, 버튼 같은 UI를 직접 그리지 않는다.
6. 실제 런 화면에는 이 배경을 재사용하지 않는다.

러너 시안을 교체할 때도 파일 이름과 런타임 키를 유지한다. 아래 조건을 지킨다.

1. 투명 배경의 세로 2:3 전신 이미지를 사용한다.
2. 뒤 또는 뒤쪽 3/4 시점으로 달리는 방향이 정면 통로와 맞아야 한다.
3. 탁한 연녹색 피부, 뿔, 짙은 머리, 주홍 허리띠처럼 작은 크기에서도 읽히는 특징을 유지한다.
4. 머리끝, 발끝, 휘날리는 장식이 이미지 밖으로 잘리지 않게 안전 여백을 둔다.
5. 바닥 그림자, UI, 글자, 판정선은 이미지에 직접 그리지 않는다.

함정 아틀라스를 교체할 때는 정확히 같은 3:1 구조를 유지한다.

1. 왼쪽 1/3은 점프할 바닥 함정, 가운데 1/3은 숙일 상단 함정, 오른쪽 1/3은 비틀 측면 함정으로 둔다.
2. 각 셀은 정사각형이며 물체가 이웃 셀로 넘어가지 않게 한다.
3. 각 물체 바깥은 완전 투명으로 두고 글자와 동작 기호를 넣지 않는다.
4. 작은 화면에서도 세 실루엣의 높이와 방향이 서로 다르게 읽혀야 한다.

주행 통로를 교체할 때도 파일 이름과 런타임 키를 유지한다.

1. 16:9에 가까운 불투명 가로 이미지를 사용한다.
2. 세 레인과 소실점을 화면 중앙에 맞추고 직선 주행 방향을 유지한다.
3. 중앙 하단은 러너와 판정선을 위해 대비와 장식을 낮춘다.
4. 캐릭터, 활성 함정, UI, 글자를 배경에 직접 넣지 않는다.

## 직접 확인

1. 현재 진행도를 유지한 채 Play한다. 타이틀부터 다시 볼 때만 진행도 초기화 메뉴를 사용한다.
2. 타이틀에서 통로와 도깨비 소녀가 먼저 읽히는지 본다.
3. 연결 화면에서 배경이 한 단계 약해지는지 본다.
4. 로비에서 버튼과 문틀보다 배경이 뒤로 물러나는지 본다.
5. 일반 런을 시작하면 입구 배경은 완전히 사라지고 캐릭터 없는 직선 주행 통로 배경으로 자연스럽게 바뀌는지 본다.
6. 16:9와 더 넓은 가로 Game 뷰에서 화면 가장자리가 비지 않는지 본다.
7. 로비의 작은 주자와 런의 주자가 같은 도깨비 소녀로 이어지는지 본다.
8. 점프, 숙이기, 비틀기 때 그림 전체가 기존 주자 동작을 따라가고 검은 사각형이나 배경 테두리가 보이지 않는지 본다.
9. `시야 안정 ON/OFF`에서 Miss 흔들림 강도만 달라지고 판정 결과는 같게 유지되는지 본다.
10. 바닥 / 상단 / 측면 함정이 각각 가시 / 칼날문 / 측면 회전날로 바뀌고 `↑ / ↓ / ↔` 기호가 그림 위에서 읽히는지 본다.
11. 선택 / 카운트다운 / 주행 / 일시정지 순서로 통로의 선명도가 달라지고, 회전 구간에서는 통로만 작게 기울며 HUD와 판정선은 고정되는지 본다.
12. 에디터에서는 `F11`로 테스트 버튼과 주행 중 설정 버튼을 숨기고 그래픽을 확인한다. `F1` 무적과 `F9` 동작 확인은 유지되며, `ESC` 메뉴를 열면 소리·보정 설정이 다시 보인다. 재개 후에는 다시 숨고 `F11`을 한 번 더 누르면 복원되어야 한다. 일반 실행 빌드에서는 클린 뷰가 기본이다.

## 반복 화면 검사

2026-09-09 화면 정리: 주행 중 긴 소개 문구를 숨기고 전환 배너를 입력 레인 위쪽으로 옮겼다. 동작 안내는 주자 아래 빈 영역에 표시하며, 판정 피드백이 나오는 동안에는 안내를 숨겨 겹침을 막는다. 선택 화면에서도 가운데에 반복하던 설명을 숨기며 실제 좌·중·우 선택지 이름과 효과, 아래 상태·추천은 유지한다. 결과 요약은 계속 표시한다.

일시정지에서는 공유 버튼들을 고정 메뉴판의 자식으로 배치한다. 가로 화면 너비에 따라 소리·보정 버튼이 메뉴 밖으로 벌어지던 문제와 `시야 안정` 버튼이 어두운 배경 뒤에 가리던 문제를 수정했다. 재개 숫자는 메뉴 제목에 나타나고 재개 준비 버튼은 카운트 중 비활성화된다. 재개 뒤에는 버튼들이 게임 루트로 돌아가며 숨겨진 메뉴에 남지 않는다.

Unity 재생을 멈춘 뒤 `Greed Last > Capture Prototype Visual Checks`를 실행하면 `Logs/VisualChecks`에 9개 PNG가 생성된다. 타이틀, 로비, 시작 선택, 주행, 일시정지, 재개를 1280×720 기준으로 촬영하고 로비 1920×1080, 주행·일시정지 2340×1080 및 좌우 96픽셀 안전 여백을 추가 확인한다.

이 검사는 현재 씬과 저장 프로필을 수정하지 않는 임시 UI·코어를 사용한다. 실제 모바일 터치, 센서, 오디오 지연 검사나 사용자 전체 플레이를 대신하지 않는다. 카메라가 [Unity의 미리보기 씬](https://docs.unity3d.com/2021.3/Documentation/ScriptReference/SceneManagement.EditorSceneManager.NewPreviewScene.html)만 렌더링하므로 다른 프로그램이 앞을 가려도 화면을 비교할 수 있다.

로비 배경 편집 프롬프트: `Remove only the foreground girl and her cast shadow; reconstruct the stone threshold beneath her. Preserve the full 16:9 composition, central perspective, gate, mechanisms, torches, banners, colors and illustrated brushwork. No people, text, logos or UI.`

## 빌드

Unity 상단 `Greed Last > Build Verified Windows Prototype`을 사용한다. 전체 스모크가 통과한 경우에만 `Builds/GreedLastPrototype/GreedLastPrototype.exe`를 갱신한다.

### 2026-09-09 검증

- 전체 스모크와 Windows 빌드 성공: `Logs/prototype-verified-checkpoint-20260909.log`
- 9개 비어 있지 않은 화면 캡처 및 화면 검토: `Logs/prototype-visual-choice-final-20260909.log`, `Logs/VisualChecks`
- 실행 파일 12초 부팅 중 게임 예외 없음: `Logs/prototype-player-boot-20260909.log`. 테스트로 띄운 숨김 프로세스는 검사 뒤 종료했다. 창 닫기 응답이 없어 해당 테스트 프로세스를 종료했으므로 정상 종료 흐름까지 검증한 것은 아니다.
- 캡처 검사는 타이틀·로비·선택·활성 함정·일시정지·재개 UI의 격리 검사다. 실제 모바일 입력·음향 지연이나 전체 손 플레이를 완료했다는 뜻은 아니다.
