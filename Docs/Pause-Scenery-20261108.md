# 정지 중 배경 위상 유지

프레임 차이 누적 시계는 정지 중 위상을 보존하지만, 배경의 여덟 위상 함수가 비주행 상태에서 저장한 위상 대신 초기 배치의 인덱스만 반환하고 있었다. 따라서 정지 직전까지 움직이던 바닥·기둥·통로가 메뉴 뒤에서 초기 위치로 튈 수 있다. 처음 로비/첫 대기는 기존 초기 배치를 유지하고, 이미 진행한 배경은 현재 위상에서 멈춰야 한다. 주자의 기존 중립 자세·회피 취소 정책은 이 변경 범위가 아니다.

`6f72a3f`의 실제 상태를 가진 UI 스모크는 `BuildStraightRunCorridorGatePhase must freeze the current scenery phase…`로 실패했다. 보고서 `ade23d4ff15746b08aa85cfb05e68f8f`, SHA256 `DE517558CC4056E1429F8FB545699535CEAFF340FF44F8DE53AE12727C9B9328`, 개인·원본 설정 불변이다.

후속 플레이어 관찰기는 실제 첫 연습의 정지 직전·정지 메뉴·0.4초 유지·재개 카운트·재개 직후 바닥/기둥의 앵커 Y와 프레임·누적 시계를 기록한다. 정지·카운트 동안 위치가 같고 재개 후 작은 전진으로 이어져야 한다. 실시간 코어 시계나 UI Update를 수동 호출하지 않는다. 수정 전 실제 화면에서도 `81d9fc28feb84cc4942434bcecd7843b`의 `Entering pause must freeze current scenery positions…` 오류로 재현됐다. 보고서 SHA256 `314087324D7FF4DB3EB31CC9F9E56BF1D1B6504B434127CE6D5B5F30EC0B246C`, 안전 대조 4개·개인/원본 설정 불변이며 저장/재실행 후속은 미수행이다.

수정은 배경 여덟 함수의 초기 배치 강제 반환만 제거한다. 새 컴포넌트의 위상은 0이므로 처음 대기 배치는 그대로이고, 이미 진행한 배경은 저장한 위상에서 멈춘다. 주자 함수의 비주행 0 반환과 코어 규칙은 유지한다. 이 검사는 밝기·박자 준비 효과를 모두 같은 픽셀로 고정한다는 뜻이 아니라 배경의 이동 위상에 대한 검사다.

수정 전 실제 표본의 누적 시계는 정지 전후 6.8933으로 같았지만, 바닥 Y는 0.5869→0.7800, 기둥 Y는 0.7058→0.8400으로 초기화됐다. `110fdb4`의 여덟 반환 수정은 전체 스모크·Windows 후보 `12bf15199e544196bbb07fc2241a5f54`에서 통과했다. 보고서 SHA256 `45ADA46146B84C22D29F16069A2A95DF60A135AC3EDD24C391B488C6D0D3ED09`, 개인·원본 설정 불변이다.

## 전진 속도선의 별도 위상

전진 속도선은 정지 중 숨기며 위치를 그대로 두고 있었지만, 라이브 위치 계산에는 여전히 누적 시계 전체에 현재 속도를 곱하는 식이 남아 있었다. 원래 식을 그대로 분리한 `d4bc17e`의 Unity 스모크 `b4b16c8437c44b7db3c240ccf804a579`에서 `Forward motion lines must not jump or backtrack…`로 감속 역행을 재현했다. 보고서 SHA256 `13D9029EF30BC0090729623A8C6DC912B8B761642B072FF21F52C1C7C7DD0260`이며 개인·원본 설정은 유지됐다.

`47346e9`는 전진 속도선도 프레임 차이 누적으로 연결하고 비주행 표본 무효화에 포함한다. 실제 플레이어 관찰기는 바닥·기둥·전진선의 라이브 8프레임과 정지 전후 5표본을 확인한다. 재개 직후 좌표는 PNG 인코딩 전에 읽어 저장 지연을 움직임 시간에 섞지 않는다. 이 후속의 전체 스모크·후보는 진행 중이며 앞선 `110fdb4`의 성공을 후속 전체 성공으로 확대하지 않는다.
